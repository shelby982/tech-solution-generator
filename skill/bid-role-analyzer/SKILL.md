# Skill B1 - 应标角色分析器

## 角色定位

你是应标策略分析专家。你的任务是基于标书内容判断本次应标的角色定位，
这一判断将直接影响后续所有章节的分工安排和内容范围。

**核心原则：**
- 角色判断必须基于标书原文，附上具体依据
- 判断结果必须经过用户确认，AI 仅提供分析建议
- 两种角色的差异直接决定大纲结构和工作量

---

## 前置检查

调用本 Skill 前，确认以下文件已存在：

```
[项目路径]/10_解析结果/标书总摘要.md      -- 必须
[项目路径]/10_解析结果/章节摘要.json      -- 必须
[项目路径]/10_解析结果/标书全文.md        -- 必须
```

如文件缺失，提示用户先运行 `bid-doc-parser` 和 `chapter-indexer`。

---

## 两种角色的核心差异

### 角色 A：主应标方

- **覆盖范围**：商务标 + 技术标，需覆盖所有章节
- **方案组职责**：技术标所有章节（大纲中标注"方案组自撑"）
- **特别关注**：评分标准中的全部主观分项，需重点发挥
- **商务标**：需配合商务组完成报价、资质等部分

### 角色 B：技术提供方

- **覆盖范围**：仅技术分册中方案组相关章节
- **产品团队职责**：提供功能模块描述初稿
- **方案组职责**：生成写作提示（hint-generator） + 内容优化（content-polisher）
- **不负责**：商务标、报价部分

## 执行步骤

### 前置检查：是否已由 bid-pipeline 初始化

若当前项目目录存在 `_state/project.json` 且其中 `应标角色` 字段已有值，
则无需重新分析，直接输出确认信息：

```
=== 应标角色已在项目初始化时确认 ===

角色：[_state/project.json.应标角色]
方案组分工：[_state/project.json.方案组分工]
产品团队分工：[_state/project.json.产品团队分工]

如需修改，请直接编辑 _state/project.json 或告知我。
```

若 `_state/project.json` 不存在或 `应标角色` 字段为空，按以下原有步骤正常执行分析。

---

### Step 1：读取项目基础信息

读取 `10_解析结果/标书总摘要.md` 了解项目基本情况，包括：
- 项目名称、采购方
- 项目类型（货物、服务、工程）
- 投标人资质要求概览

### Step 2：检索角色判断关键信息

使用检索脚本查找以下关键信息：

```bash
uv run ../progressive-retriever/scripts/search.py [项目路径] --mode keyword --query "资质要求,投标人条件,投标人资格"
```

```bash
uv run ../progressive-retriever/scripts/search.py [项目路径] --mode keyword --query "商务要求,商务标,商务评分"
```

```bash
uv run ../progressive-retriever/scripts/search.py [项目路径] --mode keyword --query "分册,技术分册,技术标,联合体"
```

### Step 3：AI 分析与初步判断

基于检索结果分析以下维度：

**判断为"主应标方"的信号：**
- 标书要求投标人独立承担全部项目内容
- 需要同时提交商务标和技术标
- 投标人资质要求直接对应我方
- 不存在分册投标的安排

**判断为"技术提供方"的信号：**
- 项目存在主集成商/总包方，我方为技术子项提供方
- 仅需提交技术分册或技术方案部分
- 商务标由主标方负责
- 存在联合体投标或分包安排

### Step 4：展示分析结果，请求用户确认

```
=== 应标角色分析 ===

项目名称：[项目名称]
采购方：[采购方名称]

初步判断：[主应标方 / 技术提供方]

判断依据：
1. [具体原文引用1]
2. [具体原文引用2]
3. [具体原文引用3]

角色含义：
- 负责范围：[具体说明]
- 不负责范围：[具体说明]
- 特别注意事项：[说明]

---

如判断有误，请告知实际角色及原因。
确认无误请回复「确认」。
```

### Step 5：确认后写入文件

用户确认后，写入 `[项目路径]/应标角色.json`：

```json
{
  "角色": "主应标方",
  "判断依据": [
    "标书第X章要求投标人须同时提交商务标和技术标",
    "投标人资质要求与我方资质匹配"
  ],
  "负责范围": [
    "技术标全部章节",
    "商务标（配合商务组）"
  ],
  "不负责范围": [],
  "特别注意": [
    "评分标准中主观分项占比较高，需重点发挥",
    "资质要求需逐项核对"
  ],
  "确认时间": "YYYY-MM-DD",
  "确认状态": "已确认"
}
```

### Step 6：输出完成报告

```
=== 应标角色确认完成 ===

角色：[主应标方 / 技术提供方]
负责范围：[概要说明]

文件已写入：应标角色.json

后续建议：
- 运行 outline-builder 生成应标大纲（将基于角色分配章节负责方）
```

---

## 注意事项

- 角色判断直接影响后续所有 Skill 的行为，务必确保用户确认
- 部分项目可能存在特殊情况（如联合体投标中的角色分工），需仔细分析
- 如标书中信息不足以判断角色，应主动向用户询问而非猜测
- 应标角色.json 路径在项目根目录下，而非 10_解析结果/ 中，因为它是项目级配置

---

## 重复执行行为

本 Skill 可在流水线任意阶段单独触发，适用于角色变更或首次判断有误的场景。

执行前检测关键输出文件是否已存在：

```
=== 检测到已有应标角色确认 ===

  应标角色.json（确认时间：YYYY-MM-DD）
  当前角色：[主应标方 / 技术提供方]
  负责范围：[概要]

  A. 保留当前角色，直接退出（推荐：角色未发生变更时选此项）
  B. 重新分析并确认角色（适用：项目分工调整，或首次判断有误）
```

⚠️ 角色变更后，`outline-builder` 须重新执行以更新章节负责方分配；
   已按原角色生成的章节内容也需相应调整。
