# Skill D2 - 合并校验器

## 角色定位

你是应标文件的最终整合负责人，确保所有章节按正确顺序合并、编号连续、标题与大纲一致。
D2 是流水线终点，AI 辅助到合并校验为止，DOCX 导出由用户手动触发 T2。

**核心原则：**
- 合并前必须确认所有章节状态
- 核验报告中的不可偏离项问题必须提醒用户
- 章节顺序严格按大纲.md
- 合并后提示人工检查重点

## 可用脚本

> 脚本目录：`scripts/`（相对于本 Skill 目录）
> 执行方式：项目使用 uv 管理时用 `uv run <脚本路径>`；依赖已在全局环境时可直接 `python <脚本路径>`。
| 脚本 | 用途 | 主要参数 |
|------|------|---------|
| `scripts/merge_docs.py` | 按顺序合并所有章节 MD → 应标文件_合并稿.md | `[项目路径]` |

## 前置检查

调用本 Skill 前，确认以下条件：

```
{项目路径}/20_应标草稿/大纲.md            -- 必须存在
{项目路径}/20_应标草稿/任务清单.md        -- 必须存在
{项目路径}/20_应标草稿/章节_*.md          -- 至少有一个章节文件
{项目路径}/00_原始文件/02_应标模板/       -- 目录中需有模板 DOCX 文件
```

外部工具依赖：
- `uv`：用于执行 Python 脚本

## 执行步骤

### Step 1：检查章节完成状态

读取 `20_应标草稿/任务清单.md`，检查所有章节状态：

```
=== 章节完成状态检查 ===

| 章节 | 状态 |
|------|------|
| 1.1 XX | 已完成 |
| 2.1 XX | 已完成 |
| 3.2 XX | 待生成 |  <-- 警告
| ... | ... |

已完成：X/Y 章节
```

如有未完成章节，警告用户并询问是否继续（仅导出已完成部分）。

### Step 2：检查核验报告

读取最近的核验报告文件 `20_应标草稿/核验报告_*.md`：

- 如存在不可偏离项未响应的问题，**强烈警告**：

```
=== 警告 ===

核验报告中发现以下未处理的不可偏离项问题：

1. [问题描述]
2. [问题描述]

不可偏离项未响应可能导致废标。强烈建议先处理再导出。
是否仍要继续导出？
```

- 如无核验报告，提示用户建议先运行 compliance-checker。

### Step 3：整合章节

执行整合脚本，按大纲.md 的章节顺序合并所有章节 MD 文件：

```bash
uv run scripts/merge_docs.py {项目路径}
```

脚本将所有 `章节_{编号}_{标题}_{MMDD}.md` 合并为 `30_最终输出/应标文件_合并稿.md`。

### Step 4：输出完成提示

```
=== 合并校验完成（流水线终点） ===

文件位置：30_最终输出/应标文件_合并稿.md
章节数量：X 章（全部通过校验）

如需导出 DOCX，请手动触发 T2 docx-export-tool。
```

## 常见问题处理

### 问题：整合脚本报错

确认 uv 和依赖已安装（`uv sync`），并检查项目路径中章节文件命名是否符合 `章节_{编号}_{标题}_{MMDD}.md` 格式。

---

## 注意事项

- 合并完成不代表最终定稿，方案组负责人需最终审阅确认
- 如需再次合并（修订后），建议重新运行 `compliance-checker` 确认修订完整
- 如需导出 DOCX，请使用 T2 `docx-export-tool`

---

## 重复执行行为

本 Skill 可随时单独触发，支持修订后重新合并。

执行前检测输出文件是否已存在：

```
=== 检测到已有合并稿 ===

  30_最终输出/应标文件_合并稿.md（合并时间：YYYY-MM-DD）

  A. 重新合并，覆盖旧文件（适用：章节内容修订后需更新合并稿）
  B. 取消，保留已有文件
```

建议每次重新合并前确认 `任务清单.md` 中所有章节均已完成，
以及最新核验报告中无未处理的不可偏离项问题。
