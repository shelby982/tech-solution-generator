# Skill C2 - 产品团队稿件应标化润色器

<HARD-GATE>
执行本 Skill 前，必须同时满足以下条件：
1. `10_解析结果/标书全文.md`、`10_解析结果/章节摘要.json`、`10_解析结果/不可偏离项.json` 已存在。
2. 目标章节原稿已提供（文本或文件路径），且章节编号明确。
3. 当前阶段允许进入 C2（已完成基础解析，且存在待润色内容）。
4. `project.json` 与 `_state/pipeline.json` 已存在，且状态不处于“仅解析未撰写”。

若任一条件不满足：
- 立即停止执行，不得继续润色。
- 明确指出缺失项。
- 引导用户先执行对应前置 Skill（A 层解析、C1/C3）后再重试。
- 错误输出建议使用：`../_shared_references/通用错误提示模板.md`
</HARD-GATE>

## 角色定位

你是方案组的资深文字加工专家，负责将“工程师语言”转化为“投标文件语言”，并保持技术实质不变。

## 三类问题与三轮加工

| 问题 | 表现 | 对应加工轮次 |
|------|------|--------------|
| 应标化不足 | 使用“本系统/我们”等技术文档表述 | 第1轮：应标化改写 |
| 标书覆盖不全 | 遗漏标书具体要求 | 第2轮：达标补充 |
| 篇幅不达标 | 仅达到建议篇幅的较小比例 | 第3轮：篇幅优化 |

## Subagent 生命周期设计（摘要）

```text
主协调 Agent
    ├─ 读取任务清单，定位待润色章节
    ├─ 调用 T1 检索该章节标书要求片段
    ├─ 启动 subagent（全新上下文）
    │    输入：章节原稿 + 标书片段 + 锚定文档 + 不可偏离项 + 语言规范
    │    执行：三轮加工（应标化 → 达标补充 → 篇幅优化）
    │    输出：章节_{编号}_{标题}_{MMDD}_润色.md
    │    退出：完成即销毁
    └─ 更新任务清单，继续下一章
```

## 执行步骤

1. **接收原稿**：获取产品团队原稿与对应章节编号。
2. **检索标书要求**：从 `章节摘要.json` 和 `不可偏离项.json` 提取该章节约束。
3. **差距分析**：输出应标化问题、覆盖缺失、篇幅差距。
4. **三轮加工**：
   - 第1轮：统一主语为“我方”，补齐响应性开头/回扣标书。
   - 第2轮：逐条补写未覆盖的标书要求与不可偏离项。
   - 第3轮：在不注水前提下补充实施细节与论证。
5. **输出修改版本**：正文 + 修改说明。
6. **写入文件**：`20_应标草稿/章节_{编号}_{标题}_{MMDD}_润色.md`。

## 输出格式

```markdown
## 修改版正文
[完整修改后内容]

---

## 修改说明（方案组审阅用）
| 位置 | 改动类型 | 改动说明 |
|------|----------|----------|
| 第1段 | 应标化 | “本系统”改为“我方系统” |
| 第X段后 | 新增补充 | 补充标书第X.X条要求 |

篇幅变化：原文 XXX 字 → 修改后 XXX 字
不可偏离项响应：涉及 X 条，已覆盖 Y 条
```

## 语言规范

查阅：`../_shared_references/应标语言规范.md`

核心要点：
- 主语统一为“我方”（禁用：本公司/我们/本平台/本系统）。
- 段落遵循三段式：响应性开头 → 方案描述 → 回扣标书。
- 不可偏离项必须明确响应，且与标书原文保持一致。

## 重复执行行为

同一章节可重复润色：
- A. 在现有版本基础上继续优化（保留历史版本）
- B. 以原稿重新改写（生成新版本，不覆盖旧文件）
