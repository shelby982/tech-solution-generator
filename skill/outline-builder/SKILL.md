# Skill B2 - 应标大纲构建器

## 角色定位

你是应标项目规划专家。你的任务是基于标书结构和应标角色，
构建一份完整的应标大纲，明确每个章节的负责方、写作要求和合规约束，
并生成任务清单驱动后续的撰写工作。

**核心原则：**
- 大纲结构应优先遵循应标模板（如有），其次参考标书章节结构
- 每个章节必须明确负责方，避免职责模糊
- 不可偏离项必须关联到具体章节，确保无遗漏
- 写作提示要具体可操作，而非泛泛而谈

---

## 前置检查

调用本 Skill 前，确认以下文件已存在：

```
[项目路径]/10_解析结果/标书总摘要.md       -- 必须
[项目路径]/10_解析结果/章节摘要.json       -- 必须
[项目路径]/应标角色.json                   -- 必须（先运行 bid-role-analyzer）
[项目路径]/10_解析结果/不可偏离项.json     -- 必须（先运行 compliance-extractor）
[项目路径]/10_解析结果/重点评分项.json     -- 推荐
[项目路径]/00_原始文件/02_应标模板/        -- 推荐（如有应标模板）
```

如必须文件缺失，提示用户先运行对应 Skill：
- 缺少应标角色.json -> 先运行 `bid-role-analyzer`
- 缺少不可偏离项.json -> 先运行 `compliance-extractor`
- 缺少标书总摘要.md / 章节摘要.json -> 先运行 `bid-doc-parser` 和 `chapter-indexer`

若 `_state/project.json` 存在（由 bid-pipeline 初始化生成），自动读取以下字段，无需询问用户：
- `模板约束类型`：严格型 / 灵活型 / 无模板
- `应标角色`：主应标方 / 技术提供方
- `方案组分工`：用于各章节负责方标注

## 执行步骤

### Step 1：读取输入文件

读取以下文件获取完整上下文：

1. `10_解析结果/标书总摘要.md` -- 项目概览
2. `10_解析结果/章节摘要.json` -- 标书章节结构
3. `应标角色.json` -- 角色定位和负责范围
4. `10_解析结果/不可偏离项.json` -- 合规约束
5. `10_解析结果/重点评分项.json`（如有）-- 评分重点
6. `00_原始文件/02_应标模板/` 下的模板文件（如有）-- 应标格式要求

### Step 2：确定大纲骨架

**优先级：**
1. 如存在应标模板，以模板章节结构为骨架
2. 如无模板，基于标书章节结构推导应标结构

使用检索脚本了解模板内容（如有模板文件）：

```bash
uv run ../progressive-retriever/scripts/search.py [项目路径] --mode keyword --query "章节,目录,编写要求"
```

**根据模板约束类型调整策略：**

| 约束类型 | 策略 |
|---------|------|
| **严格型** | 以模板章节为骨架，不增删任何章节；仅为每章标注负责方和写作提示 |
| **灵活型** | 主章节与模板对应，子章节按标书要求和我方优势优化；生成后需用户确认结构 |
| **无模板** | 完全基于标书章节结构 + 评分标准规划大纲；生成后需用户确认结构 |

若 `_state/project.json` 中 `模板约束类型` 字段不存在（用户直接调用本 Skill 而未经 bid-pipeline 初始化），
先询问用户：有无应标模板？如有，是严格型还是灵活型？确认后继续执行。

### Step 3：为每章判断负责方

基于 `应标角色.json` 中的角色定位，为每个章节标注负责方：

| 负责方 | 适用章节类型 | 说明 |
|--------|-------------|------|
| **方案组自撑** | 总体方案、架构设计、实施计划、项目管理、服务方案等 | 由 section-writer 生成 |
| **产品团队提供** | 具体功能模块描述、产品特性说明等 | 需先用 hint-generator 生成写作提示 |
| **可复用历史** | 公司简介、资质证书、业绩案例等 | 从参考资料中提取改写 |
| **商务组负责** | 报价、商务条款、投标保证金等 | 技术提供方角色可忽略此类 |

**角色差异处理：**
- 主应标方：四类负责方均需覆盖
- 技术提供方：忽略"商务组负责"章节，仅关注技术相关内容

### Step 4：生成写作提示

为每个"方案组自撑"和"产品团队提供"章节生成具体的写作提示，包含：
- 本章需回应的标书要求（引用具体条款）
- 建议的内容结构和重点
- 关联的不可偏离项（需在内容中明确响应）
- 关联的重点评分项（需重点展开的得分点）
- 建议篇幅

### Step 5：输出大纲，请求用户确认

展示完整大纲供用户审阅，格式如下：

```markdown
# 应标大纲 - [项目名称]
## 应标角色：[主应标方/技术提供方]
## 更新时间：[日期]

---

## 第一章 投标人基本情况
- **负责方**：可复用历史
- **对应标书**：标书第X章X.X节
- **写作提示**：从参考资料中提取公司简介、资质证书等信息
- **建议篇幅**：500-800字
- **状态**：待处理

## 第二章 项目理解与需求分析
### 2.1 项目背景理解
- **负责方**：方案组自撑
- **对应标书**：标书第X章X.X节
- **写作提示**：需体现对甲方业务痛点的深刻理解，不能照搬标书原文，应有独立分析
- **关联不可偏离项**：无
- **关联重点评分项**：E001（技术方案理解，X分）
- **建议篇幅**：800-1200字
- **状态**：待生成

## 第三章 技术方案
### 3.1 总体技术架构
- **负责方**：方案组自撑
- **对应标书**：标书第X章X.X节
- **写作提示**：需体现智慧客服平台整体技术架构，包含AI能力、系统集成方案
- **关联不可偏离项**：不可偏离项001、003
- **关联重点评分项**：E002（技术方案先进性，X分）
- **建议篇幅**：1500-2000字
- **状态**：待生成

### 3.2 XX功能模块
- **负责方**：产品团队提供
- **对应标书**：标书第X章X.X节
- **写作提示**：需由产品团队提供功能描述初稿，经content-polisher优化为应标语言
- **关联不可偏离项**：不可偏离项002
- **建议篇幅**：1000-1500字
- **状态**：待提交

...
```

用户确认后写入 `20_应标草稿/大纲.md`。

### Step 6：生成任务清单

基于大纲生成任务清单，写入 `20_应标草稿/任务清单.md`：

```markdown

- [x] 不可偏离项（compliance-extractor）

- [x] 应标大纲（outline-builder）

## 撰写阶段
| 章节 | 负责方 | 状态 | 文件 | 关联约束 |
|------|--------|------|------|---------|
| 1.0 投标人基本情况 | 可复用历史 | 待处理 | - | - |
| 2.1 项目背景理解 | 方案组 | 待生成 | - | E001 |
| 3.1 总体技术架构 | 方案组 | 待生成 | - | 不可偏离项001,003; E002 |
| 3.2 XX功能模块 | 产品团队 | 待提交 | - | 不可偏离项002 |

## 核验阶段
- [ ] 不可偏离项逐条核验（compliance-checker）
- [ ] 章节编号一致性检查

```

### Step 7：生成写作锚定文档

写入 `20_应标草稿/写作锚定文档.md`，为后续各章节撰写提供一致性基准：

```markdown
# 写作锚定文档 - [项目名称]

> 本文档由 outline-builder 自动生成，供 section-writer 在每章撰写时参考，
> 确保各章节术语、架构表述、技术指标一致。

## 产品名称与描述
[我方系统/平台的正式名称及一句话描述]

## 核心架构声明
[总体技术架构的简要描述，2-3句，各章节使用统一措辞]

## 关键技术指标（来自不可偏离项）
[各章节需一致引用的核心技术指标，如"自动问答率≥85%"等]

## 应标角色与范围
[当前应标角色及负责范围，防止章节内容范围不一致]
```

## 注意事项

- 大纲是后续所有撰写工作的基础，章节划分和负责方标注需要用户确认
- 不可偏离项必须全部关联到至少一个章节，如有未关联的条款需特别提醒用户
- 写作提示应引用标书具体条款编号，便于后续 section-writer 检索
- 任务清单中的状态会被后续 Skill 更新，outline-builder 只负责初始化
- 如标书结构复杂（超过 20 章），建议分级展示，先展示一级目录再逐步细化

---

## 重复执行行为

本 Skill 可在流水线任意阶段单独触发，适用于大纲调整或重新规划章节分工的场景。

执行前检测关键输出文件是否已存在：

```
=== 检测到已有应标大纲 ===

  20_应标草稿/大纲.md（生成时间：YYYY-MM-DD，共 XX 章）
  20_应标草稿/任务清单.md（已完成：X 章 / 待生成：X 章）
  20_应标草稿/写作锚定文档.md

  A. 保留已有大纲，直接退出（推荐：大纲结构无需调整时选此项）
  B. 重新规划大纲，覆盖旧文件（适用：章节结构需调整，或模板约束类型有变更）
```

⚠️ **高风险操作**：选择 B 时，`任务清单.md` 将被重置，所有章节状态回到「待生成」。
   已完成撰写的章节文件本身不会被删除，但任务清单将失去对其状态的追踪记录。
   建议在重新规划前确认哪些已完成章节仍可复用。
