# Skill A2 - 章节索引构建器

## 角色定位

你是标书结构分析专家。你的任务是对已转换的标书 Markdown 文件进行深度结构解析，
生成分层章节索引、逐章摘要和标书总摘要，为后续所有 Skill 提供精准的导航基础。

**核心原则：逐章处理，绝不一次性加载全文。**

## 前置条件

- `bid-doc-parser` 已运行，`10_解析结果/标书全文.md` 已生成
- 项目工作区目录结构已就绪

## 执行步骤

### 可用脚本

> 脚本目录：`scripts/`（相对于本 Skill 目录）
> 执行方式：项目使用 uv 管理时用 `uv run <脚本路径>`；依赖已在全局环境时可直接 `python <脚本路径>`。
| 脚本 | 用途 | 主要参数 |
|------|------|---------|
| `scripts/split_chapters.py` | 解析 Markdown，提取章节结构，生成章节索引 JSON | `[标书全文.md路径]` |
| `scripts/gen_summary.py` | 提取各章节内容并输出结构化提示，**无需 API Key**，兼容所有模型 | `[项目路径] [--profile compact\|standard\|extended\|unlimited]` |

```bash
# 生成章节索引
uv run scripts/split_chapters.py [标书全文.md路径]

# 准备摘要生成提示（输出到当前会话，由 Claude 处理）
uv run scripts/gen_summary.py [项目路径]
```

### Step 1：确认输入文件

检查以下文件是否存在：

```bash
python -c "import os, sys; p='<项目路径>/10_解析结果/标书全文.md'; print('标书全文已就绪' if os.path.isfile(p) else '标书全文不存在，请先运行 bid-doc-parser'); sys.exit(0 if os.path.isfile(p) else 1)"
```

如果文件不存在，提示用户先运行 `bid-doc-parser`，终止执行。

同时获取文件基本信息（行数、大小），不读取全文：

```bash
python -c "p='<项目路径>/10_解析结果/标书全文.md'; lines=sum(1 for _ in open(p,encoding='utf-8')); import os; size=os.path.getsize(p); print(f'{lines} 行, {size} 字节')"
```

### Step 2：提取章节结构

**方式一：使用现有脚本（优先）**

```bash
uv run scripts/split_chapters.py "[项目路径]/10_解析结果/标书全文.md"
```

**方式二：手动解析（脚本不可用时）**

逐段扫描标书全文，识别章节标题。按以下规则判断章节边界：

1. 读取文件前 100 行，识别标题格式模式（Markdown `#` 标题 或 编号标题如 `第一章`、`1.`、`一、` 等）
2. 使用 Grep 工具搜索所有标题行：

```
# 搜索 Markdown 标题
pattern: "^#{1,4}\s+"
path: "<项目路径>/10_解析结果/标书全文.md"

# 搜索中文编号标题
pattern: "^(第[一二三四五六七八九十百]+[章节条款篇]|[一二三四五六七八九十]+[、.]|[0-9]+[\\.\\s])"
path: "<项目路径>/10_解析结果/标书全文.md"
```

3. 合并搜索结果，按行号排序，确定每个章节的起止行号
4. 计算每个章节的字数（结束行 - 起始行的字符数）

### Step 3：生成章节索引 JSON

将解析结果写入 `<项目路径>/10_解析结果/章节索引.json`，格式：

```json
{
  "文件": "标书全文.md",
  "总行数": 5000,
  "总字数": 120000,
  "章节列表": [
    {
      "编号": "1",
      "标题": "项目概述",
      "层级": 1,
      "起始行": 10,
      "结束行": 45,
      "字数": 820
    },
    {
      "编号": "1.1",
      "标题": "项目背景",
      "层级": 2,
      "起始行": 12,
      "结束行": 30,
      "字数": 420
    }
  ]
}
```

**字段说明：**
- `编号`：章节编号（保留原始编号格式）
- `标题`：章节标题文本
- `层级`：标题层级（1=一级标题，2=二级标题，以此类推）
- `起始行` / `结束行`：在标书全文.md中的行号范围
- `字数`：该章节的字符数

### Step 4：生成章节摘要（Bottom-Up 分批模式）

脚本采用 **Bottom-Up 分批处理**，重复运行直到完成，自动跳过已完成章节。

**按上下文容量选择档位（与具体模型无关）：**

| --profile | 适用场景 | 每批叶子数 |
|-----------|---------|-----------|
| compact   | ~32k 可用 | 10 |
| standard  | ~128k-200k（默认） | 20 |
| extended  | ~500k-1M | 60 |
| unlimited | one-shot，不限制 | 全部 |

**运行命令（可重复运行，自动续接）：**

```bash
# 默认 standard 档（适合 GLM-4.7 等 200k 模型）
uv run scripts/gen_summary.py [项目路径]

# 指定档位
uv run scripts/gen_summary.py [项目路径] --profile extended
```

**三个自动阶段：**

- **Phase 1（叶子节点）**：输出叶子章节原文 → 你生成摘要 → append 到 `章节摘要.json`
  - 长章节（>250 行）自动头尾采样（前 200 行 + 后 50 行），避免截断
- **Phase 2（内部节点）**：输出父章节的子摘要 → 你汇总 → append 到 `章节摘要.json`
  - 输入极短（子摘要文本），不消耗大量上下文
- **Phase 3（总摘要）**：所有章节完成后，自动输出总摘要生成指令

**按脚本指示操作，每批完成后再次运行命令，直到出现 ✅ 提示。**

### Step 5：生成标书总摘要

Phase 3 自动触发，基于所有章节摘要（不重新加载全文），生成 `<项目路径>/10_解析结果/标书总摘要.md`。

**总摘要包含以下板块：**

```markdown
# 标书总摘要

## 项目背景与建设目标
（从相关章节摘要提炼）

## 核心技术需求概览
（列出主要技术要求和系统模块）

## 评分项分布
（如标书中包含评分标准，列出各评分大项及分值）

## 截标时间与应标要求
（投标截止时间、开标时间、资质要求等）

## 需要特别关注的事项
（潜在风险点、特殊要求、易遗漏条款等）
```

### Step 6：输出完成报告

```
=== 章节索引构建完成 ===

标书全文：XX 行 / XX 字
章节数量：XX 个（一级 X 个，二级 X 个，三级 X 个）
已生成文件：
  - 章节索引.json（章节结构和行号索引）
  - 章节摘要.json（逐章摘要）
  - 标书总摘要.md（项目概览）

下一步建议：
  - 运行 compliance-extractor 提取不可偏离项
  - 运行 progressive-retriever 按需检索标书内容
```

## 错误处理

### 标书全文不存在

```
[错误] 未找到标书全文：<项目路径>/10_解析结果/标书全文.md
请先运行 bid-doc-parser 转换标书文档。
```

### 章节标题识别失败

如果自动识别的章节数量过少（少于3个），可能是标题格式不标准：

1. 读取文件前 200 行，展示给用户
2. 请用户确认标题格式模式
3. 根据用户反馈调整正则表达式重新解析

### 章节内容过长

如果单个章节超过 500 行，建议进一步拆分为子章节处理，避免一次加载过多内容。

## 与其他 Skill 的关系

- **前置依赖**：`bid-doc-parser`（需要标书全文.md）
- **后续调用**：`progressive-retriever`（使用章节索引定位内容）、`compliance-extractor`（使用章节摘要辅助提取）
- **被引用**：几乎所有后续 Skill 都依赖本 Skill 生成的索引文件

## 重复执行行为

本 Skill 可在流水线任意阶段单独触发，支持重新生成或补全摘要。

执行前检测关键输出文件是否已存在：

```
=== 检测到已有章节索引 ===

  10_解析结果/章节索引.json（生成时间：YYYY-MM-DD，共 XX 章）
  10_解析结果/章节摘要.json / 标书总摘要.md

  A. 保留已有索引，直接退出（推荐：索引准确且后续步骤已就绪时选此项）
  B. 重新生成，覆盖全部索引文件（适用：标书全文有更新，或章节划分不准确）
  C. 仅补全摘要（适用：章节索引.json 正确，但摘要未全部生成完毕）
```

⚠️ 选择 B 重新生成时，`章节摘要.json` 和 `标书总摘要.md` 将同步清空，
   需重新运行摘要生成步骤（gen_summary.py）。
