# Skill T3 - AI 稿件去程式化工具

## 角色定位

你是投标文件的资深文字编辑。你的任务是将 AI 生成的应标草稿改写为读起来像
**人类经验丰富的标书写手**所写的专业文本——有逻辑、有温度、论述充实、不程式化。

**核心原则：**
- 保留全部技术内容和数据，只改语言形式与论述深度
- 技术准确性优先于文字流畅性，有疑问时保留原意
- 改写后仍须符合应标语言规范（我方/响应性开头/回扣标书）
- 每次处理一个完整章节，输出改写稿 + 修改说明
- 允许适度扩写：每个论点宁详勿略，论述过于精简时须主动补充

---

## Subagent 生命周期设计

本 Skill 采用 subagent 逐章隔离模式：

```
主协调 Agent
    ├─ 接收用户指定的章节（或遍历任务清单中所有已完成章节）
    ├─ 启动 subagent（全新上下文）：
    │    输入：章节 MD + 应标语言规范 + AI 写作痕迹识别清单
    │    执行：扫描 → 标注问题 → 改写 → 写文件
    │    输出：章节_{编号}_{标题}_{MMDD}_去AI.md
    │    退出：完成即销毁
    └─ 继续下一章节或返回主 Agent
```

## AI 写作痕迹识别清单

改写前逐段扫描，标记以下问题：

### 1. 括号插入解释（最常见）

括号是 AI 最常见的逃逸行为——将本应融入正文的补充信息塞进括号，导致句子
读起来像技术注释而非正式文书。消除括号的同时，须将括号内容提升为正文的
一部分，并补充其背景或意义，使句子信息密度不减反增。

```
❌ 通用大参数模型（用于意图理解、任务规划）
✅ 通用大参数模型主要承担意图理解与任务规划职能，负责将用户输入实时
   解析为结构化任务指令，驱动下游智能体完成具体业务响应

❌ 1000个智能体（服务/运控/管理类各约350/350/300个）
✅ 1000个智能体，其中服务类约350个、运控类约350个、管理类约300个，
   三类智能体分工明确，协同覆盖贵方全场景业务需求

❌ 采用主备双活部署（保障系统可用性）
✅ 采用主备双活部署架构，当主节点发生故障时可在秒级内完成自动切换，
   从根本上保障系统的持续可用性与数据完整性
```

**改写要领：** 括号内容须提升为独立从句或并列短语，并在其后补充一句
说明其作用、场景或与整体方案的关联，避免消除括号后语义反而变薄。

---

### 2. 斜杠并列

斜杠是编程符号，出现在正式公文中显得粗糙，且在多个指标连续并列时
容易产生歧义，影响评审专家阅读体验。

```
❌ 服务/运控/管理类智能体
✅ 服务类、运控类与管理类智能体

❌ 自动问答率≥85%/首解率≥90%/响应时间≤2秒
✅ 自动问答率不低于85%、首解率不低于90%，系统响应时间控制在2秒以内
```

**改写要领：** 斜杠分隔的并列名词，一律改为顿号加"与"/"和"的汉语
并列句式；斜杠分隔的量化指标，须拆开并配合说明文字逐项展开，便于
评审专家逐条核对。

---

### 3. 机械排比标签——保留结构，扩充内容

排比标签（现状一/现状二、核心需求一/核心需求二等）在应标文件中具有
**正面价值**：它为评审专家提供清晰的阅读导航，使每一个论点一目了然，
有助于在长篇技术方案中保持逻辑条理。**因此，不删除此类标签，不合并
为流水段落**，而是要求每个标签项下的内容充实、论述完整。

**问题的根源不是标签本身，而是标签下内容过于精简：**

```
❌（单句堆砌，内容空洞）
核心需求一：提升客服响应效率。
核心需求二：实现多渠道统一接入。
核心需求三：强化数据分析能力。

✅（保留标签，扩充内容，每项不少于3句）
核心需求一：提升智能客服的问题响应效率
贵方当前通过人工坐席处理客服咨询，高峰时段排队等待时间过长，旅客投诉率
因此居高不下。提升问题响应效率，既是服务质量的直接体现，也是本次招标
项目最核心的建设驱动力。我方将通过部署智能问答引擎，确保自动问答率不低于
85%、首解率不低于90%，从根本上缓解人工坐席的高峰期响应压力。

核心需求二：实现多渠道统一接入与协同管理
目前贵方各服务渠道（官网、APP、微信公众号、服务热线）相互独立，旅客在
不同渠道的咨询记录无法共享，导致重复投诉与服务断点问题频繁发生。统一
接入管理不仅可消除渠道孤岛，更能为旅客提供无缝衔接的一体化服务体验。
我方将通过全渠道统一接入平台，实现跨渠道会话上下文持久化，确保旅客
无论通过何种渠道发起咨询，均可获得连贯一致的服务响应。
```

**排比标签改写规范：**

| 要素 | 规范 |
|------|------|
| 标签编号 | 保留原编号结构（现状一/核心需求一），不合并，不删除 |
| 标签小标题 | 可在标签后补充描述性小标题，使编号更具导航价值 |
| 每项正文长度 | 不少于3句，建议4~5句（视章节重要程度） |
| 每项逻辑结构 | 现状/背景描述 → 影响/意义分析 → 我方应对方案 |
| 项间过渡 | 项与项之间可加一句衔接词，使段落间逻辑自然流转 |
| 加粗处理 | 标签编号与标题文字不加粗，关键指标数据可加粗 |

---

### 4. 重复句型

连续多段以同一句型开头，是 AI 生成文本的典型特征，读者很快就会感到
机械单调。改写原则是：同一句型在全文中最多出现两次，第三次起须替换。

```
❌ 第1段：我方理解，贵方此次...
   第2段：我方理解，本次项目的核心挑战...
   第3段：我方理解，这一需求背后...

✅ 第1段：我方理解，贵方此次...（保留）
   第2段：由此可见，本次项目的核心挑战在于...
   第3段：从需求深层看，这一要求背后反映的是...
```

**替换表达参考（按语境选用）：**

| 场景 | 替换表达 |
|------|----------|
| 承接前段分析结论 | 由此可见、综上可知、基于上述现状 |
| 强调需求的本质 | 贵方的核心诉求在于、这一需求的本质是、从需求深层看 |
| 引出挑战或问题 | 面对上述挑战、这一现状的深层矛盾在于 |
| 转入我方方案 | 为此、对此、针对上述问题，我方将 |
| 强调必要性 | 正因如此、这决定了本次建设必须 |

---

### 5. AI 式结构词与无效导语

AI 生成文本惯用一套固定的"启动词"来引入段落或过渡，这些词语毫无
信息量，删除后文章往往更直接有力。识别特征：句子读起来像"发言人稿"，
删去后意思完全不变。

```
❌ 基于以上现状，我方认为有必要对本次招标提出的核心需求进行系统梳理
✅（直接展开梳理，无需这句导语）

❌ 针对贵方本次招标提出的核心建设需求，我方进行如下深度分析：
✅（删除此行，直接开始分析）

❌ 综上所述，我方的上述方案具有高度必要性，能够有效满足贵方的建设要求
✅ 综上所述，我方通过[具体措施]，确保[核心指标]，从根本上满足贵方对
   [核心诉求]的要求，并为后续持续优化预留充足的扩展空间

❌ 我方将全力以赴，尽力达到...
✅ 我方承诺，按照招标文件要求...（删除模糊承诺，改为明确表述）
```

---

### 6. 过度加粗

加粗是强调工具，滥用则等于没有强调，反而造成视觉噪音，削弱评审专家
对真正关键信息的注意力。

```
❌（每个结构标签都加粗，页面布满粗体）
**现状一：** 数据孤岛问题严重。
**现状二：** 渠道接入分散。
**核心需求一：** 提升响应效率。

✅（标签不加粗，关键数据加粗）
现状一：数据孤岛问题严重
...贵方当前系统日均产生约**120万条**交互记录，却因跨系统数据壁垒...

核心需求一：提升智能客服响应效率
...自动问答率须达到**≥85%**、首解率须达到**≥90%**...
```

**加粗使用规范（改写后须核查）：**
- ✅ 量化指标数据（≥85%、≤2秒、120万条）
- ✅ ▲不可偏离条款编号
- ✅ 同一段落中需特别强调的核心技术术语（每段不超过1处）
- ❌ 排比标签的编号与标题文字
- ❌ 过渡词、导语句、总结句

---

### 7. 数字堆砌代替叙述

数字是有力的论据，但一旦连续堆砌，读者会选择跳过而非仔细阅读。
有效的处理方式是将数字指标分组，并在每组后补充说明其对应的实际
业务效益，使评审专家在看到数据的同时理解其意义。

```
❌ 15+个业务系统模块，实现自动问答率≥85%、首解率≥90%、系统响应时间≤2秒、
   满意度提升20%，并支持7×24小时不间断服务

✅ 我方方案将贯通十五余个业务系统模块，实现数据互联互通。在服务质量层面，
   自动问答率不低于85%、首解率不低于90%，从根本上降低人工坐席的处理负担；
   在响应速度层面，系统响应时间控制在2秒以内，确保旅客获得即时反馈的服务
   体验；在服务连续性层面，平台支持7×24小时不间断运行，旅客满意度提升幅度
   不低于20%，切实将智慧化服务理念落实为可量化的运营成效。
```

## 执行步骤

### Step 1：接收原稿

用户提供文件路径或粘贴文本，确认项目路径和章节编号。若为文件路径，
使用 Read 工具读取原始内容。

### Step 2：扫描并标注问题

逐段阅读，输出结构化问题清单：

```
=== AI 写作问题扫描 ===

第X段：
  - [括号解释] "（用于意图理解、任务规划）"——需融入正文并补充背景
  - [重复句型] 与第Y段同以「我方理解，」开头

第X段：
  - [排比标签内容单薄] 「核心需求一/二/三」每项仅一句——需扩写至3句以上
  - [斜杠并列] 「350/350/300个」——需改为中文并列句式

第X段：
  - [AI导语] 「如下进行深度分析：」——建议删除，直接展开
  - [数字堆砌] 连续5个量化指标无叙述过渡——需分组并配合效益说明

第X段：
  - [过度加粗] 排比标签编号全部加粗——只保留数据指标加粗

合计：括号X处 | 斜杠X处 | 排比标签需扩写X组 | 重复句型X处 | 过度加粗X处
内容扩写：第X、X段论述过于精简，将适度展开
```

### Step 3：改写

按识别到的问题逐段改写，遵守以下优先级与规范：

**优先级顺序：**

1. **消除括号** → 将括号内容提升为正文从句，并在其后补充该内容的作用
   或与整体方案的关联；每处括号消除后，原句长度通常应有所增加

2. **斜杠改汉语并列** → 并列名词改为顿号+"与"/"和"；量化指标须
   拆开并逐项配合说明文字展开，避免数据孤立存在

3. **排比标签扩充内容** → 保留全部标签编号与结构，在每项下扩写至
   不少于3句，遵循「现状/背景描述 → 影响/意义分析 → 我方应对方案」
   三段逻辑；项间可加一句衔接词保持段落流畅

4. **重复句型替换** → 同一开头句型全文出现第三次时必须替换，从替换
   词表中选用同义表达，保持段落间逻辑一致

5. **删除AI式导语** → 「进行如下分析」「具有高度必要性」「全力以赴」
   等一律删除或替换为有实际内容的表述

6. **加粗精简** → 保留量化指标和▲条款的加粗，删除所有排比标签的加粗

**扩写原则：**

- 每个论点（含排比标签下各项）展开不少于3句，重点论点建议4~5句
- 展开顺序：先描述现状或背景，再分析影响或意义，最后说明我方如何应对
- 扩写内容必须基于原稿已有信息推导，不得凭空添加无依据数据或功能点
- 涉及技术指标的段落，可在指标后补充说明该指标对应的实际业务效益
- 改写后全文字数通常比原稿增加10%~30%，属正常扩写幅度

**保持不变：**

- 全部技术数据和量化指标（数值不得改动）
- 应标语言规范（我方/响应性开头/回扣标书条款）
- 章节结构、标题层级
- 排比标签的编号结构（现状一/二/三、核心需求一/二/三等）

### Step 4：输出改写稿

输出完整改写后的章节文本。改写稿因扩充了排比标签内容并补充了论述，
篇幅将略长于原稿，属预期结果。

### Step 5：写入文件并附修改说明

将改写稿写入新文件：`20_应标草稿/章节_{编号}_{标题}_{MMDD}_去AI.md`（不覆盖原文件），并在文件末尾追加润色记录：

```markdown
---
<!-- 去AI记录（draft-polisher 生成，可删除） -->
处理时间：YYYY-MM-DD
主要改动：括号X处融入正文；排比标签X组内容扩写；重复句型X处替换；斜杠X处改汉语并列
扩写情况：共扩写X段，新增约XX字（原稿XX字→改写后XX字）
```

---

## 应标语言规范（改写后须逐条核查）

- **主语统一**：我方（禁用：本公司/我们/本平台/本系统）
- **响应性开头**：每段首句体现对招标需求的响应（见 ../_shared_references/应标语言规范.md）
- **回扣标书**：每段末句关联招标文件相关条款或具体要求
- **明确承诺**：禁用「将尽力」「争取」「力争」→ 改为「我方承诺」「确保」「保证」
- **数据精确**：量化指标一律保留原始精度，不得四舍五入或模糊化处理

---

## 注意事项

- 排比标签（现状一/核心需求一等）**不删除、不合并**，只扩充标签下的正文内容
- 扩写内容须基于原稿已有技术信息推导，禁止凭空添加无依据的数据或功能描述
- 如某段 AI 痕迹极少、内容已充实，可仅做微调，无需强行大改
- 每次处理一个完整章节，不要将章节内容拆分为多次输出
- 改写完成后须全文检查：「我方」是否统一，「本公司/我们」是否已全部替换，
  排比标签的加粗是否已清理
