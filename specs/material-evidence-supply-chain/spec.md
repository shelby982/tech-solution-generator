# SPEC：素材证据供应链：从文件库到需求-证据-使用闭环

- slug：material-evidence-supply-chain
- 日期：2026-11-05
- 状态：已批准（2026-11-05，人审通过）

## 1. 背景与问题

素材模块当前同时承担「素材缺口」「文件库」「公开来源」「本章引用」「推荐素材」五种角色，导致：

- 用户不知道先看需求、还是先看文件；
- 上传文件不等于形成可用证据，片段确认/绑定链路没有被真正使用；
- 「本章素材」在没有节级绑定时回退整章素材，造成“本节有素材”的错觉；
- 检索结果是片段列表，不是“能回应哪条规范/评分点”的证据；
- 正文引用无法快速回答“这句话依据是什么、哪一节还没证据”；
- 解析状态只有 pending/parsing/done/failed，缺少进度、质量、待核对、失败原因。

本项目实测：`material_chunks` 有 1446 段，但当前章节 `chapter_material_chunks` 为 0，说明素材选择/绑定没有形成用户行为闭环。继续堆上传和检索功能，只会放大“有库无用”的问题。

目标不是做一个更完整的文件管理器，而是把素材变成**可被写作消费的证据供应链**：

```
需求 Need（这一节要什么证据）
  → 供给 Evidence（可引用的最小片段/证据卡）
  → 使用 Usage（绑定到节、插入正文、标注来源）
  → 覆盖 Coverage（要求是否被证据覆盖、正文是否有依据）
```

## 2. 目标（可验证）

### G1：节级证据需求可见

- 每个可写章节的每一节，能列出由「本章要求 + 技术规范条款 + 评分点」派生的证据需求；
- 每条证据需求包含：需求文本、来源类型（规范/评分点/编写要求）、覆盖状态；
- 没有证据需求的节明确显示“本节无强制证据需求”，不能伪造需求。

### G2：节级证据绑定生效，不再整章回退

- 用户可把某个已确认片段绑定到指定节；
- 某节没有绑定时，写作上下文明确返回“本节无证据”，**不得回退使用整章其他节的素材**；
- 绑定关系和节名可被 API 查询、可移除、可重复应用（幂等）。

### G3：统一证据卡

- 每个可采用的证据以统一卡片呈现，至少包含：原文摘录、来源文件名/机构/URL、页码或定位、来源类型、可信度/确认状态、适用节/要求、使用状态；
- 用户可从卡片执行：看原文、定位、采用到本节、替换、标记失效；
- 证据卡与底层 `material_chunks` / `citation_chunks` 的对应关系可追溯。

### G4：素材页签以「本章证据」为主视图

- 素材页签默认展示：覆盖摘要、本节证据、推荐证据（最多 3 条）、未标来源；
- 「素材缺口」不再作为素材页签内的并列清单；缺口只在待办出现，素材页保留一行覆盖摘要并可跳转；
- 素材库、上传管理、公开检索默认折叠/次级入口，不再占据主视图。

### G5：上传解析有可理解的状态

- 上传后可见：解析中/完成/失败、进度或阶段、切片数、待核对数、失败原因；
- 支持对片段执行确认/拒绝/待核对；
- 解析失败可重试，失败不会静默消失；
- 不要求本期实现 OCR/表格/图片抽取，但状态和入口必须为后续留出位置。

### G6：写作前能拿到需求驱动的推荐

- 推荐证据的排序依据必须能解释：命中的规范条款/证据需求、关键词、来源类型；
- 推荐结果最多 3 条/节，避免变成第二个素材库；
- 没有可用推荐时明确显示“未找到匹配证据”，不显示空推荐或假装有结果。

### G7：引用覆盖可核对

- 章节可显示：引用总数、未标来源数、按节分组的引用点；
- 每个引用点可定位到对应小节/段落，并能看原文或补来源；
- 每节可显示规范条款覆盖摘要；覆盖不足时给出缺失项，不阻断生成但必须可见。

### G8：联网检索能力诚实可用

- 未配置检索源时，联网检索入口明确提示“当前未配置联网检索”，不得展示可点击但无结果的假入口；
- 配置检索源后，检索查询必须从证据需求生成（至少包含规范条款/评分点关键词），不得只用一个章节标题词盲搜；
- 检索结果先进入证据卡，不直接写入正文。

## 3. 非目标（明确不做）

1. 不在本期做通用文件管理器（文件夹、批量移动、复杂权限）；
2. 不在本期做跨项目素材复用/共享库；
3. 不在本期做素材有效期、审批流、审计日志等企业治理能力；
4. 不在本期强制接入新的 OCR、表格识别或第三方检索 API；
5. 不在本期重写正文生成/评审链路；只改素材如何被选择、绑定、展示、核对；
6. 不在本期自动批量重写旧章节；
7. 不在本期做“所有正文事实必须 100% 有来源”的强阻断；只做可见、可定位、可补。

## 4. 约束与依赖

- 技术约束：FastAPI + aiosqlite + 原生 JS；复用 `material_chunks`、`chapter_material_chunks`、`citation_chunks`、`chapter_materials`；
- 兼容性：旧章节/旧绑定数据可读；新增字段必须可空/有默认值；旧 API 响应保持兼容；
- 数据：现有 `material_chunks` 约 1446 段；`chapter_material_chunks` 可能为空，必须允许从零开始；
- 外部依赖：联网检索依赖已配置的搜索源；未配置时按 G8 降级；
- 时间/人力：按 P0/P1 分阶段交付，先完成 G1–G5/G7，再做 G6/G8 的增强；
- 不允许破坏现有测试与导出链路。

## 5. 验收标准（Definition of Done）

### 自动化

- [ ] 后端全量：`./.venv/bin/python -m pytest -q` 通过；
- [ ] 前端：`node --test tests/frontend/*.test.mjs` 通过；
- [ ] 新增行为有对应测试（API 契约、节级绑定不回退、覆盖摘要、搜索降级）；
- [ ] 文档/接口说明已同步到 `docs/` 或本 spec 的变更记录。

### 行为验收（人工/接口）

- [ ] 任选一个含技术规范条款的章节：素材页默认显示覆盖摘要 + 本节证据 + 推荐证据；
- [ ] 在未绑定任何素材的节写作：上下文明确标记“本节无证据”，不出现其他节素材；
- [ ] 绑定一条证据到节后：该节上下文出现该证据，其他节不受影响；
- [ ] 上传一份文件：能看到解析阶段、切片数、待核对/失败状态，失败可重试；
- [ ] 正文含【来源：X】时，引用清单能按节列出并定位；
- [ ] 未配置搜索源时，联网入口明确不可用；配置后检索查询来自证据需求。

### 评审门槛

## 6. 风险与待决问题

| 风险 | 影响 | 缓解 |
|---|---|---|
| 现有 UI 已形成两套素材入口，重构可能造成用户迷路 | 使用率下降 | 保留旧入口一版，默认新主视图，逐步下线 |
| `chapter_material_chunks` 历史为空 | 无法验证真实行为 | 用测试数据 + 手工绑定路径覆盖；不假设已有数据 |
| 节级绑定后用户仍可能忘记绑定 | 写作仍无证据 | 写作前检查并提示“本节无证据”，推荐最多 3 条 |
| 联网检索源不可用/不稳定 | G8 无法完整验收 | 明确降级状态；不把“去检索”做成假按钮 |
| 覆盖检查误报/漏报 | 用户不信任 | 先展示“覆盖摘要 + 缺失项”，不阻断；保留人工核对 |
| 解析质量差（扫描件/表格） | 证据不可用 | 本期只暴露质量状态与重试；OCR/表格列入后续 |

### 待决问题

1. 「证据需求」是新增表，还是从现有 `requirements + spec_requirements + review_points` 动态派生？本 spec 只要求行为，不锁定实现。
2. 素材页签是否保留“素材库”弹窗作为次级入口，还是改为独立页面？先保留弹窗，主视图重排。
3. “可信度”是否首期只做来源类型（招标文件/客户提供/公开来源/法规标准），还是引入人工评分？首期用来源类型 + 确认状态。
