# SPEC：素材证据工作台：需求动作、覆盖真相、需求驱动采用

- slug：material-evidence-workbench
- 日期：2026-11-05
- 状态：已批准（2026-11-05，人审通过）

## 1. 背景与问题

上一版已经把素材从“文件库”推进到“证据供应链”：

- 有节级证据需求；
- 有证据卡 DTO；
- 有节级隔离，不再回退整章；
- 有覆盖/引用/上传状态。

但当前真实使用仍卡在“最后一公里”：

1. **需求只能看，不能做**：每条证据需求没有“上传 / 从素材库选 / 联网找 / 忽略”动作；
2. **采用不绑定本节/要求**：素材页顶部推荐的“采用”仍以 `section=''` 绑定整章，覆盖检查对不上；
3. **覆盖数字失真**：没有需求时显示“规范覆盖 100%”；
4. **无大纲时像空系统**：章节有要求、但没有大纲，证据需求显示 0，推荐却独立漂浮；
5. **推荐不是需求驱动**：仍以章节画像/关键词为主，会把评分标准、模板、表格误当证据；
6. **空状态没有主行动**：最需要的“上传/选库/检索”藏在「素材库」弹窗里。

本期的目标不是再加一个素材库页面，而是把“看到缺口”变成“能完成补证据”。

## 2. 目标（可验证）

### G1：每条证据需求可操作

- 每条 evidence need 必须返回并展示可执行动作：
  - 上传（上传到本节/本要求）
  - 从素材库选（只选给这条要求）
  - 联网找（有检索源时）
  - 忽略（需记录理由，不能静默消失）
- 需求卡展示状态：`未开始 / 有候选 / 已覆盖 / 已忽略`；
- 没有动作的需求不允许出现在主视图。

### G2：采用必须绑定本节 + 要求

- 所有“采用”动作必须携带 `section` 和 `requirement_id`；
- 绑定写入 `chapter_material_chunks.requirement_id`；
- 采用成功后，该需求立即变为“已覆盖”，并能查到对应证据卡；
- 只有“放入本章、不绑要求”的旧行为保留为兼容路径，但不得在主视图作为主按钮出现。

### G3：覆盖数字必须真实

- 需求数为 0：显示“无强制证据需求”或 `—`，不得显示 100%；
- 有需求、无覆盖：显示 `0/N` + 缺口；
- 有覆盖、无引用：显示“已备未用”；
- 有引用、未标来源：单独显示“未标来源”；
- API 覆盖率在分母为 0 时返回 `null`，而不是 `1.0`。

### G4：无大纲时回退章节级需求

- 章节有大纲：按节展示证据需求；
- 章节无大纲但有本章 requirements/spec clauses：回退为**章节级证据需求**，并明确标注“章节级”；
- 章节无任何要求：显示“本章还没有可执行要求”并给“生成大纲/确认计划”入口；
- 推荐必须挂在需求下，不能在没有需求时独立出现。

### G5：推荐必须需求驱动

- 推荐 query 至少由：evidence need 文本 + 本节标题/要点 + 规范条款 组成；
- 推荐结果必须返回 `matched_need_id`（对应哪条证据需求）和 `reason`；
- 过滤明显不是证据的片段：
  - 原始 Markdown 表格（除非本节明确需要表格）；
  - 评分标准/评分办法/目录/模板/表单类片段；
  - 无正文的碎片；
- 每节最多 3 条推荐，宁缺毋滥；
- 推荐卡必须显示来源、定位、可信度和“为什么推荐”。

### G6：空状态必须有主行动

- 素材页空状态至少提供：
  - `上传文件`
  - `从素材库选`
  - `联网找`（有检索源时；无检索源显示“去配置”而非假按钮）
- 上传入口不得只藏在「素材库」弹窗里；
- 空状态要解释“为什么空”和“做完会发生什么”。

## 3. 非目标（明确不做）

1. 不在本期做 OCR、表格识别、图片抽取的新能力；
2. 不在本期做素材权限、有效期、审批流、审计日志；
3. 不在本期做跨项目素材复用；
4. 不在本期重写正文生成/评审链路；
5. 不在本期把所有素材页改成独立全屏应用；先完成右栏内的任务闭环；
6. 不在本期自动批量补证据或自动批量重写章节；
7. 不在本期引入新的外部检索 API。

## 4. 约束与依赖

- 技术：FastAPI + aiosqlite + 原生 JS；复用 `material_chunks`、`citation_chunks`、`chapter_material_chunks`；
- 数据：`chapter_material_chunks.requirement_id` 已有；无大纲旧章节必须兼容；
- 外部：联网检索仍依赖 `SERPER_API_KEY`，未配置时按 G6 降级；
- 兼容：旧绑定（requirement_id 为空）继续可读，但不计入“已覆盖要求”；
- 不允许破坏现有素材库弹窗、上传、解析、引用、导出链路。

## 6. 风险与待决问题

| 风险 | 影响 | 缓解 |
|---|---|---|
| 需求动作增加 UI 复杂度 | 右栏更拥挤 | 默认只显示主按钮 + “更多”；动作在需求卡内展开 |
| 旧绑定没有 requirement_id | 覆盖率偏低 | 显示“历史绑定未关联要求”，提供重新绑定；不静默丢弃 |
| 推荐过滤过严 | 推荐变少 | 宁可少，不可错；保留“从素材库选”兜底 |
| 无大纲回退章节级需求 | 可能把整章要求套到每一节 | 标注“章节级”，并在有大纲后自动切换为节级 |
| 忽略状态需要持久化 | 新增表/字段 | 用轻量 `evidence_need_actions` 表，不改现有素材数据 |

### 待决问题

1. 忽略状态是按“章节 + 需求”持久化，还是仅会话级？倾向持久化，避免反复出现。
2. 需求动作中的“上传”是上传后自动绑定到该 requirement，还是上传后再选片段？首期采用“上传后自动建议绑定，用户确认”。
3. 无大纲回退时，章节级需求是否显示在“章节”分组而不是伪造节名？是。
