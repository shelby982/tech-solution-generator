为什么难

标书不是"写不出来"，
是写完了还是漏分、废标、返工。

一本响应文件动辄两三百页、上千条要求。人工做，问题不在产能，在"对不齐"。

分

漏分点

评分办法 30 分项下分十几条要素，写着写着就漏了；事后才发现，改动牵一发动全身。

废

废标风险

★ 条款、资格条件、证明材料齐备性——这类问题一条就出局，却和普通问题混在一起看不见。

散

素材散

业绩、资质、参数、政策文件散在十几个附件里，写的时候靠翻，翻到也不敢直接引。

审

不可审计

"这页为什么这么写"说不清；评审意见只有一句"缺细节"，改完也无法证明真的改好了。

常见问题

你可能关心

会不会写出"待补充"这种半成品？

不会。正文红线：不留占位符。缺的内容写成完整但概括的表述；确实需要材料的，转成"需你上传"的待办，并在此前提示。

评审分数能直接当"能不能中标"看吗？

不能，也不该。系统把结论拆成三层：否决风险（会不会废标）、得分预估（能拿几分、缺口在哪）、 交付判断（现在能不能交）。分数只作趋势参考。

评审会不会把一章的问题放大到整项？

不会。得分按已评章节加权折算，未评章节不计入分母并单列"待评"；评分点风险仍按最差章节提示，但不再等价于整项零分。

改完之后怎么知道真的改好了？

问题有状态：未修 → 已修待验 → 已验。应用修改后自动复评审，问题消失才置"已验"； 若仍在，回到"未修"，避免"分数涨了但问题没解决"。

能不能控制成本？

可以。跑量前先给预算（章节数 / 调用次数 / token / 预计耗时）；规则预检零成本； 有硬伤时先走单角色快评，成本约为双角色的一半。

适合多大体量的标书？

从单章到上百章都支持：章节级计划、按节绑定素材、后台批量评审、断点续跑； 目前实测包含 14 章 / 1.9 万字级章节的完整链路。
