# 应答编写方案（总纲）：一条主线、七个环节

> 本文是「应答编写」工作流的**唯一总纲**：先给主线，再给每个环节"要做什么、谁确认、落在哪个界面、
> 用了哪些对象、现在做到哪一步"。此前分散在多个方案里的结论，统一收敛到这里。

---

## 一、主线（一张图）

```
                    ┌──────────────── 全局：编写规范（L0 纪律 + L1 模块配方）────────────────┐
                    │                                                                        │
 解析依据 ──► ① 选型与计划 ──► ② 依据与素材准备 ──► ③ 生成 ──► ④ 质检 ──► ⑤ 修正定稿 ──► 评审与交付
 (上游已有)    一级目录/章节      按"要求"补齐          多 Agent     对照准绳      人工 + 局部重写    导出
               要求/体裁/篇幅      依据 + 素材          主编+3专员    四组检查      版本化
                    │                                    +双审          │
                    └──────────── 闸门①：计划确认 ────────┘            └─ 闸门②：质检清单处置
```

**一句话**：**规范定方法 → 计划定标准 → 依据/素材供弹药 → 多 Agent 生成 → 质检对标准 → 人工收口**。

## 二、七个环节：要做什么

### 环节 0 · 解析依据（上游，已完成）

| 项 | 内容 |
|---|---|
| 输入 | 招标文件、技术规范书（用户上传） |
| 做的事 | 拆标包 → 评分点（分值/分项要素）→ 规范要求（条款 + 强制性 + ★标记）→ 原文点对点结构 |
| 输出 | 标包、评分点、规范条款、原文章节树 |
| 界面 | 阶段①「解析依据」 |
| 状态 | ✅ 已有（含点对点结构检查、层级锁定修复） |
| 谁确认 | 用户核对 |

### 环节 1 · 编写规范（全局，已完成）

| 项 | 内容 |
|---|---|
| 做的事 | L0 全局纪律（论证链/图表/来源/篇幅语言）+ L1 模块配方（每类章节的骨架/必表/必图/失分点），可编辑、多版本、可回滚 |
| 输出 | `writing_specs`（每类一份，带版本） |
| 用途 | 生成时注入提示词；质检时作为"规范级"准绳 |
| 界面 | 顶栏「编写规范」；编写页右栏「编写规范」 |
| 状态 | ✅ 已有（结构化编辑、影响面、版本/回滚、生成留痕） |

### 环节 2 · 编写计划（一级目录 → 章节；部分完成）

| 项 | 内容 |
|---|---|
| 单位 | **技术评分点的一级目录**（评分根的直接子目录），p29 共 7 个 |
| 做的事 | ① 为整棵子树出计划：每章 requirements（**要求**）、tasks（体裁：正文/表/图）、pages（篇幅）、needs（素材需求，由要求派生）② 用户确认/编辑后才能生成 |
| 输出 | `writing_plans.chapters[]`（含 requirements / tasks / pages / needs） |
| 闸门 | **闸门①：计划确认**（未确认时点「AI 编制本章」会先弹计划） |
| 界面 | 左树一级目录行的「编写计划」入口 → 计划抽屉（可编辑）；章头右侧显示所属计划 |
| 状态 | ✅ 计划/确认闸/体裁/篇幅已有；❌ **requirements（逐条要求）与 needs 未做**；❌ 计划不可编辑 |

### 环节 3 · 依据与素材准备（按"要求"补齐）

| 项 | 内容 |
|---|---|
| 依据 | 本章评分点（分值/要素）、承接的规范条款、官方来源 |
| 素材 | 我方材料（上传/关联本章）+ 外部来源（官方/非官方+确认）+ **可用片段**（段落/表格/图） |
| 做的事 | ① 由 requirements 派生素材需求（政策/标准/数据/案例/证明/图片）② 缺口自动检索（官方入口/检索 API）③ 抓取核验（trust）④ 勾选片段「补到需求」⑤ 图片一键入库 |
| 闸门 | 非官方来源必须用户确认；需求待补不阻断（正文写【待补充】） |
| 界面 | 编写页「素材」页签（外部依据 + 本章素材 + 素材状态摘要）；官方来源抽屉（单输入框：检索词/链接） |
| 状态 | ✅ 引用/片段/trust/去重/已引用未引用/多章复用已有；❌ **片段未挂到需求**；❌ 需求级充足度未做 |

### 环节 4 · 生成（多 Agent）

| 项 | 内容 |
|---|---|
| 编排 | 章节主编出任务 → 正文/表格/图示**三路并发** → 王安石（技术）+ 包拯（合规）**双审并发** → 组装 |
| 上下文 | `package` = 字段（评分点/规范条款/原文/材料）+ 编写规范（L0+L1）+ 引用片段 + 计划要求 |
| 做法 | 「AI 编制本章」→ 单章生成；计划确认后可按章并发 |
| 留痕 | `job.artifacts.spec`（规范版本）+ `writing_plans`（计划版本）+ 生成记录 |
| 闸门 | 未确认计划 → 先出计划（闸门①） |
| 界面 | 章头「AI 编制本章」；右栏「编制进度」（角色进度/字数/停止/重试） |
| 状态 | ✅ 已有（真多 Agent、异步、并发、可按角色换模型） |

### 环节 5 · 质检（对照准绳，四组检查）

| 项 | 内容 |
|---|---|
| 准绳 | 规范（骨架/必表/必图）· 计划（要求/体裁/篇幅）· 依据（评分点/规范条款）· 素材（需求/来源） |
| 检查 | A 规范级 6 项 · B 计划级 3 项 · C 依据级 4 项 · D 素材级 4 项（详见《质检-方案》） |
| 输出 | 每章逐条问题：check + level + message + basis（对照哪条准绳）+ location（可跳转）+ actions |
| 视图 | 按章（默认）/ 按检查项 / 按级别；**不给整册总分** |
| 闸门 | 不阻断保存；导出前提示未解决项 |
| 界面 | 编写页「更多 › 质检清单」；右栏「进度/质检」；进度中心待办 |
| 状态 | ✅ 章节级 10 项已有（骨架/表图/空词/篇幅/素材不足/来源未引用）；❌ 未归组、未落库、❌ 要求级/规范条款级未做 |

### 环节 6 · 修正与定稿

| 项 | 内容 |
|---|---|
| 人做的事 | 按质检清单逐条处置（补素材 / 改写法 / 局部重写 / 标为已处理） |
| 系统支持 | 编辑器（正文/表格/预览）、按需求注入片段后**局部重写**、版本记录（每次保存递增，可回滚）、Word 导出 |
| 界面 | 正文编辑区；更多 › 质检清单；「章节版本」 |
| 状态 | ✅ 编辑/保存/版本/导出已有；❌ 局部重写（按需求/按节）未做 |

### 环节 7 · 评审与交付（下游）

| 项 | 内容 |
|---|---|
| 做的事 | 生成评审意见 → 评分点结论（verdict）→ 交付导出（Word，仅含已保存正文） |
| 界面 | 阶段④「评审与交付」；导出入口 |
| 状态 | ✅ 已有（评分点结论页、导出） |

## 三、对象与关系（数据主线）

```
标包 → 评分点（分值/要素）           ┐
      → 规范条款（强制性/★）         ├─ 解析依据（环节 0）
      → 原文章节树（点对点）         ┘

编写规范（L0/L1，版本化）            ← 环节 1（全局一份）

编写计划（一级目录）
  └ 章节条目：requirements[]（要求） ← 环节 2（待建）
              tasks[]（体裁）
              pages（篇幅）
              needs[]（素材需求，由要求派生）← 环节 3（待建）

依据：block.review_point_ids / spec_requirement_ids / criterion_text
素材：chapter_materials（我方）+ citations（外部：trust/segments/selected/links）
片段 ↔ 需求：need_snippets（待建）

正文：blocks.content + 版本（block_revisions）
生成：chapter_writing_jobs（artifacts: chief plan / spec 版本）
质检：quality_findings（待建，open|fixed|ignored）
```

## 四、闸门与状态机

| 闸门 | 条件 | 未通过时 |
|---|---|---|
| ① 计划确认 | 一级目录计划已确认（可编辑后确认） | 「AI 编制本章」先弹计划；子节不再二次确认 |
| ② 来源确认 | 非官方来源需勾选"已核对真实可靠" | 接受按钮禁用；后端 409 |
| ③ 质检处置 | 不阻断；导出前提示未解决项 | 允许导出，但提示"未解决 N 条" |
| ④ 定稿 | 章节状态=完成 / 篇幅达标 | 阶段④可看进度 |

**章节状态**：目录 → 未开始 → 草稿（已生成/已编辑）→ 完成（人工确认）→ 已核对
**运行状态**：解析中 → 待确认计划 → 编写中 → 已完成 → 中断（可重跑）

## 八、验收标准（每个环节"做完"的判断）

| 环节 | 验收 |
|---|---|
| 2 计划 | 打开一级目录 → 每章看到"要求 N 条"，可编辑并确认；未确认时生成被拦 |

| 5 质检 | 每章一条清单，能指到"规范哪条/计划哪条要求/哪条来源"，可跳转 |
| 6 修正 | 质检项可标为已处理；局部重写后该章重新体检 |

## 九、边界（明确不做）

1. **不自动编造事实**：缺证明写【待补充】；外部信息必须有来源（官方优先，非官方需用户确认）。
2. **不替用户定要求**：要求由主编/用户确认；LLM 只起草。
3. **不评分**：质检不给总分，只给可执行的逐条结论。
4. **不阻断**：质检/需求待补都不禁止保存与导出，只提示。
5. **素材只是输入之一**：章节结构由规范+计划决定，素材不决定结构。
6. **一个语义一个 owner**：计划确认只在计划面板、质检只在质检清单、来源只在素材模块。
