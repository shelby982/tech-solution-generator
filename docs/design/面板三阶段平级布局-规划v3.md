# 面板布局：三个平级阶段（规划 v3）

> 用户口径（原话）：
> 「"待确认"其实是目前拆分评审点之后的一个中间环节。按照此逻辑去规划：
>  1. 拆分评审点：拆分商务、技术和技术规范书。
>  2. 待确认：拆分完之后的一个确认环节。
>  3. 产物和对应的映射矩阵：确认完之后，若评审点等拆解没有问题，再去输出对应的目录和映射矩阵。
>  所以，产物跟映射矩阵其实是最终生成的内容，**跟拆分评审点是平级的**。」
> 先规划布局，待确认后再改。

---

## 一、当前布局的问题

现在是一排**扁平页签**：

```
[商务评分点] [技术评分点] [技术规范书拆解] [待确认] [产物·目录] [产物·技术与评分点映射矩阵]
```

问题：**阶段层级被抹平了**。"商务评分点""待确认""产物·目录"看起来是同一类东西，
但实际上它们是三个不同阶段：**拆解 → 待确认 → 产物**。
用户明确要求：产物（目录 + 映射矩阵）**与拆分评审点平级**，作为一个阶段性的最终产物。

---

## 二、目标布局：两级结构（3 个平级阶段 + 阶段内子页签）

```
┌ 筛选（只留标包）─────────────────────────────────────────────────────────────┐
│ 标包 [标的1 / 标包2 · 高可靠技术专题研究与验证标包 ▾]                           │
│ 当前产物：标的1 / 标包2 · 商务+技术（还没生成）                                  │
└─────────────────────────────────────────────────────────────────────────────┘
┌ 阶段导航（三个**平级**阶段）──────────────────────────────────────────────────┐
│   [ ① 拆分评审点 ]  ──▶  [ ② 待确认 ]  ──▶  [ ③ 产物与映射矩阵 ]              │
│     未拆完时 ② 置灰；未确认时 ③ 置灰（置灰处写明"还差什么"）                     │
└─────────────────────────────────────────────────────────────────────────────┘
┌ 阶段内容 ───────────────────────────────────────────────────────────────────┐
│  ① 拆分评审点                                                                │
│     ├─ 子页签：[商务评分点 8] [技术评分点 8] [技术规范书拆解 153]               │
│     └─ 内容：评分因素 / 详细评审项 / 分值 / **结构化评分口径**（逐条条件 + 分值） │
│                                                                             │
│  ② 待确认（拆完才可点）                                                       │
│     ├─ ① 投标范围（标包，来自顶部筛选）                                        │
│     ├─ ② 要生成哪些类别（商务 / 技术 …）                                       │
│     ├─ ③ 技术规范书主题归属（可选）                                            │
│     ├─ ④ 其他待确认项                                                         │
│     └─ [ 确认，生成产物 ]        ← "确认"就是这一阶段的目的                      │
│                                                                             │
│  ③ 产物与映射矩阵（**确认之后才可点**，点确认即生成）                            │
│     ├─ 子页签：[目录 15] [技术与评分点映射矩阵 16]                              │
│     └─ 内容：目录 = 评分因素→详细评审项→细项骨架（含章节树）；
│              映射矩阵 = 评分点 ↔ 技术要求 ↔ 章节                                │
└─────────────────────────────────────────────────────────────────────────────┘
页脚：[重新拆分评审点]（原「重新拆解评分点」）
```

要点：
- **一级 = 阶段**（拆分评审点 / 待确认 / 产物与映射矩阵），三者平级，且前后有依赖箭头；
- **二级 = 阶段内的子页签**（拆解三块、产物两块）；
- 顶部筛选只放**标包**（类别在"待确认"里选，符合上一轮的结论）。

## 三、门控规则（阶段可见/可点）

| 状态 | ① 拆分评审点 | ② 待确认 | ③ 产物与映射矩阵 |
|---|---|---|---|
| 刚上传，未拆 | 可点（空态 + 引导拆解） | 置灰："等拆完" | 置灰："等确认" |
| 拆解中 | 可点（进度） | 置灰："拆解中…" | 置灰："等确认" |
| 三块拆完、未确认 | 可点 | **可点**（默认落在这里） | 置灰："先在待确认里确认" |
| 已确认、生成中 | 可点 | 可点 | 可点（显示"生成中"） |
| 已生成 | 可点 | 可点 | **可点，显示产物内容** |

判定依据（现成数据，不用新表）：
- 拆完 = 该标包各类评分点已落库 + 技术规范书拆解有内容（`spec_requirements` 非空）；
- 已确认 = 运行级作答有 `categories`（+ 投标范围）；
- 已生成 = `outline_pending` 为假且目录有内容。

## 四、默认落地与文案

| 项 | 规划 |
|---|---|
| 展开面板默认阶段 | 未拆完/拆完未确认 → **① 拆分评审点**（子页签 = 该标包第一个类别）；已生成 → ③ 产物与映射矩阵 |
| 阶段导航样式 | 分段控件（segmented）：当前阶段高亮；置灰阶段带 tooltip 说明"还差什么" |
| 文案统一 | 左下按钮与页脚：**拆分评审点 / 重新拆分评审点**（原"拆解评分点"）——见决策 1 |
| 指标条 | 按当前阶段给**该阶段相关**的指标：拆分阶段（商务 n、技术 n、技术规范书 n 条）；确认阶段（待确认 n 项）；产物阶段（目录 n、映射 n） |

## 五、与现状的差异（实施清单）

1. `mode-outline.js` 的 `tabs` 由**扁平 6 项**改为**两级**：
   - 一级阶段数组（含 disabled 判定与 tooltip）；
   - 二级子页签按阶段渲染（拆解三块 / 产物两块）。
2. 默认阶段与默认子页签逻辑（见 §四）。
3. 顶部筛选保持只留标包（不变）。
4. 指标条按阶段切换（现在是六个并列指标，拆解/确认/产物混在一起）。
5. 文案：左下按钮与页脚改为「拆分评审点 / 重新拆分评审点」。
6. 门控 + 交互沿用现有实现（`data-tab` 切换、`openSplitReport({tab})` 保持当前阶段）。

## 六、验收标准

1. 面板顶部出现**三个平级阶段**（拆分评审点 / 待确认 / 产物与映射矩阵），前后有依赖关系；
2. 未拆完：② 置灰并写明原因；未确认：③ 置灰并写明原因；
3. ① 内三个子页签：商务评分点 / 技术评分点 / 技术规范书拆解（该标包没有的类别不显示）；
4. ② 内四个部分 + [确认，生成产物]；
5. ③ 内两个子页签：目录 / 技术与评分点映射矩阵；**确认并生成后**才有内容；
6. 评分口径仍为结构化逐条展示（无折叠、无截断）；
7. 切换阶段/子页签不跳页、不重跑；
8. `__bootErrors = []`；后端 748 passed / 前端 102 passed。
