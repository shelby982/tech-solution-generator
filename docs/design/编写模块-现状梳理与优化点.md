## 二、现在的编写逻辑（as-is，按用户操作路径）

### 1. 进入与页面结构

```
顶栏：项目 › 标包 ▾ | 编写 2% · 待办 2 | 编写规范 · 素材 | 模型
依据条：依据 2 份文件 · 5.3 MB  ⓘ
阶段 rail（①解析依据 ②应答策划 ③应答编写 ④评审交付）
编写工作台：左 目录树 | 中 正文（章头 + 工具栏 + 编辑器） | 右 依据/素材/编制进度（三页签）
```

### 2. 选章

- 左树列出 124 节，每行有状态（目录/未开始/草稿/完成）+ 篇幅进度条
- 点章 → 加载该章：章头（标题 / 状态 / 篇幅：预算·已写·差 / 所属计划入口）+ 正文 + 右栏
- **章节类型**由 `recommend_layout` 按标题猜（"项目理解/技术方案/实施计划/人员业绩/点对点"），只影响**提示词结构与质检配方**，不是"这一章的标准"

### 3. 生成（核心动作）

```
点「AI 编制本章」
  ├ 闸门：本章所属一级目录的计划未确认 → 弹「编写计划」抽屉（不生成）
  └ 已确认 → team.start()
       章节主编出计划（tasks：正文/表格/图示）
         → 正文 / 表格 / 图示 三路并发
         → 王安石（技术）+ 包拯（合规）双审并发
         → 组装 → 保存正文（写 revision）
```
- **粒度：一章一次性**（如 7127 字的那章是一次生成的）
- 上下文 = 评分点 + 规范条款 + 原文段落 + 关联材料 + **编写规范（L0/L1）** + 已接受来源的**选中片段**
- 但 AI 不知道"这一章有哪几条具体要求"，只能按体裁（写正文/出表/出图）发挥

### 4. 编写计划（闸门）

```
左树一级目录行 → 「编写计划 · N 节」→ 抽屉
  · 每章：体裁任务（正文/表/图）+ 篇幅 + 素材缺口（evidence_required，多数为空）
  · 「确认并开始编制」→ 按章起 job，确认过的计划被预置进 job（主编不再重规划）
```
- 计划是**确定性生成**（不调模型、不可编辑）
- 只回答"写什么体裁"，不回答"按什么标准写"

### 5. 篇幅

- 在**应答策划（阶段②）**分配与确认（100 页 / 15 章）
- 编写页**只读**展示（章头：预算/已写/差；左树行内进度条）

### 6. 素材

```
右栏「素材」页签
  ├ 外部依据 N（已引用 x / 未引用 y）  + [添加官方来源]
  └ 本章素材 N（我方材料）+ 上传 + 从项目素材库关联
官方来源抽屉：单输入框（检索词 → 自动找来源；https:// → 核验链接）
  → 候选（命中/未命中标记）→ 抓取核验（trust：官方/非官方+确认）
  → 可用片段（段落/表格/图，筛选/搜索/全选）→ 选用 → 进本章上下文
```
- 片段与"要求"没有对应关系；素材页签只能看"本章有没有来源"，看不到"哪条要求用什么素材"

### 7. 质检

```
更多 › 质检清单（实时计算，不落库）
  检查：骨架落点 / 必表 / 必图 / 空词 / 篇幅偏差 / 素材不足 / 来源未引用
  输出：章级 + 节级 + 一级目录聚合（96 单元 / 通过 2 / 高优 2 / 中优 4）
  点击可跳到章节
```

### 8. 完成与交付

- 「确认本章完成」是**人工判断**（系统不校验）
- 正文每次保存写 revision（可回滚到某版）
- 导出 Word（仅含已保存正文）

## 三、现状的实质特征（五条 PM 提炼）

1. **主线是"章 → 生成 → 改"，不是"要求 → 素材 → 写"**：所有建议/闸门都围绕"这一章怎么写"，没有"这一章要满足什么"的显式对象。
2. **计划是体裁清单，不是标准**：`tasks` 只说"写正文/出表"，不含"必须覆盖哪几个政策/给什么数据"；`objective` 是模板文字。
3. **素材是"来源池"，与正文没有结构关系**：只有"已引用/未引用"的粗判断，无法回答"哪条要求用了哪段素材"。
4. **质检是机械项 + 人工看**：7 项检查全部是"有/没有"类判断，不对照"要求"与"规范条款"。
5. **确认只在生成前**：计划确认是唯一硬闸；生成后没有验收闸（完成靠人工点）。

## 四、可优化点（按影响 × 成本排序）

| # | 优化点 | 影响 | 成本 | 现状依据 |
|---|---|---|---|---|
| **1** | **计划里加"逐条要求"（requirements）并做成可编辑** | ★★★ 主线锚点，解锁素材/质检/进度全部 | 中 | 计划 2 个已生成，均无要求字段 |
| **2** | **生成粒度：章级一次性 → 按节/按条 + 局部重写** | ★★★ 7000 字一次生成难控质量/成本，也难"只改一条" | 中高 | 6 章中有 3 章 >6000 字 |
| **3** | **素材挂需求（片段 × 要求）+ 需求级充足度** | ★★★ 解决"素材与正文看不出关系" | 中 | 2 条来源有片段但未引用；材料关联 0 |
| **4** | **质检：归组（规范/计划/依据/素材）+ 要求级 + 落库 + 一键动作** | ★★☆ 从"整体数字"变"可执行清单" | 中 | 现在只给 96 单元/通过 2 这类汇总 |
| **5** | **依据：本章评分点/规范条款 ↔ 正文的对应** | ★★☆ 让"为什么这样写"可追 | 中 | 依据页只有列表，无对应 |
| **6** | **进度：要求回应率（要求 5 条已回应 3）** | ★★☆ 进度从"字数"升级为"完成标准" | 低（依赖 1） | 现在只有章数/字数/篇幅 |
| **7** | **篇幅在编写页可见可调（单章预算）** | ★★ 现在只能回策划页改整册 | 低 | 篇幅只在策划页设置 |
| **8** | **完成状态加校验（要求回应 + 无高优质检）** | ★☆ 避免"没写完就点完成" | 低 | 完成是纯人工判断 |
| **9** | **AI 稿与人工稿的 diff / 回滚入口** | ★☆ 只有章节版本列表，没有对比 | 低 | revisions 18 条，无 diff |
| **10** | **模型选择从顶栏移到设置** | ★ 低频配置占视觉 | 低 | 顶栏右侧常驻 |

## 五、建议的动手顺序（与总纲一致）

```
第 1 步  优化点 1（计划加要求）＋ 6（要求回应率）
第 2 步  优化点 4（质检归组/落库）— 不依赖要求，可立刻见效
第 3 步  优化点 3（素材挂需求）＋ 5（依据对应）
第 4 步  优化点 2（按节生成 + 局部重写）
第 5 步  优化点 7/8/9/10（体验类小项）
```

**为什么这个顺序**：要求是主线上唯一的空锚点；质检归组能立刻让"体检"可执行；素材/依据挂在要求上之后，
"按节生成 + 局部重写"才有意义（否则还是整章重跑）。

---

## 六、一句话结论

> 现在的编写模块**"工具有了，标准没有"**：计划、素材、规范、质检、进度都在，但彼此的连接点
> 是"章节"，不是"要求"。把"要求"补进计划、让素材和质检都挂到要求上，
> 现有的这些能力才能从"各自可用"变成"一条线可用"。
