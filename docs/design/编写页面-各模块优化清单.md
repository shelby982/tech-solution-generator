## 1. 编写引擎（SSE 作业）

**现状**：`POST /chapter-writes` → 单条 SSE：`job/plan/role/section/delta/chart/todo/done`；正文串行、图表并行、占位符合并、取消/重试/重启恢复都已有。

| # | 优化项 | 优先级 | 说明 / 验收 |
|---|---|---|---|
| 1.1 | **占位符缺失/多余的闭环** | P0 | 现在只发 `error(scope=chart)` 事件，没进待办。要求：占位符无对应图表 → 待办「补图」；图表无占位 → 待办「正文未引用该图」|
| 1.2 | **图表失败后自动重试一次 + 失败原因进待办** | P0 | 现在失败只发事件。要求：失败 1 次自动重试（换图型），仍失败进待办并带原因 |
| 1.3 | **章节级作业支持"按节重跑"** | P1 | 现在 retry 只补未写的节。要求：可指定 `section_index` 重跑单节（不重跑整章）|
| 1.4 | **生成过程可中断恢复 UI 状态** | P1 | 刷新后 `GET job` 能重建"4 头像 + 节进度"，现在只恢复状态文本 |
| 1.5 | **`llm_usage` 行透传 block/section/role** | P2 | 现在三列为空（contextvar 跨任务失效）→ 改显式参数，便于成本归因 |

## 2. 章头（状态 / 工具条）

**现状**：章名 + 状态胶囊（未保存/保存中/已保存·时间/已确认完成/失败）+「编写整章 / 保存 / 编辑·预览 / 插入 / 更多」。

| # | 优化项 | 优先级 | 说明 |
|---|---|---|---|
| 2.1 | **「编写整章」前显示代价预估** | P0 | 现在点了就跑。要求：提示「本章 8 节 · 预计 10 次调用 · 约 3 分钟」，可取消 |
| 2.2 | 编写中支持「暂停/继续」 | P1 | 现在只能整体取消（取消后不落库）|
| 2.3 | 保存状态补「上次保存时间 + 本次改动字数」 | P2 | 现在只有时间 |
| 2.4 | 章头显示"本章质量分/待处理数"入口 | P2 | 与交付检查联动，点击打开交付检查 |

## 3. 编写计划面板

**现状**：只读说明书；大纲逐节可展开看三问（依据/写法/交付物）；「重做大纲」；章节类型。

| # | 优化项 | 优先级 | 说明 |
|---|---|---|---|
| 3.1 | **「写法」升级为硬契约** | P0 | 现状类：事实+来源；目标类：指标名/值/验收口径；行业类：禁复述法条；难点类：问题→影响→措施→验证。生成时注入并校验 |
| 3.2 | 章节契约：理解类章节必含「范围与边界」 | P1 | 现在大纲可缺该节 |
| 3.3 | 评分点矩阵 | P1 | 面板显示：本章对应哪几条评分点 + 每节覆盖情况 |
| 3.4 | 节契约可编辑（低频） | P2 | 现在只读；允许"调整本节写法/交付物" |
| 3.5 | 计划版本对比 | P2 | 重做大纲后显示"新增/删除/改动"的节 |
| 3.6 | 计划与正文偏离提示 | P2 | 正文节与大纲节不一致时在面板标黄（现在靠进度判断"未写"）|

## 十五、验收口径（整体）

1. 一份带「`type=layered` + 任务包 + 14 处【待补充】」的章节，**导出被拦**且逐条可定位
2. 生成后「行业背景」不再复述法条；「现状」每 300 字至少 1 个来源标记
3. 图表缺失/失败会进待办并带原因；插入图表后正文自动有引用句
4. 待办里每一类都能 30 秒内做完（上传/选说法/补来源/生成/补写）
5. 交付检查一处看全：硬门 N / 质量 M / 建议 K，且与导出、确认完成同源
6. 各模块不重复计数（一个概念一个位置）
