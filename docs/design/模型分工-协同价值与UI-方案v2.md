# 模型分工 × 编写场景：协同价值、UI 交互与生成质量（方案 v2）

> 用户提出四件事：①文字精修/修改吃模型能力 → 要能切模型 ②图片也要能切模型
> ③编写本章时展示 3 个头像（主编 / 图片 / 表格）体现协作
> ④重写时展示对应 Agent 的**一个** logo（文字 / 图片 / 表格）
> 并追问：**这几个 Agent 协同有没有必要？价值在哪？**（目前只看到"异步 + 修正"）

---

## 一、先回答：协同有没有必要

### 1.1 诚实结论

**"多 Agent 讨论 / 互相评审 / 投票"这类协同一律不做。**
成本高（N 倍调用）、不可控（互相说服、越改越差）、不可解释（用户不知道为什么变成这样）。

**真正值得保留的协同只有三处**，都是"结构化"而非"对话式"：

| 协同 | 形式 | 价值 |
|---|---|---|
| ① 主编 → 分节 | 一次规划产出"节 + 每节三问"，后续按任务执行 | 让写正文时有**明确任务边界**，不像整章一次生成那样越长越散 |
| ② 图/表 ← 正文 | 图/表由**本节正文**派生，而不是并行"自由创作" | **同源一致**：图不会画正文没有的东西；表不会编数字 |
| ③ 审校 → 待办 | 审校只产出意见，回到待办，**不自动改正文** | 质量兜底且不破坏用户已确认内容 |

### 1.2 你看到的"异步 + 修正"确实是对的，但不完整

| 你看到的 | 实际价值 | 应该怎么做 |
|---|---|---|
| 异步 | 图/表可与正文**并行**，整章更快 | 保留：按节流水线，节内图表并行 |
| 修正 | 靠"另一个 Agent 来改"容易越改越差 | 改为**校验驱动**：机器可判的（节点不在正文、表缺列、字数不足）自动标记为缺口，交给"一键修"或用户 |

**一句话**：协同的价值不在"多个模型聊天"，而在
**分工（边界清晰）+ 同源（图文表一致）+ 校验（可判的自动判）+ 隔离（一个角色失败不影响其他）**。

### 1.3 那三个头像要不要展示

**要，但要展示"分工与状态"，不是"AI 在聊天"。**
用户看到 3 个头像在干活、各自完成，能建立"这一章是有章法的"信任感——这是**可解释性**，不是噱头。

## 二、UI 交互设计

### 2.1 编写整章：3 个头像 + 阶段

```
┌ 编写整章 ────────────────────────────────────────────┐
│  [🧭 主编]        [🖼 图片]        [▦ 表格]           │
│   规划中/统稿中    等待/生成中      等待/生成中         │
│   deepseek-v4-pro  deepseek-flash  deepseek-flash     │
│                                                       │
│  正在写：③ 行业发展背景分析（3/8 节）                   │
│  ██████████░░░░░░░░░░  62%                            │
└───────────────────────────────────────────────────────┘
```

- **主编**：规划与统稿（写正文、控节奏）
- **图片**：按节生成图示
- **表格**：按节生成表格
- 每个头像下方小字显示**当前模型**；点头像 → 换这个角色的模型（本次生效）
- 状态：`等待` / `工作中`（呼吸动画）/ `完成`（✓）/ `跳过`（本节不需要）/ `失败`（红，点开看原因）

### 2.2 重写/精修：单个 logo

```
┌ 重写「政策要求与项目对应关系」────────────────────────┐
│ [✍ 文字编写]  deepseek-v4-pro  [换模型]               │
│                                                       │
│ 优化方向：…（提示词）                                  │
│                                   [取消] [开始重写]     │
└───────────────────────────────────────────────────────┘
```

- **文字内容** → ✍ 文字编写 Agent 的 logo
- **图片调整** → 🖼 图片生成 Agent 的 logo
- **表格重生成** → ▦ 表格 Agent 的 logo
- 写作/生成时：该 logo 在正文预览区左上角**常驻 + 呼吸**，配一行「正在用 deepseek-v4-pro 重写本节…」

### 2.3 图标资产（不引第三方）

用**内联 SVG / 单色 emoji 风格**自绘，跟随主题色，避免加载外部图片：

| 角色 | 图标 | 主色 |
|---|---|---|
| 主编 | 罗盘/笔尖 | 靛蓝 |
| 文字编写 | 钢笔 | 蓝 |
| 图片 | 画框/山形 | 橙 |
| 表格 | 网格 | 绿 |

## 三、模型切换（你要的能力）

### 3.1 两个层级

| 层级 | 位置 | 作用 |
|---|---|---|
| **章节默认** | 更多 → 编写设置 | 一次配好，之后都按这个 |
| **本次覆盖** | 编写整章弹窗 / 重写弹窗 / 图调整弹窗 | 只影响这一次 |

**默认值建议**
- 正文编写：`flash`（快、够用）
- **精修/重写：默认 `pro`**（吃能力，正如你说的）
- 图片生成：`pro`（结构化抽取更准）
- 表格生成：`flash`
- 主编（大纲）：`pro`

### 3.2 可选模型来自现有配置

已有两条配置：`deepseek-v4-pro`（强）、`deepseek-flash`（快）。
选择器显示：`名称 + 强/快` 标签 + 推荐标记（精修场景标"推荐"）。

### 3.3 记忆

- 每个角色记住**上次选项**（localStorage + 项目设置）
- 精修弹窗里显示「上次用：deepseek-v4-pro」

## 四、实际编写逻辑（后端编排）

```
整章编写（SSE 一路到底）
  ① 主编：读计划（已存在则跳过）→ 产出"节 + 三问"
  ② 逐节循环（串行）：
      text(流式) → 本节正文
      ├─ 需要表？ table → 表格（列名来自交付物）
      └─ 需要图？ diagram → 图示（**输入=本节正文**）
      校验（见第五节）→ 缺口
  ③ 汇总：缺口进待办；正文可保存
  失败隔离：图/表失败 → 待补，正文照常完成
```

**接口约定**
- `/studio/section/stream` 增加 `role`（默认 text）+ `model`
- `/studio/diagram`、`/studio/table` 增加 `model`
- SSE 增加 `stage` 事件：`{role, state, section, model}` → 直接驱动 3 个头像

**重写/精修**
- `role` 决定用哪个 Agent（text/diagram/table）→ UI 显示对应 logo
- `model` 由"本次覆盖 > 章节默认 > 系统默认"解析
- 文字精修：注入 **原文 + 提示词 + 依据 + 交付物 + 字数下界**；保留表名/图块/引用

## 五、生成质量（这是根本）

### 5.1 文字

| 措施 | 说明 |
|---|---|
| 精修必带原文 | 让模型"改"而不是"重写一篇" |
| 字数下界 | 精修后不得低于目标字数 80%，否则标"缩水" |
| 引用保留 | 原文里的【来源】不得丢 |
| 术语表 | 统一用词（营销管理系统 / 南方电网…）|
| 依据注入 | 本节 basis 必须被引用到（可校验关键词）|

### 5.2 图片（最容易被"编造"的地方）

| 措施 | 说明 |
|---|---|
| **图由文生** | diagram 的输入就是本节正文（不额外自由生成）|
| **节点可溯源**（硬校验）| 图中每个节点名必须能在本节正文里找到对应词，否则标"图与文不一致" |
| 节点数 2–12 | 超限自动修正 |
| 不编数字 | 图中出现正文没有的数字 → 标记待核对 |
| 图型按交付物 | 交付物要"层次图"就不能出流程图 |

### 5.3 表格

| 措施 | 说明 |
|---|---|
| 列名来自交付物 | 交付物给了列名就照着来 |
| 数字来自正文/素材 | 不许新造数字 |
| 表名统一 | 上方 `**表：名**` |
| 与正文数字一致 | 轻量校验（表内数字应出现在正文）|

### 5.4 校验失败怎么办

- **不让预览/导出失败**（已修的坑）
- 缺口进「待办」的 `auto` 组（可一键修复）或 `proof` 组（要你核对）
- 每个缺口带"为什么"（第 5.2 的溯源证据）

```

  ├ 主编（规划/统稿）   [pro]
  ├ 文字编写            [flash]

  └ 表格生成            [flash]
```

本次覆盖只在弹窗里，不写回默认（除非勾"设为默认"）。

## 七、验收标准

1. 编写整章时正文上方出现 **3 个头像**（主编/图片/表格），状态随 SSE `stage` 变化
2. 重写时出现**单个** logo：文字→✍、图片→🖼、表格→▦
3. 每个 logo/头像旁显示**当前模型**，可一键切换（本次生效）
4. 文字精修**默认 pro**；可在弹窗里改；选择被记住
5. 图片/表格生成可单独换模型
6. 图片硬校验：节点必须能在正文找到依据，否则进待办（不静默）
7. 精修后字数不低于目标 80%，引用未丢，表名/图块保留
8. 图/表失败不影响正文完成；缺口标注原因
9. 章节默认与本次覆盖两个层级都生效（覆盖不污染默认）
10. 无控制台错误；自检覆盖 1/2/3/6
