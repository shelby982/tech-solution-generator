# 待办内容审核（第三轮）：为什么用户还是看不懂，以及怎么改

> 用户反馈（原文）：「除了上传的，其他我还是看不懂。"待确认"需要我确认什么呢？
> 这部分内容并且原文中都没有，你需要我确认什么，我还是不太看懂。」
> 要求从 **产品经理 / 易用性 / 应标人员操作流程** 三个角度深度分析。

---

## 一、先认账：这轮暴露的是**内容可信度**问题，不是文案问题

上一轮我把"检查器语言"换成了"动词标题"，但用户仍然看不懂 —— 因为真正的问题是：

**待办里报了正文里根本不存在/不成立的"问题"，用户当然无法确认。**

### 1.1 实测抓到的假阳性（已修）

| 卡片（上一版） | 检查器说法 | 原文实际 |
|---|---|---|
| 核对 **3 处**引用来源 | 「引用未标来源：《网络安全法》/《数据安全法》/《个人信息保护法》」| **同一段落末尾明明有** `【来源：中华人民共和国网络安全法】【来源：数据安全法】【来源：个人信息保护法】` |
| 原因 | `citation_items` 按**句子**判断有无【来源】| 标书常见写法是**段末统一标来源** |

**这是最严重的一类问题**：用户打开正文一看"来源就在那儿"，从此不再信任整个待办。

已修：改为**按段落**判断（同段任何位置有【来源】就不报），实测从 3 条假阳性降为 **2 条真实**。

### 1.2 "待确认"到底要确认什么 —— 用户问对了

当前 `confirm` 类卡片（「核对 3 处引用来源」）的三宗罪：

1. **没有对象**：用户不知道要确认哪句话/哪张图/哪个表；
2. **没有标准**：确认"对/不对"的依据是什么？
3. **没有动作**：确认完要做什么？（改？保留？）

结论：**"确认"只有在"系统产出了具体东西、需要人点头"时才成立。**
当前系统没有把产出物（生成的图表/补写内容）带到待办里，所以这一类别**不该存在**。

## 二、三个角度的审核

### 2.1 产品经理角度：待办的"信噪比"决定它有没有用

| 原则 | 现状问题 | 改法 |
|---|---|---|
| **只报"确定成立"的问题** | 引用来源假阳性 | 检查器口径修正（按段落）+ 单测覆盖 |
| **只报"人能解决"的问题** | 系统任务混在待办 | 系统任务单独区，且每条都有"现在就做" |
| **只报"用户能定位"的问题** | 有的条目原文里找不到 | **硬规则**：原句必须能在正文逐字找到，否则不进待办 |
| **同一条只出现一次** | 11 条依据 → 11 张卡 | 合并成 1 张（已做）|
| **不解释系统内部语言** | 「待确认」「口径」「阻塞」 | 换成人话 + 说明后果 |

**一句话**：待办的价值不是"我检查出多少问题"，而是"**用户敢照着做**"。宁可少报，不可错报。

### 2.2 易用性角度：每条必须能"30 秒内决定做什么"

用户的真实阅读路径是：**标题 → 我能做什么 → 在哪 → 做完什么样**。所以每条卡必须有四要素：

| 要素 | 差的例子 | 好的例子 |
|---|---|---|
| 标题 | 核对 3 处引用来源 | **补 2 处引用来源** |
| 原句 | （无）| 「本项目总体目标是在满足《中华人民共和国网络安全法》…」|
| 为什么 | 影响评分/可读性 | 「这段引用了《网络安全法》却整段没有【来源：…】；评委会问出处」|
| 动作 | 定位 | **[去补来源]**（打开检索，选中后插到引用处）|

另外：
- **候选必须来自原句**，不能是通用模板。
  差的：「把这句改成「拟按最小必要原则明确…」」（跟原句无关）
  好的：「改为「**拟在实施阶段明确数据分类分级与权限控制规则**」」（把原句的主语拿过来）
- **定位必须高亮到正文那一段**（现在：切预览 + 黄色高亮 4 秒 + 状态条给"第 7 段"）。

### 2.3 应标人员操作流程角度：只有 4 种真实动作

应标人员看到待办后，实际只可能做四件事。**待办条目必须能映射到其中一种，否则就是噪音**：

| # | 真实动作 | 触发场景 | 系统需要提供 | 做完怎么算好 |
|---|---|---|---|---|
| 1 | **补材料**（上传/从素材库选） | 缺业绩、资质、合同、内部数据 | 说清要什么格式、用在哪、影响几章 | 上传后自动绑定 + 复检通过 → 消失 |
| 2 | **定说法**（从候选里选 / 自己写） | 原文有这句话，但口径/承诺/表述需要定 | 原句 + 2~3 个**贴合原句**的改法 + 后果 | 服务端替换 + 写版本 → 复检通过 → 消失 |
| 3 | **补内容**（写一段 / 让系统写） | 原文**缺**这块内容（不是改，是新增） | 说清缺在哪、要多少字、谁写 | 插入到指定位置 → 复检 |
| 4 | **确认系统产出**（看再点头） | 系统生成了图表/补写了段落 | **必须先把产出物展示出来** | 插入正文 / 重新生成 / 不要 |

**凡是不属于这四类的条目，一律不进待办**（降级为"系统处理中"或"建议"）。

当前实现映射：

| 待办卡 | 属于 | 状态 |
|---|---|---|
| 上传 1 份业绩材料 | ① 补材料 | ✅ 可用 |
| 定 2 处口径 | ② 定说法 | ✅ 候选已由原句派生 |
| 补 2 处引用来源 | ② 定说法（补来源也算定表述）| ✅ 已改动作「去补来源」 |
| 补 11 条依据原文 | ③ 补内容（系统先做）| ✅ 有「现在去查」|
| 生成表格/图示 | ④ 确认系统产出 | 🟡 有「现在生成」，但生成后**还没回到待办做"确认"** |
| 本节偏长 | — → 建议区 | ✅ 不算交付门 |

## 三、这轮实际改了什么（已落地）

### 3.1 检查器可信度

| 改动 | 文件 | 效果 |
|---|---|---|
| 引用来源检查改为**按段落** | `services/todo_checks.py` | 项目 29 假阳性 3 → 0；真实项 2 条保留 |
| 决定项**跳过表格行**（上一轮）| 同上 | 不再把单元格拼成"原句"|

### 3.2 待办准入硬规则（v3 §5.4 落地为代码）

```python
# todo_tasks._locatable()
带原句的任务：原句去掉空白后必须能在正文里找到；找不到 → 不进待办
```
效果：**"原文里没有"的条目从此不会再出现**（这正是用户最不能接受的）。

### 3.3 内容改写

| 之前 | 现在 |
|---|---|
| 核对 3 处引用来源 [定位] | **补 2 处引用来源 [去补来源]** |
| 核对 引用未标来源：《网络安全法》（why 是整段证据噪音）| why：这段引用了《网络安全法》却整段没有【来源：…】；评委会问出处，补上来源即可 |
| 候选是通用模板「拟按最小必要原则明确…」| 候选**从原句派生**：「拟在实施阶段明确**数据分类分级与权限控制规则**」|

### 3.4 动作闭环

| 动作 | 行为 |
|---|---|
| 上传 | 打开素材面板 + 上传后自动复检 |
| 定说法（候选）| 服务端按原句替换 + 写版本 + 重算待办 |
| 去补来源 | 定位到该段 + 打开检索（选中后插入引用）|
| 现在去查 / 现在生成 / 现在补写 / 现在统一 | 立即执行（不再"下次生成"）|
| 定位 | 切预览 + 黄色高亮 4 秒 + 状态条给"第 N 段 + 原句" |

## 四、还没解决的问题（如实列出）
