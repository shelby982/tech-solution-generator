# 编写计划（可执行版）方案：从"字段堆砌"到"施工图"

> 用户原话：**"虽然放了一堆字段，但对于应答人员来讲，还是不知道要写什么、怎么写。"**
> 目的：每一章的计划里必须明确给出 —— (a) 怎么写、写哪些东西；(b) 对内要求、评分点；
> (c) 写多少字多少页。编写人员要能**照着它**去调整已有内容、改 AI 稿、补素材。

---

## 一、应答人员的真实动作（先想清楚场景，再设计内容）

一个应聘人员打开某一章，只会做三件事之一：

| 动作 | 他此刻需要什么 | 现有计划给了吗 |
|---|---|---|
| **写**（新写 / 从 AI 稿改） | 这章分几块写、每块要答哪几点、每块多少字 | ✗ 只有"写清楚「背景」" |
| **改**（已有正文，按计划调） | 哪一段超了/缺了、缺哪个必答点、差多少字 | ✗ 只有"计划 12 页 · 已写 26 页" |
| **补**（素材/表图缺） | 缺哪几份料、哪几张表、去哪找 | ✗ 只有"素材待补 5" |

**结论**：计划的每一块内容，都必须能直接回答"**我现在该写哪一段、写几句、用什么料**"。
否则就是"看起来高大上、实际落不下去"。

## 二、当前计划为什么不可执行（逐项对照实测）

实测：子章「项目背景现状目标」评分点 1 个、**规范条款绑定 0 条**、已写 6532 字、计划 12 页（自动分配）。

| 现在显示的内容 | 为什么不可执行 |
|---|---|
| 要求：**写清楚「背景」** | 这是标签不是指令 —— 背景要写什么？（项目由来/政策依据/建设动因/现状问题）|
| 依据：对项目的理解正确、深入、全面（10 分）| 评分点**原文没展开**（满分档要求什么、怎么得分、怎么失分，看不到）|
| 产出要求：政策依据映射表（文件/要求/对应工作）| 有表头，但"**填几行、每行从哪来、示例**"没有 |
| 计划 12 页 · 已写 26 页（超 14 页）| **12 页怎么分到 3 个要求？** 每段写多少字？不知道 |
| 素材待补 5 | 补什么？（政策原文 2 份？数据 1 套？）去哪找？|
| 父章：本章只写总述，概述下列 7 节要点 | **哪 7 节？各节写什么？总述写多少字？** |
| 完成判定：3 条要求正文未回应 | 哪 3 条？在哪一节？差多少？|

**根本原因有两个**：
1. **"必答点"这一层没有建**：从"背景"到"写什么"之间少了一层"背景要答哪几个点"
2. **招标条款没有挂到章节**：153 条技术规范条款里，本章该满足的几条一条都没绑（实测 `spec_requirement_ids` 为空）
   → "对内要求是什么"无从体现

## 三、目标：每章计划必须回答的 6 个问题

```
① 这章要交出什么（交付物清单，逐条可勾选可定位）
   [文字] ①建设背景   600–800 字  ← 必答：项目由来 / 建设动因 / 政策依据 / 现存问题
   [文字] ②现状与差距 500–700 字  ← 必答：现状数据 / 主要问题 / 与目标的差距
   [表格] ③政策依据映射表  6–10 行 ← 表头：文件 / 要求 / 对应工作
   [图示] ④趋势对比图               ← 内容：2021–2025 关键指标趋势
   （父章：①总述 300–500 字 + ②子节索引）

② 对内要求与评分点（为什么这么写）
   · 评分点原文（满分档）：深刻理解项目背景、现状、目标…分析全面准确、描述详细，得 8–10 分
   · 本章承接的招标条款：1.4.1 组织保证（强制性）→ 要求"明确项目组织保障措施"
   · 失分点：只复述招标文件 / 没有现状数据 / 目标与现状混淆

③ 写多少（可执行的字数分配）
   计划 12 页 = 3000 字
   ├ ①建设背景  600–800 字   已写 1200 字 → 超 50%，建议精简
   ├ ②现状与差距 500–700 字  已写 0 → 缺
   ├ ③政策依据映射表 6–10 行  已写 1 张表（8 行）→ 达标
   └ ④趋势对比图             已写 0 → 缺

④ 素材清单（要什么料，从哪来）
   · 政策原文 ×2（官方来源）    已有 1 / 缺 1   [去找]
   · 现状数据（我方运维报告）     缺            [上传 / 关联]
   · 2021–2025 指标数据         缺            [去找 / 从材料提取]

⑤ 怎么写（写法指令，不是套话）
   · 顺序：先结论后论证；背景 → 现状 → 差距 → 目标
   · 每段第一句必须是判断句（"本项目建设具备必要性，依据有三"）
   · 表后必跟一段"从表可见…"的落点

⑥ 写完自检（可勾，作为"完成"}判定依据）
   □ 4 个交付物都在
   □ 每段字数在区间内（±15%）
   □ 3 条必答点都能在正文找到
   □ 引用外部信息带【来源】
   □ 表 1 张、图 1 张
```

## 四、每块内容的数据来源（这是"能不能做出来"的关键）

| 计划块 | 数据来源 | 现状 |

| ① 交付物清单 | 参考文档同章骨架（8 类模板：背景→项目由来/动因/政策依据/现状问题）+ 本章评分点要素 | 🟡 模板有，**没展开成必答点** |
| ② 对内要求 | 评分点原文（已有 `review_points.criterion`）+ **招标条款 → 章节匹配**（153 条，需新增） | ✗ 条款未绑定 |
| ③ 字数分配 | 计划页数 × 250 字，按交付物加权（表≈300 字/张、图≈200 字/张） | ✗ 未做 |
| ④ 素材清单 | 按交付物类型映射：政策类→官方原文；数据类→我方材料/外部数据；案例→业绩 | ✗ 未做 |
| ⑤ 写法指令 | 编写规范 L1 配方（已有骨架/失分点）+ 参考文档写法（先结论后论证） | 🟡 配方有，未落到"每段一句指令" |

**要新增的两件底层数据**：
1. **条款 → 章节匹配**：把 153 条技术规范条款按主题/关键词挂到章（多条↔多章），强制性(★/mandatory)优先
2. **必答点表**：每章 3~8 条"必须回答的点"（由评分点要素 + 条款 + 参考骨架合并去重生成，可编辑）

## 七、分期实施

| 期 | 内容 | 能解决 |
|---|---|---|
| **D1** | ①标书条款→章节匹配（可编辑）②评分点满分档原文进"对内要求" | "对内要求是什么"终于有内容 |
| **D2** | ③必答点（每章 3~8 条，逐条可编辑）④交付物清单 + 字数分配（表图折算）+ 已写差额 | "写什么、写多少"可执行 |
| **D3** | ⑤素材清单（类型/数量/现有-缺/去哪找）⑥自检清单 + 与正文定位联动 | "补什么、怎么写"可执行 |
| **D4** | 父章统筹视图（子节表 + 总述写法）+ 父章页数=总述+子节汇总 | "副章节统筹子章节" |

## 八、边界（明确不做）

1. **不替代正文编辑**：计划只给"指令"，不在这里写正文
2. **必答点不穷举**：每章 3~8 条，宁可少而准
3. **字数给区间**（±15%），不精确到字
4. **素材清单只到"类型+数量+用途"**，不指定具体文件
5. **条款匹配允许人工修正**（自动匹配必然有偏差）

---

## 九、一句话总结

> 现在的计划是"**目录的注脚**"（有哪些要求、几页），
> 要变成"**施工图**"（这一段写什么、答哪几点、多少字、用什么料、写完怎么验）。
> 关键是要新增两层数据：**招标条款→章节**的匹配，和**每章的必答点**。
