# 素材库重构方案 v2：三块内容 + 片段挑选器 + 素材接入 AI 编写

> 用户口径（本次）：
> 1. 「我上传的 / 联网搜索的」不要左右两块，**用页签切换**，切换后只展示当前页签内容；
> 2. 素材库实际分三块：**① 当前已有的素材 ② 我上传的文件 ③ 联网搜索的来源**；
> 3. 文件与来源要能 **增删改查**；
> 4. 解析结果很多，需要一个好的交互**从文件/文章/网页里挑出需要的片段**；
> 5. 素材产出后**如何接入 AI 编写过程**，也需要交互设计。
>
> 本文是整体方案（先设计，确认后实现）。

---

## 一、问题归纳

| 现状 | 问题 |
|---|---|
| 素材库弹窗里左右两列平铺 80 + 66 条 | 信息过载；无法"按文件/按来源"管理，也无法增删改 |
| 素材 = 解析片段（已有 531 段）| 片段是**解析产物**，不等于"我决定用的素材" |
| 从解析结果里挑片段 | 现在只能滚动 80 条 checkbox → 找到目标段落极难 |
| 素材如何进入 AI 编写 | 现在只有"应用到本章"一个动作，看不出"用在哪个小节、以什么方式用" |

**核心判断**：
- **素材库管理的是"三类对象"**：文件（原料）→ 来源（网页/文章）→ 素材（我从原料里挑出来的片段）
- **解析只是把原料拆开**；**挑片段**是人的动作；**素材**是挑的结果
- **素材接入编写**需要两级：章节级"用哪些" + 小节级"怎么用"

## 二、信息架构：素材库 = 三个页签

```
素材库
┌ 页签：[素材 42] [我的文件 6] [联网来源 2]           🔍搜索   ＋新增 ┐
│                                                                  │
│ ① 素材页签：我从文件/来源里挑出来的片段（真正可用的东西）            │
│    按来源分组：                                                    │
│    ▸ 广东电网…pdf（来自文件）· 18 条片段                            │
│    ▸ 中共中央 国务院关于发展新质生产力…（来自联网）· 24 条            │
│    每条：片段文本 + 位置（第 3 页 / 网页）+ 被哪些章节引用             │
│                                                                  │
│ ② 我的文件页签：上传的文件（原料层，可增删改）                        │
│    [＋上传文件]                                                    │
│    · 广东电网…pdf · 477 段 · 已挑 18 条      [查看片段] [重新解析] [删除] │
│    · 技术招标文件.docx · 54 段 · 已挑 0 条    [查看片段] [重新解析] [删除] │
│                                                                  │
│ ③ 联网来源页签：搜索得到网页/文章（原料层，可增删改）                  │
│    [＋联网搜索]                                                    │
│    · 发改委答记者问 · 2026-10-10 · 40 段 · 已挑 24 条  [查看片段] [删除] │
└──────────────────────────────────────────────────────────────────┘
```

**为什么这样分**
- 「文件/来源」= **原料**，低频、批量、要管理（上传/重解析/删除）
- 「素材」= **结果**，高频、要看、要用（挑出来能引用的东西）
- 同一个片段在"文件"里是**候选**，挑中后进"素材"——**这就是"解析→挑选"的过程**

## 三、核心交互：片段挑选器（从原料里找内容）

点文件/来源的「查看片段」→ 打开**片段挑选器**（全屏大弹窗，三栏）：

```
┌──────────────────────────────────────────────────────────────────────┐
│ 广东电网…pdf（477 段）      🔍[关键词123]  筛选[含数字▾][含条款▾]  ☑全选命中  │
├──────────────┬──────────────────────────────────────┬────────────────┤
│ 目录/页码     │ 片段列表（虚拟滚动，命中高亮）          │ 已选 3 条        │
│ 第1页 ▸       │ ┌──────────────────────────────────┐ │ · 招标范围…第3页 │
│ 第2页 ◂当前   │ │ ☑ 2.1 招标范围…（命中 2 处）       │ │ · 资格要求…第4页 │
│ 第3页         │ │  ☐ 2.2 项目概况…                  │ │ · 投标人资格…第4页│
│ 第4页 ▸       │ │ ☑ 3. 投标人资格要求…              │ │                │
│ 第5页         │ │ …（每段 2~4 行，可展开看全文）      │ │ [清空]          │
│ …             │ └──────────────────────────────────┘ │                │
│              │ 每页 20 条 · 共 24 页                │ [加入素材]       │
└──────────────┴──────────────────────────────────────┴────────────────┘
```

**关键交互（解决"内容太多怎么找"）**

| 手段 | 作用 |
|---|---|
| **关键词搜索 + 命中高亮** | 输入"业绩/资质/数据"，直接定位到含该词的片段，命中数显示 |
| **目录/页码跳转**（左栏）| 招标文件按章节/页码导航，快速到达"第三章 投标人资格" |
| **结构化筛选** | 只看「含数字」「含条款号」「表格」「政策文件名」——找依据/指标时最有效 |
| **批量选择** | 全选当前页 / 全选命中结果 / 按章节全选 |
| **AI 预筛（推荐）** | 顶部「按本章需求推荐」：用本章各节要点做关键词匹配，直接给 Top 10 候选片段 |
| **已选面板（右栏）** | 随时看到选了哪些、可移除、点条目定位回原文 |
| **确认即素材** | 点「加入素材」→ 这些片段成为素材（带来源与位置），进入「素材」页签 |

**方案 C 的语义不变**：解析即可用，**挑 = 建立素材**（无需再"确认"一遍）。

## 四、素材 → AI 编写：两级接入

### 4.1 章节级：本章用哪些素材

位置：编写页签「本章素材」/ 素材页签「本章引用」旁（其实两者是同一份数据的两面）

```
本章素材 6   [选素材]
· 招标文件 · 第 3 页「招标范围…」      用法：引用出处  → 正文【来源：…】
· 招标文件 · 第 4 页「投标人资格…」    用法：引用出处
· 发改委 · 2026-10-10「…以标准提升…」  用法：数据依据
· 我方材料 · 现状数据「业务量 12 万笔」 用法：粘贴原文
                                    [调整用法 ▾]
```

**三种用法（写进生成提示词的方式不同）**

| 用法 | 生成时怎么用 | 正文表现 |
|---|---|---|
| **引用出处**（cite）| 只把"来源标签"给模型，模型引用时标【来源：X】 | 句尾【来源：广东电网…pdf（第 3 页）】|
| **数据依据**（data）| 把片段内容（可截断）注入，模型据此写数字/事实 | 句子含具体数字 + 【来源：…】|
| **仅上下文**（context）| 注入但**不允许**出现在正文（避免抄全文）| 无标注，只影响写法 |

### 4.2 小节级：哪一节用哪条素材（可选，进阶）

```
计划面板 → 某节 → 「本节素材」：可指定 1~3 条（不指定则用本章素材全集）
```

**为什么需要**：避免"政策依据节的素材被注入到目标节"，提高生成相关性。

### 4.3 生成时的注入规则（确定性）

```python
prompt 注入 = 本章素材(用法=cite 的 → 只给 source_label)
            + 本章素材(用法=data 的 → 给片段文本 ≤300 字)
            + 本章素材(用法=context 的 → 给片段文本 ≤500 字)
            + 本节素材（若有，优先）
未加入素材的片段：不进提示词
```

生成后：正文里的【来源：X】由模型标注 → 引用清单可追溯到素材（已实现）。

## 五、数据模型（在现有基础上调整）

| 层 | 表 | 说明 |
|---|---|---|
| 原料-文件 | `materials` | 已有（filename/role/parse_status）→ 加 `deleted_at`（软删）|
| 原料-来源 | `citations` | 已有（url/title/domain/published_at）→ 加 `deleted_at`（软删）|
| 解析片段 | `material_chunks` / `citation_chunks` | 已有（page/chunk_index/content）|
| **素材** | `materials_library`（新） | `(id, project_id, source_type upload|web, material_id|citation_id, chunk_id, title, label, excerpt)` ← **挑中的片段** |
| 章节引用 | `chapter_material_chunks` | 已有（block_id, chunk_id, chunk_kind, mode）→ mode 扩展为 `cite|data|context` |
| 小节指定 | `chapter_section_materials`（新，可选） | `(block_id, section, chunk_id)` |

迁移：现有 `material_chunks.status='confirmed'`（1634 段）→ **不自动变素材**（它们是候选）；
素材页签现有数据 = `chapter_material_chunks`（0 条）。首次使用时需用户挑一次（或提供"全选整份文件"快捷）。

## 六、增删改查（文件与来源）

| 操作 | 文件 | 来源 |
|---|---|---|
| 增 | 上传（多选，支持 PDF/Word/Excel）| 联网搜索（关键词 → 结果列表 → 选择入库）|
| 删 | 删除（软删，连带其片段从素材中移除并标"已失效"）| 删除来源 |
| 改 | 重新解析（换切片策略/更新文件）| 更新来源（重新抓取）|
| 查 | 列表（文件名/段数/已挑数/解析状态）| 列表（标题/日期/域名/段数/已挑数）|

## 九、分期

| 期 | 内容 | 验收 |
|---|---|---|
| **M1** | 三页签结构（素材 / 我的文件 / 联网来源）+ 文件/来源的增删改查 | 能上传、删除、重新解析；素材页签按来源分组 |
| **M2** | 片段挑选器（搜索 + 目录 + 筛选 + 批量 + 已选面板）| 从 477 段里 30 秒内挑出"投标人资格"相关 3 段 |
| **M3** | AI 预筛推荐（按本章节要点匹配 Top 10）| 推荐命中率可接受（人工评测 3 章）|
| **M4** | 素材 → 本章（用法 cite/data/context）+ 生成注入规则 | 生成后正文引用可追溯到素材；context 素材不出现在正文 |
| **M5** | 小节级素材指定（可选）| 指定后只在该节注入 |
