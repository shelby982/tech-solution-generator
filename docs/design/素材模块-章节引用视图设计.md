# 「素材」模块设计（章节编写上下文）：引用可追溯优先，素材库降级

> 用户口径：素材库适合"一次性上传/质量较低"；这一块优先展示**本章引用了什么、来自哪**；
> 上传功能折叠或降低优先级。重点 = 能看到本章节引用了什么素材、对应来源是什么。

---

## 一、先想清楚：用户站在"写这一章"的位置，要回答三个问题

| 时序 | 用户在问什么 | 素材模块该给什么 |
|---|---|---|
| 写之前 | 「这一章我能用什么料？」 | 推荐/可用的素材（少量、相关）|
| 写之中 | （AI 在引用，用户不看）| 进度足够，素材不占位 |
| **写之后** | 「**这段凭什么这么说？出处在哪？**」 | **引用清单 + 来源 + 可点开原文** |

结论：**主视图是"引用台账"（citation ledger），不是"文件管理"。**

---

## 二、当前 UI 的问题（对着现有实现）

| 现在 | 问题 |
|---|---|
| 顶部「需要你上传的材料」 | 招标硬性要求才该出现，出现在「素材」里会造成"这里总有事"的感觉 |
| 「本章素材 3」+ 平铺列表 | 只有"有哪条"，没有"用在哪一节/哪一段" |
| 「素材库 531 段已确认」+ 80 段列表 + 复选框 | 素材库是**低频管理动作**，却占据主视觉，压制了真正重要的"引用" |
| 待确认 66 段 | 与素材库同级展示，噪音大 |
| 底部「外部依据 / 已关联素材」折叠 | 第三套列表，与上面重复 |

---

## 三、设计：三层优先级（引用 > 待确认 > 素材库）

```
素材（本章）
┌──────────────────────────────────────────────────────┐
│ ① 引用清单（默认全部展开）                            │
│   本章引用 8 处 · 来自 4 个来源 · 未标来源 2 处        │
│                                                      │
│   项目政策依据梳理                                    │
│   · [招标文件 p12] 「…须在验收阶段提交…」             │
│       ↗ 正文第 3 段   [看原文] [定位] [换来源]        │
│   · [公开来源 发改委 2026-10-10] 「…以标准提升…」      │
│       ↗ 正文第 5 段   [看原文] [定位] [换来源]        │
│                                                      │
│   现状差距分析                                        │
│   · [我方材料 现状数据] 「业务量 12 万笔/年」          │
│       ↗ 正文第 2 段   [看原文] [定位]                │
│   · ⚠ 本段有数据但没有【来源】                        │
│       [系统补来源] [手动添加来源]                     │
│                                                      │
│ ② 待确认（有才出现，一行）                            │
│   ▸ 有 12 段素材待确认   [去确认]                     │
│                                                      │
│ ③ 素材库（折叠，默认收起）                            │
│   ▸ 素材库 · 531 段已确认   [搜索/选择应用到本章]      │
│   ▸ 上传素材（PDF/Word/Excel）· 管理素材库 ›          │
└──────────────────────────────────────────────────────┘
```

**为什么这样排**
1. 写完之后用户 90% 的时间在核对"引用是否成立" → 放第一；
2. 待确认是"有事要做"，但不需要常驻 → 一行提示即可；
3. 素材库是能力，不是任务 → 折叠，展开后才有搜索/勾选/应用；
4. 上传是低频、批次性动作 → 折叠在最底部（或跳"管理素材库"页）。

## 四、引用清单的字段设计（这是核心）

每条引用 = **引用点（Citation Point）**，字段：

| 字段 | 示例 | 用途 |
|---|---|---|
| `section` | 项目政策依据梳理 | 分组 |
| `paragraph` | 第 3 段 | 定位到正文 |
| `quote` | 正文里那句（截断 40 字） | 让用户认出"就是这句" |
| `source_kind` | 招标文件 / 公开来源 / 我方材料 | 图标与筛选 |
| `source_label` | 招标文件（第 12 页）/ 发改委 2026-10-10 | 【来源：】文本 |
| `excerpt` | 素材原文片段 | [看原文] |
| `state` | 已引用 / 未标来源 / 已失效（素材被删）| 核对状态 |

**汇总行（一定要有）**：
```
本章引用 8 处 · 来源 4 个（招标文件 1 / 公开来源 2 / 我方材料 1）· 未标来源 2 处
```
这一个数字比"素材库 531 段"有用得多。

**动作**
- [看原文]：展开素材片段（来自哪个文件第几页 / 哪个 URL）
- [定位]：切到正文并选中该句（复用现有定位）
- [换来源]：从素材库选另一条替换该引用（替换【来源：】并记录）
- 未标来源：[系统补来源]（已有 enrich/search）/ [手动添加]

## 五、写之前的"推荐"（次要但有用）

当某节还没有任何引用时，给**最多 3 条**推荐（按节标题/要点匹配已确认素材）：

```
现状差距分析  本节还没有引用
  推荐：· [招标文件 p18] 「…需在验收阶段提供测评报告…」  [应用]
        · [公开来源 工信部 2026] 「…行业数据…」        [应用]
```

规则：**每节最多 3 条、只显示 1 行标题**，避免又变成"库列表"。

## 六、素材库页（低优先级，但仍保留）

折叠展开后：

```
素材库
[搜索已确认素材…]                       [上传素材] [管理 ›]
类型：全部 / 招标文件 / 公开来源 / 我方材料
☐ 文件 · 技术招标文件.pdf  第 0 页  「总则…」
☐ 公开来源 · 发改委 2026-10-10       「回顾过去40年…」
                          [应用到本章]
```

- 上传、解析、确认（M1/M2 已有）都收进「管理 ›」或上传抽屉
- 主视图不再常驻这些

---

## 七、与其它模块的边界（避免重复）

| 内容 | 归属 |
|---|---|
| 招标硬性要求上传的材料 | **编写页签**（待办区）提示 + 「素材」顶部一行「1 份材料待上传 [上传]」 |
| 本章引用清单 | **素材页签**主视图 |
| 引用是否成立（来源可追溯）| 交付检查（内部校验）+ 素材页签的"未标来源"提示 |
| 素材上传/解析/确认 | 素材页签的「管理 ›」（折叠） |

---

## 八、实现要点（改造清单）

| # | 改造 | 依赖 |
|---|---|---|
| 1 | 新增 `GET /api/blocks/{id}/citations`：从正文解析【来源：X】+ 绑定关系，返回引用点列表（含节/段落/原句/来源/状态）| 现有 bound + 正文正则 |
| 2 | 前端素材页签重排：引用清单（主）→ 待确认一行 → 素材库折叠 | 现有接口 |
| 3 | 引用点动作：看原文 / 定位 / 换来源 / 补来源 | 复用定位与 enrich |
| 4 | 推荐（每节 ≤3 条）| 现有素材库 + 关键词匹配 |
| 5 | 上传/管理收进折叠抽屉 | 现有上传接口 |

**M3 建议就做这 5 条**，做完这个模块的"重点"（本章引用了什么 + 来源）就成立了。

---

## 九、验收

1. 打开任一已写章节，素材页签默认显示「本章引用 N 处 · 来源 M 个 · 未标来源 K 处」
2. 每个引用点能：看原文（第 X 页/URL）、定位到正文该句、换来源
3. 未标来源的句子有 [系统补来源]
4. 素材库与上传**默认折叠**，展开后功能与现在一致
5. 没有引用也没有推荐的章节：只显示一行「本章还没有引用素材」+ 上传入口（折叠）
