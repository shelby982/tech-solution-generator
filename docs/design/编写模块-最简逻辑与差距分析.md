# 编写模块的最简逻辑：计划 → 按计划写到可交付 → 只列"人才能补的" → 靠提示词优化

> 用户原话（本次要求）：
> 1. **写完的内容必须是可交付的**，而不是给一堆需要确认的东西；需要我补的列到「待办」；正文里不能空着一堆东西等我补。
> 2. **后续优化**：基于已写完的内容，针对某模块重新给提示词去修改即可。
> 3. 生成内容、**图片、表格**都按这个逻辑处理。
>
> 本文是对照这套逻辑做的差距分析（当前实现 vs 目标），以及要改什么。

---

## 一、目标形态（一句话）

**计划是唯一入口，写出来的东西就是可交的；系统能做的全做掉，只把"只有人能给的东西"留在待办；不满意就针对该模块重新给提示词重写。**

```
① 给出编写计划（一次看清：写什么、按什么要求写）
        ↓
② 按计划写（正文 + 图 + 表 一次到位，直接落正文）
        ↓
③ 待办 = 只有你能给的东西（材料 / 口径 / 授权）
        ↓
④ 不满意 → 对该模块重新给提示词 → 重写这一块
```

**不该出现的东西**（当前产品里有，需要拆掉）：
- 「保留 / 撤销这版」这类**写完再让人确认**的中间态
- 「现在去查 / 现在生成 / 系统重写 / 系统补齐」这类**要用户点了系统才做**的按钮
- 正文里的占位（`[[FIGURE:…]]`、`【待补充】`、空的图表位置）
- 写完后的"交付门 / 就绪度 / 一堆检查项"作为**用户可操作**的东西

## 二、逐条对照：当前实现的问题

### 2.1 「写完必须是可交付版本」

| 当前行为 | 问题 | 应该怎样 |
|---|---|---|
| 系统补写/重写后弹确认条「保留 / 撤销这版」 | 违反"不要给我一堆需要确认的东西" | **直接落库**；不满意用「重新给提示词重写」覆盖 |
| 「生成表格 / 生成图示 [现在生成]」→ 生成后要你确认再插入 | 中间态 | 生成即**直接插入正文对应位置**，图表编号与引用句一并补好 |
| 图表生成失败 → 正文留下 `[[FIGURE:x]]` 占位 | 正文有空位 | 失败时**不写占位**：该处改为完整文字表述（"如下图所示"→"具体指标以招标文件要求为准"），图表项进待办（可选）或直接放弃该图表 |
| 引擎里 `merge_charts` 的 `chart_missing` 只是发事件 | 用户会看到"占位未闭环" | 同上：生成阶段就消除，不留给用户 |
| 正文净化（占位符/内部术语）已自动执行 ✅ | 已是目标形态 | 保持，并扩展到**图表占位** |

### 2.2 「系统能做的不要留给用户点」

| 当前待办里 | 问题 | 应该怎样 |
|---|---|---|
| 补 11 条依据原文 [现在去查] | 系统该在**生成时**就去查 | 生成阶段自动检索；查不到的**不写具体条款**（写成概括表述），不生成待办 |
| 补 3 处引用来源 [现在去查] | 同上 | 同上 |
| 补目标节的量化指标 [系统重写] | 需要用户点 | 首次生成时按契约就产出指标；事后发现缺失 → **自动重写该节**（无人参与） |
| 改 1 处模糊表述 [系统重写] | 同上 | 同上 |
| 补引用文号与标准号 [系统补齐] | 需要用户点 | 生成落库前**自动补齐** |

**目标：待办里只允许出现两类**
1. **上传材料**（业绩/资质/内部数据/测评报告…）
2. **定口径**（同一句话的 2~3 种说法里选一种）

其余一切"系统做"的项，从待办中移除，改为生成阶段自动完成。

### 2.3 「后续优化靠提示词」

| 当前 | 问题 | 应该怎样 |
|---|---|---|
| 重写有 `openRewriteDialog`（可带提示词） | 入口在"更多"，不够显眼；没有"针对模块整体重新给提示词" | 明确一个入口：**「重新编写本模块…」**（可填提示词：风格/篇幅/重点/必须包含…）|
| 图表只能一个个改 | 图/表也应有"按提示词重做" | 「重做这张图/表…」带提示词 |

### 2.4 图、表按同一逻辑

| 环节 | 目标行为 |
|---|---|
| 生成 | 写正文时同时产出图/表，**直接插入该节**，并补"如表 X-1 所示"的引用句 |
| 编号 | 自动编号（表 1-1、图 1-1），表题在图/表上方 |
| 失败 | 不留占位：降级为完整文字；该节仍可交付 |
| 优化 | 「重做这张表/图…」+ 提示词，直接替换 |

## 三、产品改造清单（按优先级）

### P0：把"中间态"全部消掉（这是这次的核心）

| # | 改动 | 涉及 |
|---|---|---|
| 1 | 系统补写/重写/补齐**不再弹确认条**，直接落库；撤销入口统一收到「更多 → 版本历史」 | 前端 `showProposalBar` 移除调用 |
| 2 | 「生成表格 / 生成图示」直接插入正文（含编号与引用句），不再"生成后确认" | 前端 `runTaskQuickFix`、插入逻辑 |
| 3 | 图表生成失败**不写占位**：该处降级为完整文字；`merge_charts` 的 missing 项自动处理掉 | 后端 `chapter_sse.merge_charts`、`body_align` |
| 4 | 生成阶段自动补齐：引用文号/标准号（已实现，改为自动调用） | 后端生成流水线 |
| 5 | 生成阶段按契约直接产出：目标带指标、现状带来源、难点带措施（提示词已加，验证效果） | 后端 prompt |

### P1：待办收敛到两类

| # | 改动 |
|---|---|
| 6 | 待办只保留 `upload_material` 与 `choose`（定口径）；其余"系统项"不再出现在待办 |
| 7 | 「补依据/补引用来源」在生成时执行；查不到 → 正文写概括表述（不留占位、不进待办） |
| 8 | 待办卡片增加"为什么需要你"的一句话（材料用途/口径影响哪些章节） |

### P2：优化入口显性化

| # | 改动 |
|---|---|
| 9 | 章头加「重新编写本模块…」：可选范围（整章/某节/某图表）+ 提示词 + 强度（保守/正常/大改） |
| 10 | 「重做这张图/表…」带提示词，直接替换 |
| 11 | 版本历史里能看出"哪次是提示词重写"（便于回退到某一版） |

### P3：把"检查"变成隐形

| # | 改动 |
|---|---|
| 12 | 交付门/就绪度不再作为用户操作项；作为**导出时的内部校验**，正常情况应为 0 |
| 13 | 导出时若真有阻塞（极少），只提示一次"还有 N 项需要你补"，不阻止"带风险导出" |

## 四、改造后的用户体验（端到端）

```
1. 打开章节 → 看计划（写什么、什么要求）
2. 点「按计划编写」
   → 正文一段段长出来（4 个头像显示谁在做）
   → 图/表直接在对应位置出现，带编号与引用句
   → 文号/标准号自动补齐
   → 结束后：整章是**可交付版本**
3. 待办里只剩：
   · 上传 1 份业绩材料（附：用于"业绩"小节的举证）
   · 定 1 处口径（原句 + 3 种说法，点一个）
4. 不满意某节 → 「重新编写本模块…」→ 填提示词 → 只重写这一块
```

## 五、一个需要你确认的取舍

**"写完直接落库、不确认" 的风险**：模型偶尔改坏原文。
当前用"确认条"来兜。取消后建议用**两条兜底**：

1. **自动写 revision**（已有）→ 「更多 → 版本历史」可一键回退到上一版
2. 若某次重写导致**字数骤降 >40% 或引用丢失**，则不覆盖，改为"建议稿"并在状态条提示一次（仅这种情况）

这样可以做到"默认不打扰，出问题才提示"。
