## 二、设计稿：一个主线 + 三层信息

**主线 = 待办清单**（编写人员最重要的问题：我现在该做什么）
**明细 = 交付物**（要看"哪一项、多少字、必答什么"时展开）
**参考 = 标准 + 写法**（低频，折叠）

```
┌───────────────────────────────────────────────────────────────┐
│  本章编写计划                                          ×      │
├───────────────────────────────────────────────────────────────┤
│  项目背景现状目标                                   [叶子章]    │
│  计划 12 页 · 3000 字 ｜ 已写 5634 字 ⓘ ｜ 待办 3 项           │
│                                              [去补 3 项]      │
├───────────────────────────────────────────────────────────────┤
│  ① 待办 3 项（按优先级）                                      │
│                                                               │
│   1 ▸ 补 1 份「我方材料（数据/案例/业绩）」        [去找素材]   │
│   2 ▸ 政策/标准/数据处补【来源】标注              [去补来源]   │
│   3 ▸ 字数超计划 88%（5634 / 3000 字）             [去精简]    │
│                                                               │
├───────────────────────────────────────────────────────────────┤
│  ② 交付物 5 项 ｜ 3 项不足 · 2 项未写                  [改要求] │
│                                                               │
│   ▾ [文字] 写清楚「背景」            833 字 · 已写 231 · 不足  │
│       必答：项目由来与建设动因 / 政策依据（引用文件与要求）     │
│       [定位到正文]                                             │
│   ▸ [文字] 写清楚「现状」            833 字 · 已写 268 · 不足  │
│   ▸ [文字] 写清楚「目标」            833 字 · 已写 308 · 不足  │
│   ▸ [表格] 政策依据映射表            300 字 · 未写             │
│   ▸ [图示] 趋势或现状对比图          200 字 · 未写             │
│                                                               │
├───────────────────────────────────────────────────────────────┤
│  ③ 依据与标准（评分点 1 · 条款 3 · 失分点 4）            ▸     │
│  ④ 写法要点（结构 / 段落 / 落点）                        ▸     │
├───────────────────────────────────────────────────────────────┤
│                                  [AI 编制本章]   [关闭]        │
└───────────────────────────────────────────────────────────────┘
```

## 三、信息架构决策（需要你确认的 7 条）

### 决策 1｜主线换成「待办清单」
- **为什么**：编写人员打开弹窗时的问题不是"这章有几项交付物"，而是"我现在该干什么"。
- **怎么做**：待办 = 素材缺口 + 自检未过项（最多 5 条，按"卡住生成 > 质量 > 格式"排序），每条一句行动 + 一个按钮。
- **替代方案**（若你更想以交付物为主线）：把"还缺什么"折叠成一行「3 项待补 ▸」，默认只看交付物。

### 决策 2｜交付物从"全展开"改成"一条主项展开、其余一行"
- **为什么**：5 项全展开占 60% 屏高，"必答点"被淹没。
- **怎么做**：默认展开**第一项未达标**的交付物（用户下一步就要改它），其余折叠为一行（类型 · 标题 · 数字 · 状态）。
- **收益**：屏高从 5 行×2 行说明降到 1 项展开 + 4 行摘要。

### 决策 3｜状态只出现一次
- 顶部汇总写「待办 3 项」（唯一汇总）
- 交付物行只在末尾放一个状态词（不足/未写/达标），描述里不再重复
- 交付物块的块头只写「5 项 ｜ 3 不足 · 2 未写」，不再写"待补 5"

### 决策 4｜口径说明移到 ⓘ
- 「已写 5634 字」后面加 ⓘ，hover/点击显示："按小节标题能对应到交付物的是 807 字，逐项'已写'为估算值"
- 正文不再出现两行免责声明

### 决策 5｜动作收敛为"1 主 + N 行内"
| 动作 | 位置 | 频率 |
|---|---|---|
| 去补 N 项 / 去写总述 / 看子节进度 | 顶部主按钮 | 高频（下一步） |
| 去找素材 / 去补来源 / 去精简 | 每条待办行内 | 中频 |
| 改要求 | 交付物块头 | 低频 |
| 看写作规范 | ④ 折叠区内 | 低频 |
| 关闭/AI 编制本章 | 底部 | 低频 |

### 决策 6｜折叠有明确暗示
- 折叠块统一用 `▸ 标题 … 摘要` + hover 背景色；展开后变 `▾`
- 摘要行必须有一个具体数字（如"评分点 1 · 条款 3 · 失分点 4"），让用户不展开也能判断要不要看

### 决策 7｜两栏只在宽屏启用
- ≥ 720px：左侧 交付物（60%）+ 右侧 待办（40%）并排，减少滚动
- 窄屏：单列，待办在上
- ⚠️ 这条是可选优化，若你觉得"一条竖线读下来"更顺，就保持单列

## 四、父章 / 目录节点 两种变体

### 父章（自己有正文 + 有子节，只写总述）

```
项目背景现状目标[父章]  总述 384/400 字 · 子节 7 个（84 页 · 已写 61 页）
① 待办 1 项
   1 ▸ 总述已达标，检查是否覆盖 3 个结论（可看写法要点）
② 子节统筹 7 节（进度条 + 已写页数，整行可点）
③ 依据与标准 ▸      ④ 写法 ▸
```

### 目录节点（自己无正文，下辖子节）

```
项目管理方案及质量管理方案[目录节点]  下辖 5 节 · 计划 100 页 · 已写 0 页
① 子节统筹 5 节（进度条 + 状态）
（无待办、无交付物、无字数分配）
```

## 五、字段归属（信息架构落到数据上）

| 界面区块 | 数据来源 | 现状 |
|---|---|---|
| 顶部汇总 | plan.pages / word_plan.total / word_plan.written / 待办数 | ✅ 已有 |
| 待办清单 | materials 未齐 + self_check 未过 + deliverables 未写/不足 | 🟡 需在后端统一成 `todo[]`（含优先级 + 动作类型） |
| 交付物明细 | deliverables（含 written_detected / status / target_words） | ✅ 已有 |
| 必答点 | key_points_by_deliverable | ✅ 已有（需按项对应得更准） |
| 依据与标准 | basis.points / grade_band / clauses / guidance.pitfalls | ✅ 已有 |
| 写法要点 | guidance.skeleton / notes | ✅ 已有 |
| 子节统筹 | children[] | ✅ 已有 |

**只需后端补一个**：`todo[]`（统一待办，带优先级 priority 与动作 action），前端不再自己拼。
