# 编写计划 × 素材：从"两套东西"到"计划内嵌素材"（PM 分析 + 方案）

> 用户问题：制定编写计划时，应该先知道"有哪些素材可以用在哪一节"，再据此生成；
> 现在素材与计划是脱离的 —— 这个缺乏关联的状态有问题。

---

## 一、现状：素材与计划在什么时候才相遇？

```
评分点/条款 ──▶ 编写计划（节 / 要点 / 交付物 / 写法）      ← 完全由需求侧推导，不看素材
                                    │
                                    ▼
                            按计划编写（逐节生成）
                                    │
素材库（出处→片段→勾选→素材）────────┘ 只在"应用到本章"时挂上
                                    │
                                    ▼
                        写完才在素材页签看到"推荐素材"
```

**问题清单（都是同一个病根：关联建立得太晚）**

| # | 现象 | 后果 |
|---|---|---|
| 1 | 计划只看需求，不看素材 | 计划写下"业绩举证""现状数据"，但库里可能一条都没有 |
| 2 | 素材"应用到本章"是章节级 | 无法体现"这条素材是给第 2 节用的"，生成时全章灌入，相关度差 |
| 3 | 推荐出现在**写完之后**（素材页签）| 用户先写完、再发现"这节该用素材但没用" → 返工 |
| 4 | 素材缺口只反映"招标硬性材料" | 计划需要的普通素材（数据/案例）缺失没有任何提示，正文只能写空话 |
| 5 | 计划面板看不到素材情况 | 用户无法判断"这一章能不能写、写成什么样" |

**本质**：现在是一条"需求 → 内容"的单向链，**素材是挂在链条末端的外挂**；
正确做法是把素材作为**计划的一等输入**，在计划阶段就完成"哪节用哪些素材"的绑定。

---

## 二、目标逻辑：素材先行、计划落地、生成按节取用

```
① 需求侧：评分点 / 条款 / 交付物          （已有）
② 素材侧：可用素材盘点（按章节意图匹配）    （新增，在计划阶段）
③ 计划：每节 = 要点 + 交付物 + 写法 + **可用素材 + 素材缺口**
④ 确认计划 → 按节生成（生成时只注入该节素材）
⑤ 生成后回填：实际引用了哪些素材（可追溯）；缺口 → 计划/待办
```

### 关键原则

1. **计划是素材的"用武之地"**：素材不是"库里有什么"，而是"这一节要用什么"。
2. **关联粒度 = 节**（不是章）：一节 ↔ 若干素材（cite / data / context）。
3. **缺口要显性，但不一定进待办**：计划里标"缺"，正文仍按"概括表述"写完整；
   只有**招标硬性要求**的材料才进待办（与已定规则一致）。
4. **推荐前移**：素材推荐从"写完后的素材页签"前移到"计划阶段（每节画像）"。
5. **生成时按节取用**：避免全章素材互相串味。

---

## 三、方案设计

### 3.1 计划面板：每节增加「素材」一栏

```
▸ 1 项目政策依据梳理            1000 字
    写法：先陈述政策回应逻辑，再以表格逐项陈列 …
    交付物：文字 1000 字 · 表格「政策依据映射表」
    素材：可用 6 条（招标文件 5 · 联网 1）   [挑选/调整]     ← 新增
    缺口：无

▸ 4 项目现状描述               900 字
    …
    素材：可用 2 条（招标文件 2）
    缺口：现状数据（库里 0 条）→ [上传] / [不补，写概括表述]   ← 新增
```

**素材行的数据从哪来**：用 R1 的章节画像（节标题+要点+交付物）对候选池打分，
返回：可用素材 top N + **按类型的缺口判断**（data/qualification/table/image）。

### 3.2 计划阶段就能挑素材

点「挑选/调整」→ 打开挑选器（按本节画像预筛，只显示相关片段）：
- 勾选 → 立即写入"本节素材"（`chapter_material_chunks` 已有 `section` 字段，直接复用）
- 可设置用法（引用出处 / 数据依据 / 仅上下文）

### 3.3 「按写法批量编写」前：素材体检

```
开始编写整章？
  本章 8 节：5 节已有素材（共 14 条），3 节无素材
  · 第 4 节 项目现状描述：缺口「现状数据」→ 将写成概括表述
  · 第 7 节 现状与目标对比图：缺「图示数据」→ 将生成图示（无数据则降级为文字）
  [先补素材] [直接开始]
```

### 3.4 生成时按节注入

```
第 N 节提示词 =
  本节写法（practice）
  + 小节契约
  + **本节素材**（cite → 来源标签；data → ≤300 字；context → ≤500 字）
  + （若该节无素材）"本节缺素材，请用概括但完整的表述，不编造具体数字"
```

> 现在实现的是"整章素材"注入 → 改为"本节素材优先，整章素材兜底"。

### 3.5 生成后回填

- 正文里的【来源：X】与"本节素材"比对 → 计划面板显示"本节实际引用 3 条 / 未用 2 条"
- 未用的素材：标注"未使用"（用户可移除或下次重写时用）
- 计划缺口若仍缺 → 保持"缺口"状态，不阻断交付

## 四、数据模型（改动很小）

| 用途 | 现在 | 改动 |
|---|---|---|
| 节 ↔ 素材 | `chapter_material_chunks(block_id, chunk_id, section, mode)` | **已有** ✓ 直接复用：计划阶段写入 = 生成阶段读取 |
| 缺口 | 无（只有 material_gaps 硬性材料）| 新增计算：`section_material_gaps`（节画像需要的类型 vs 库里可用）**不落库**，实时算 |
| 推荐 | 章级推荐接口 | 已有 `recommend?section=` ✓ 复用到计划面板 |

**结论：不需要新表**，只要把"应用素材"的时机从"写完之后"前移到"计划阶段"，并让生成按 `section` 过滤。

## 六、分期

| 期 | 内容 | 验收 |
|---|---|---|
| **P1** | 计划面板每节显示「可用素材 N / 缺口」+ 生成按节注入 | 计划里能看到每节素材情况；生成第 4 节只带第 4 节素材 |
| **P2** | 「挑选/调整」按节预筛 + 勾选即绑定 | 在计划面板 30 秒内给某节挑 3 条素材 |
| **P3** | 批量编写前的素材体检弹窗 | 开始前明确提示"3 节无素材，将写概括表述" |
| **P4** | 生成后回填"实际引用/未使用" | 计划面板可核对素材是否真被用到 |

## 七、与已定规则的一致性检查

| 已定规则 | 本方案是否冲突 |
|---|---|
| 待办只留招标硬性材料 | ✅ 不冲突：普通缺口只在计划里标，正文写概括表述 |
| 正文不留"待补充" | ✅ 不冲突：无素材 → 写概括但完整的表述 |
| 素材=片段，勾选才成为素材 | ✅ 复用：计划阶段勾选 = 选中片段 |
| 三种用法 cite/data/context | ✅ 复用：计划的"素材行"可设用法 |
| 一个概念一个位置 | ✅ 计划负责"用在哪"；素材页签负责"有什么" |

## 八、需要你拍板

1. **缺口是否要在计划面板显性提示**？（我建议：显性，但不进待办）
2. **无素材的节**：默认写概括表述（推荐），还是生成前必须用户二选一"补素材 / 写概括"？
3. **计划阶段挑素材**是否需要"按节预筛"（本节画像匹配 Top-N），还是直接开全库挑？

# 修正版（v4）：只有两个时机 —— 计划确认 / 重写确认

> 用户修正：「已有初稿后调整素材」必须**和重写结合**——单独调整素材对生成没有意义。
> 因为生成只发生在两个时刻：首次按计划编写、以及之后重写某一节。

## 最终模型

```
素材库（上传/搜索 → 挑片段 = 素材）
        │
        ├─ 时机①【计划阶段】为每节匹配建议素材 → 用户确认 → 计划锁定"哪节用什么素材"
        │                 ↓
        │        按计划生成（严格按确认结果注入）
        │
        └─ 时机②【重写阶段】重写某节前：先确认/调整该节素材 → 再重写
                          （调整只在这里发生，因为它唯一能影响生成）
```

## 关键约束

| 约束 | 说明 |
|---|---|
| 计划里的素材行 | 首次生成前可编辑（确认/换/取消）；生成之后**只读展示** |
| 有初稿后想换素材 | 只能走「重写该节（含调整素材）」，不提供独立"改素材"入口 |
| 生成只读"已确认"绑定 | 不做生成时的自动模糊匹配（匹配只用于给建议） |
| 素材来源 | 项目素材库里 `selected` 的片段（用户已勾选过的） |

## 两个入口

1. **计划面板**（首次）：每节「建议素材（预勾选）」+ [全部采用] [只采用勾选] [换一条]
2. **重写入口**（之后）：`重写「本节」→ 本节素材 3 条 [调整素材…] → 开始重写`

## 待拍板（默认值）

1. 建议素材**默认预勾选**（最少操作）
2. 匹配不到的节 → 默认写"概括但完整的表述"
3. 支持「全项目一键生成建议 → 全部采用」（纯本地计算，很快）
