# 素材匹配方案：如何从「上传的文件 / 联网搜索」里找到"符合当前章节"的内容

> 需求：给定当前章节（小节/要点/交付物），从素材库里找出**相关的文字、表格、图片**，
> 并说明"为什么相关"，让用户能一键采用。
> 本文只出方案。

---

## 一、先把"要匹配什么"说清楚

### 1.1 查询侧：当前章节的"需求画像"（Query Profile）

从**编写计划**自动生成，不需要用户填：

| 字段 | 来源 | 例（节：项目现状描述）|
|---|---|---|
| `section_title` | 计划 | 项目现状描述 |
| `points` | 计划（节要点） | 现状、业务量、系统情况、数据管理 |
| `deliverables` | 计划（交付物）| 文字 900 字 · 表格「现状对比表」 |
| `basis` | 计划（依据/评分点）| 对项目的理解正确深入；工作项2 |
| `keywords` | 由上三者抽取 | 现状、业务、系统、数据、规模、用户数 |
| `types_wanted` | **由交付物决定** | 要表格 → `table`；要图示 → `figure/image`；要数据 → `data` |

### 1.2 素材侧：可被匹配的四种对象

| 类型 | 存储 | 匹配用什么 |
|---|---|---|
| **文字片段** | `material_chunks` / `citation_chunks` | 关键词、要点短语、类型标签 |
| **表格** | 新增 `material_tables`（表头+行+页码+表名）| 表名/列名/内容 + 类型 `table` |
| **图片** | 新增 `material_images`（页码+OCR 文本+图注+图型）| 图注/OCR/图型（截图·照片·流程图·图表）|
| **网页来源** | `citations` + 上述三类 | 同上（去掉页码，带 URL）|

## 二、匹配怎么做：四步流水线（可解释、可无模型跑）

```
① 硬过滤（先把不可能的要淘汰）
② 多路检索（关键词 / 结构化 / 语义）
③ 融合打分（可解释的加权）
④ 呈现（分组 + 为什么推荐 + 一键采用）
```

### ① 硬过滤

- 丢弃 `noise`（目录/页眉脚/页码）
- 丢弃 `rejected`（失效）
- 丢弃已被本章用过的（避免重复推荐）
- 跨来源去重（内容指纹相同只留一份）

### ② 多路检索（三路并行，取并集）

| 路 | 方法 | 作用 |
|---|---|---|
| **关键词路** | 章节 keywords 与片段做 BM25 / 子串命中 | 找"字面上对得上"的段（业绩、资质、现状…）|
| **结构化路** | 按 `types_wanted` 与片段 `tags` 匹配 | 章要表格 → 表格素材优先；要数据 → `data` 标签 |
| **语义路（可选）** | 向量相似度（章节要点 vs 片段）| 找"意思相近但用词不同"的段（"投标人资格"≈"资质要求"）|

> **两档实现**：
> - **无模型版**（第一期就能用）：关键词 + 结构化 + 同义词表 + 章节要点拆词
> - **有模型版**（二期）：embedding 向量检索（可本地模型 or 云端）

### ③ 融合打分（0~1，可解释）

```
score = 0.35 × 关键词匹配度（命中章节关键词的比例）
      + 0.20 × 类型匹配（片段 tags ∩ types_wanted）
      + 0.20 × 语义相似度（无模型版置 0，权重挪给关键词）
      + 0.15 × 要点覆盖率（章节 points 命中几条）
      + 0.10 × 来源可信度（招标文件/官方来源 > 新闻 > 未知站点）
```

**"为什么推荐"直接由分项得出**，例如：

```
推荐：招标文件 · 第 12 页「3.2 投标人资格要求：近三年业绩…」
理由：命中「业绩」「资格」· 类型：条款 · 覆盖要点 1/4 · 来源：招标文件
```

### ④ 呈现

素材页签新增（引用清单上方）：

```
本章推荐素材（12 条）                          [只看推荐] [全部素材]
  文字（6）
  · 招标文件 p12「3.2 投标人资格要求：近三年…」  命中「业绩·资格」   [采用]
  表格（3）
  · 招标文件 p18「评分标准表」4 列 12 行          类型匹配：本章要表格  [采用]
  图片（3）
  · 我方材料「现状架构截图」p3 · 截图            类型匹配：本章要图示  [采用]
```

交互：
- **[采用]** → 直接进「本章素材」（用法默认 cite；表格/图片则插入正文对应位置）
- 点条目 → **看原文/原图**（页码或 URL）
- 可切到「全部素材」自己找

## 三、图片与表格怎么提取（多模态）

### 3.1 图片素材

```
解析时抽取 → material_images(id, material_id, page, bbox, file_path,
                              ocr_text, caption, kind)
kind: screenshot 截图 / photo 照片 / flow 流程图 / chart 图表 / product 产品图
caption：图片上下 1~2 行文字（通常是图题）
ocr_text：图内文字（便于"图里有'等级保护'就命中"）
```

**匹配**：章节要"图示/架构图" → 优先 `kind ∈ (flow, chart, screenshot)` 且图注/OCR 命中章节关键词。

**用途**：
- 作为 `:::figure` 素材插入正文（走已有素材图块能力）
- 或作为附录/证明图片（如资质扫描件）

### 3.2 表格素材

```
解析时识别表格 → material_tables(id, material_id, page, caption,
                                 markdown, cols, rows)
匹配：表名/列名/内容 + 类型 table
用途：可直接插入正文（表题+表格），或作为"数据来源"引用
```

### 3.3 抽取质量要求

| 对象 | 要求 |
|---|---|
| 图片 | 清晰度 ≥ 原图 60%；带页码；图注抽出来；OCR 中英文都支持 |
| 表格 | 表头能识别；合并单元格尽量还原；列数一致；超宽表按行组切并复制表头 |

## 四、章节侧和素材侧的"绑定"关系（避免推了用不上）

```
搜索到相关素材 → [采用] → 建立 chapter_material_chunks（mode: cite/data/context）
                 ↓
生成时：只注入被采用的素材（cite 只给来源标签；data/context 给内容）
```

**不做"自动插入正文"**：推荐只是候选，采用后由用户在生成/编写时使用（避免污染正文）。

## 五、性能与缓存

| 项 | 做法 |
|---|---|
| 索引 | 片段入库时预先算好 `tags`、`keywords`（去停用词）、指纹 |
| 章节画像 | plan 变更时才算（缓存 `hash(plan_section)` → profile）|
| 推荐结果 | 按 `hash(profile + 素材版本)` 缓存，素材新增/失效时失效 |
| 规模 | 1634 段 × 章 8 节：关键词检索毫秒级；向量检索需要预建索引 |

## 六、评价与验收

| 指标 | 定义 | 目标 |
|---|---|---|
| **Top10 命中率** | 人工判断前 10 条里"确实可引用"的比例 | ≥ 70% |
| **要点覆盖率** | 章节 4 个要点里被推荐素材覆盖的个数 | ≥ 2.5/4 |
| **误报率** | 明显不相关（跑题）的比例 | ≤ 20% |
| **多样性** | 推荐里包含 文字/表格/图片 三类（当章节需要时）| 需要时必有 |
| 性能 | 打开章节到推荐出现 | < 1.5s（关键词版）|

评测方法：挑 5 个真实章节（背景/现状/目标/方案/实施各 1），人工标注相关性。

## 七、分期

| 期 | 内容 | 依赖 |
|---|---|---|
| **R1** | 章节画像 + 关键词/类型两路检索 + 融合打分 + 「本章推荐」列表（含"为什么推荐"）| 片段 tags（C2）|
| **R2** | 表格素材提取与匹配（`material_tables`）| 表格识别 |
| **R3** | 图片素材提取与匹配（`material_images` + OCR + 图注）| 图片抽取/OCR |
| **R4** | 语义检索（embedding）作为第三路，提升"换词命中" | 向量库/模型 |
| **R5** | 推荐缓存 + 质量评测面板（Top10 命中率可观测）| — |

---

## 八、需要你确认

1. **第一期是否先做"无模型版"**（关键词+类型，不用 embedding）？
   → 我建议先做，命中率靠"同义词表 + 类型匹配"能到 60~70%
2. **图片/表格是否要和文字同级**都进"本章推荐"？（我建议同级，但分三段展示）
3. **推荐数量**默认给多少？（我建议文字 ≤6、表格 ≤3、图片 ≤3）
