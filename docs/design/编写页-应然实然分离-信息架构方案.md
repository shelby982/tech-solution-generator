# 编写页信息架构梳理：计划说"怎么写"，三栏说"差在哪"

> 依据本轮产品意见整理，作为下一步改造的方案稿。
> 结论先行：**把"应然"和"实然"彻底分开** ——
> 计划面板回答「这一章要写成什么样」，右侧三栏回答「现在差在哪、差多少、怎么补」。

---

## 一、现在的割裂在哪

| 现象 | 问题本质 |
|---|---|
| 计划面板里有"① 待办 5 项" | 计划是**说明书**（应然），却塞了**差异清单**（实然）→ 打开计划先看到"我欠了 5 件事"，看不到"这章该怎么写" |
| 右侧三栏是「依据 / 素材池 / 进度」 | 三栏是**差异监控**的位置，却装了两个"资料库"（依据、素材池）→ 用户想知道"还差什么"得自己比对 |
| 计划里的待办与素材池里的"未引用来源"各说各话 | 同一类缺口散落在两处，口径不一致 |
| 素材池只列"已关联的外部依据" | 只说了"有什么"，没说"**缺什么、缺的能不能补、怎么补**" |
| 更多菜单里有「质检清单」 | 质检是**评审**职责，混在编写工具条里，削弱了"评审"这一步的存在感 |

**一句话**：计划面板和右栏都在做"混装"，所以两边都不清晰。

---

## 二、核心原则：应然 / 实然 分离

```
┌─────────────────────────────┬──────────────────────────────┐
│  计划面板（应然）            │  右侧三栏（实然）             │
│  「这一章要写成什么样」       │  「现在差在哪、怎么补」        │
├─────────────────────────────┼──────────────────────────────┤
│ · 有哪些要求（评分点/条款）   │ · 待办：差什么、哪个模块、怎么做 │
│ · 依据是什么（原文/出处）     │ · 素材：缺什么素材 / 哪来的      │
│ · 篇幅多少（页数/字数/图表）  │ · 进度：写了多少（篇幅/完成度）  │
│ · 怎么写（结构/段落/落点）    │                              │
│ · 本章类型（影响生成）        │                              │
└─────────────────────────────┴──────────────────────────────┘
        只读说明书 + 少量可编辑            只读差异 + 每条带一个动作
```

**判断标准（以后所有内容往哪放，按这三问）**
1. 这条信息是"目标"还是"现状差"？目标 → 计划；现状差 → 三栏。
2. 它需要用户**做一件事**吗？需要 → 三栏的待办（带动作）；不需要 → 计划（只读）。
3. 它是**交付前**才关心吗？是 → 评审（如质检）。

## 四、① 编写计划面板（改造）

**目标**：打开就能读懂"这一章要写成什么样"，不再被"待办"打断。

| 区块 | 内容 | 变化 |
|---|---|---|
| 结论条 | 章名 + 篇幅（计划页数/字数）+ 唯一主操作「AI 编制本章」 | 去掉"待办 N 项"和"去补 N 项"按钮 |
| ① 交付物 | 要交什么（文字/表/图 + 字数/页数），只展开第一项未达标 | 保留（这是"要求"的一部分）|
| ② 依据与标准 | 评分点（含满分档原文）/ 承接的招标条款 / 失分点 | 保留 |
| ③ 写法要点 | 结构 / 段落 / 落点 + **本章类型** | 保留（章节类型已移入）|
| ~~待办~~ | — | **整块搬走** → 右栏「待办」页签 |

> 计划面板从此**没有"去做事"的按钮**（除了主操作"AI 编制本章"），
> 只有"改要求/改类型"这类**调整说明书**的动作。

## 五、② 待办页签（新增，承接原计划里的待办）

**目标**：一句话说清"差什么、属于哪个模块、该怎么处理"，每条都能直接点走。

### 5.1 结构：按"处理模块"分组

```
待办  5 项 · 按优先级

▓ 内容模块 2
  1  写清楚「背景」：不足（231 / 833 字）        [去补写]
  2  写清楚「现状」：不足（268 / 833 字）        [去补写]

▓ 素材模块 1
  3  缺 1 份「我方业绩材料」（评分点要举证）      [去补素材]

▓ 来源模块 1
  4  政策/标准/数据处缺【来源】标注              [去补来源]

▓ 篇幅模块 1
  5  字数超计划 88%（5634 / 3000 字）           [去精简]
```

| 模块 | 判断依据 | 动作 |
|---|---|---|
| **内容** | 交付物未达标（未写 / 不足 / 超额）| 去补写（AI 重生成该段 / 定位到正文）|
| **素材** | 计划要求 × 已有材料不足 | 跳「素材」页签对应缺口 |
| **来源** | 正文有政策/标准/数据但无【来源】 | 去补来源（打开检索/素材池）|
| **篇幅** | 字数/页数偏离计划 | 去精简 / 去扩写 |
| **图表** | 计划要表/图但未产出 | 去出图（AI 生成图表片段）|

### 5.2 每条待办的信息四要素

```
[模块] 一句话问题（带数字）                  [动作]
```
- **模块**：内容 / 素材 / 来源 / 篇幅 / 图表（颜色区分）
- **问题**：必须带数字（231/833、缺 1 份、超 88%）—— 没有数字的待办会被忽略
- **动作**：一个按钮，直接跳到能解决它的地方（不弹二次选择）
- **归属**：点进正文时定位到对应小节（已实现「定位到正文」）

### 5.3 排序与上限
- 排序：**卡生成 > 内容 > 素材 > 来源 > 篇幅 > 图表**（先解决"写不出来"的）
- 每模块最多 2 条，总数 ≤ 6（避免"全是某一段不足"挤掉别的）
- 空态：`✓ 本章没有待办，可以生成/交付`

## 六、③ 素材页签（改造：从"有什么"到"缺什么"）

**目标**：不只列已有素材，而是回答三件事 —— **缺什么 / 公开的能不能补 / 哪些只能你上传**。

### 6.1 三分法

```
素材  缺 3 项

▓ 已有可用 2
  业绩证明_2024.docx        已解析 · 可引用（摘录/表格）
  国家发改委…答记者问         已引用 2 处

▓ 公开资料可补 1                       [去检索]
  「行业现状数据」
   建议来源：国家统计局 / 工信部公开报告（系统可检索）
   可用性：公开

▓ 必须你上传 2
  「近三年同类项目合同」                 [上传]
   评分点要求举证，公开渠道无此类信息
  「公司资质证书扫描件」                 [上传]
   评分为硬性材料

已关联素材与外部来源（原有列表，折叠）   ▸
```

| 分类 | 判断规则 | 动作 |
|---|---|---|
| **已有可用** | 已上传且解析成功 / 已引用 | 摘录、插入、查看片段 |
| **公开资料可补** | 缺口类型属"政策/标准/行业数据/公开报道" | 去检索（复用官方来源检索）|
| **必须你上传** | 缺口类型属"业绩/资质/合同/内部数据/客户信息" | 上传素材 |

**为什么这样分**：用户面对缺口时只想问一句"**这个我能自己弄到吗？**"。
- 能（公开）→ 给检索入口，别让他去百度
- 不能（内部）→ 直接说"需要你上传"，别让他白找

### 6.2 缺口的来源
- 计划里的 `materials`（素材计划：需要几份、什么类型）
- 交付物要求的举证材料（评分点要求"提供业绩证明"）
- 质检发现的"缺证据"项

### 6.3 保留原有能力
已关联素材 / 外部依据的**管理**（核对、移除、看片段、添加来源）收进底部折叠区，不占主视线。

## 七、④ 进度页签（保持，明确职责）

**目标**：只回答"写了多少"，不做别的。

```
进度
篇幅      计划 12 页 · 已写 25.5 页（212%）      ← 与计划对比
字数      计划 3000 字 · 已写 5634 字（188%）
完成度    交付物 3 项 · 达标 0 / 不足 3 / 未写 2
生成记录  ▸ 最近 3 次生成（时间 · 用时 · 结果）
```

- 与「待办」的分工：进度给**数字**，待办给**动作**（进度里的"超额"会同时出现在待办里，一处说数、一处说怎么办）
- 不做评分（保持"不打断写作"）

## 八、⑤ 工具条收敛

| 现在 | 改为 |
|---|---|
| 更多 ▾ → 质检清单 / 确认本章完成 / 导出本章 / 导出本组 | **更多 ▾ → 确认本章完成 / 导出本章 Word / 导出本组 Word**（3 项）|
| 质检清单在编写页 | **移到「评审与交付」（阶段④）**，作为该阶段的检查入口 |

**理由**：
- 质检是"交付前评审"的职责，放在编写页会削弱"评审"这一步；
- 编写页的质检类问题已经以**待办**形式出现（缺来源、缺素材、图表缺失），不需要再来一个总清单；
- 「更多」里只留与"本章收尾"有关的动作（确认完成 + 两种导出）。

> 注：用户原话说"只保留导出本章和导出本组两个按钮"。
> 建议额外保留「确认本章完成」——它是**状态动作**而非检查动作，且没有别的入口；
> 若你希望严格只留两个导出，我就把它也移走（可移到章头「更多」之外的状态区）。

## 十二、验收标准（自动审查规则）

1. 计划面板内**不含**待办块（`[data-cp-sec="todo"]` 不存在）
2. 右栏页签为 **待办 / 素材 / 进度** 三个，且第 1 个是「待办」
3. 待办页签每条含 **模块标签 + 数字 + 动作按钮**
4. 素材页签有三组（已有可用 / 公开资料可补 / 必须你上传），每组有动作入口
5. 更多菜单只剩 **确认本章完成 + 2 个导出**；页面内**不再出现**「质检清单」（评审页可）
6. 无控制台错误

## 十三、风险与取舍

| 风险 | 应对 |
|---|---|
| 计划面板去掉待办后，用户"打开计划看不到要做的事" | 章头角标「待办 5」+ 右栏待办页签常驻，两处都能到 |
| 「依据」页签被并入计划面板，可能被说"要多点一次" | 计划面板本来就是"依据的完整版"；右栏不再重复同一批内容（避免两处口径）|
| 素材三分法依赖"缺口类型"判断，可能误判 | 判断基于可见规则（业绩/资质/合同 → 必须上传；政策/标准/行业 → 公开），并在页面标注依据 |
| 质检移走后被遗忘 | 评审阶段做**入口强提示**（阶段④ 未跑检查时高亮）|
