# 模型分工 × 图文并行 × 章节级 SSE（方案 v3）

> 取代 `docs/design/模型分工-协同价值与UI-方案v2.md`。本版按已确认的 6 项决策重写：
> ① 扩展 SSE；② 计划定要素后图文并行；③ 4 个头像；④ 项目默认 + 章节覆盖；⑤ 审校本版不做；⑥ 图片校验改为「交付物符合 + 依据可追溯 + 图文不矛盾」。
>
> **前提修正**：图片不是正文的派生物，而是**辅助章节内容的独立材料**。v2 的「图由文生 / 节点必须在正文出现」作废。
>
> **现状基线**：`9801e22`（并行实现：3 头像 + `role/model` 第一版）。本方案在其上改造，不重做已可用的部分；基线缺陷见第一节末尾。

## 一、结论（先看这 10 条）

| # | 结论 |
|---|---|
| 1 | **唯一引擎**：章节级 SSE 作业。传输用 SSE，持久化复用 `chapter_writing_jobs`（快照、恢复、人工修改保护都已存在），前端只开一条 EventSource。 |
| 2 | **图文关系**：图/表与正文**同源于节计划**（`deliverables.elements` / `cols`）+ 依据条款 + 已核对素材；三者**并行生成**；正文只作上下文，不作图片依据；图可以包含正文未展开的要素。 |
| 3 | **大纲新增 `deliverables[].elements`**：图要表达的 2–8 个要素。旧大纲没有 elements 时按要点/依据派生，不重新生成用户已确认的大纲。 |
| 4 | **4 个头像**：主编 / 文字 / 图片 / 表格；审校角色本版不出现。 |
| 5 | **模型两层**：项目默认 + 章节覆盖；解析顺序明确、不可用可回退、每次调用记录 `used_model`。默认：主编 pro、正文 flash、精修 pro、图片 flash、表格 flash。 |
| 6 | **占位符协议**：正文在需要的位置输出 `[[FIGURE:标题]]` / `[[TABLE:标题]]`，后端用并行的图表产物替换；缺占位进待办。 |
| 7 | **校验三档**：结构/交付物硬拦；依据、数字、图文矛盾、引用软校验进 `proof`；默认不阻断导出（严格模式可选）。 |
| 8 | **失败隔离**：图/表失败不挡正文；文字某节失败保留原文；取消/断线可恢复；人工改过的正文绝不被覆盖。 |
| 9 | **留痕**：`block_revisions` + `llm_usage` 增列，能查到"哪一节、哪个角色、实际用了哪个模型、是否回退"。 |
| 10 | **清理**：`chapter-team.mjs`（无挂载）、`writeChapterApi`（死代码）、旧 job UI、前端逐节 SSE 循环全部下线，避免两套引擎并存。 |

### 现状基线（并行实现 `9801e22`，2026-10-21 17:09）

并行会话已经按 v2 落地了第一版，v3 不是从零开始：

| 已有 | 在 v3 中的处理 |
|---|---|
| 3 头像（主编 / 图片 / 表格）+ 逐节循环状态 | **扩成 4 个**（增加"文字"）；状态改由章节级 SSE 事件驱动 |

| localStorage `cs-model-choice` 按角色记忆 | 替换为项目默认 / 章节覆盖（服务端）；localStorage 只做缓存 |

| 建议式改写 / 全书待办 | 与本方案无关，保持不动 |

**已发现的缺陷（M1 前先修，否则"切模型"会假生效或报错）**：

1. `POST /studio/diagram` 的 `model` 目前是 **query 参数**（函数签名 `model: str = ''`），前端却放在 JSON body（`chapter-studio.mjs` 图调整请求）→ 图片换模型不生效。二选一并补测试。
2. `POST /studio/table` 函数体引用了**未定义的 `model`**（签名没有该参数）→ 生成表格会 `NameError`。补参数并走同一解析。
3. `/studio/section/stream` 收了 `role` 但**没有使用**；精修和正文的模型路由只靠 `model` 字符串，`role` 语义未落地。
4. `cs-model-choice` 是全局 localStorage，不区分项目/章节，"记住"会污染默认，与"项目默认 + 章节覆盖"冲突。

## 二、前提：图/表是辅助材料，不是正文派生

### 2.1 修正后的关系

```
节计划（deliverables：图型 / 图名 / elements；表名 / cols）
   │
   ├─ 正文 Agent ──────────────── 文字（引用图/表，放占位符）
   ├─ 图示 Agent（elements + 依据/条款 + 已核对素材） ┐ 三路并行
   └─ 表格 Agent（cols + 依据/素材）                  ┘
                    ↓
   结构/交付物校验 → 依据可追溯 → 图文不矛盾 → 合并进正文
```

- **共同来源是"节计划 + 依据 + 素材"，不是正文。** 正文和图表是同一份节计划的两个产物，互为补充。
- **图可以包含正文没展开的信息**（架构分层、部署拓扑、时间线、组织关系）。不要求"节点能在正文找到"。
- **正文要引用图/表**（"如图/表「标题」所示"），否则图是孤立的。
- **图表要能和正文对上**：至少不能出现"正文说三层、图里四层""正文写 2026、图里 2027"这类矛盾；图比文多不算错。

### 2.2 三类"图"要分开

| 类型 | 来源 | 是否走图示 Agent | 换模型 | 校验 |
|---|---|---|---|---|
| AI 示意图（架构/流程/层次/时间线） | 节计划的 elements + 依据 + 素材 | 是 | 是 | 本文第七节 |
| 素材图（证书/截图/现场照） | 用户上传/检索 | 否 | 否 | 格式、大小、页内归属（沿用现有） |
| 模板图/手绘图 | 用户插入 | 否 | 否 | 用户自负责 |

**"图片也能切模型"只针对 AI 示意图**；素材图没有模型可切，UI 上不要给素材图挂模型下拉。

### 2.3 对 v2 的删改清单

| v2 位置 | 处理 |
|---|---|
| §1.1②「图/表 ← 正文，同源一致」 | 改为「图/表 ← 节计划 + 依据 + 素材」 |
| §1.2「异步：图/表与正文并行」 | **保留**，并行成立 |
| §5.2「图由文生 / 节点必须在正文找到对应词」 | **删除**，改为第七节的依据可追溯 + 图文不矛盾 |
| §2.1「主编…写正文」 | 改为「主编：生成/校验计划，不写正文」 |
| §3.1「编写整章弹窗」 | 删除（当前无此弹窗，改为头像/设置面板） |
| §3.3「localStorage + 项目设置」 | 改为服务端两层存储（第六节） |
| §六 5 个角色 | 改为 4 个头像 + 1 个不进头像的精修设置（第六节） |
| §九 三个待确认 | 本版已定，不再开放 |

## 三、节计划：`deliverables` 增加 `elements`

### 3.1 Schema

```jsonc
{
  "title": "总体技术方案",
  "points": ["说明总体架构分层", "说明与现有系统的关系"],
  "words": 900,
  "basis": [{"type": "score_point", "ref": "技术架构合理性（15分）", "use": "回应分层设计"}],
  "how": {"structure": "先结论后分层", "style": "务实", "pitfalls": ["不要堆术语"]},
  "deliverables": [
    {"kind": "text", "title": "正文", "words": 700},
    {
      "kind": "figure",
      "title": "总体架构图",
      "type": "layered",
      "elements": ["接入层", "服务层", "数据层", "安全与运维体系"]
    },
    {
      "kind": "table",
      "title": "能力对照表",
      "cols": ["能力项", "现状", "目标", "拟实施措施"]
    }
  ]
}
```

规则：

- `elements`：2–8 个，每个 ≤24 字，非空、去重，禁止箭头/换行；表达"图必须覆盖的要素"，不是精确节点文案。
- `type`：`flow | layered | timeline`，缺省 `layered`。
- `cols`：表格列名，2–6 个；表格数据由表格 Agent 从依据/素材填，不从正文抄。
- 图名/表名在同一章内唯一（占位符按标题匹配）。

### 3.2 生成与归一化

改 `backend/services/section_outline.py`：

- `_normalize_deliverables()`：新增 `elements` 清洗（`_clean` 24 字、去重、最多 8 个）；figure 缺 elements 时保留空数组并标 `elements_source: "derived"`。
- `OUTLINE_SYSTEM`：新增要求——"图必须给出 2–8 个**要表达的要素**（层次/阶段/角色），不是图注"。
- `fallback_outline()`：没有模型时不编造 elements，留空并标 derived，由图示 Agent 从要点/依据派生。
- `build_section_payload()`：把 `deliverables` 原样带进正文/图示/表格三个 Agent 的输入。

### 3.3 旧大纲兼容

- 已确认的大纲**不重新生成**；读取时 elements 缺失 → 在图/表生成阶段按 `points + basis` 派生，派生结果写进 job artifacts（可追溯），不回写用户大纲。
- 章节计划页显示提示："本大纲生成于 v3 之前，图要素将由图示 Agent 从依据派生，可手动补全。"

## 四、编排：章节级 SSE 作业

### 4.1 总时序

```
POST /chapter-writes  ──►  job（快照：base_content / revision / evidence / settings / outline）
GET  /chapter-writes/{id}/stream
  ① 读计划：有 outline → 直接用；没有 → 主编生成大纲（一次调用）后继续
  ② 并行启动：
       正文循环（串行，逐节流式）  ┐
       图表批次（按节并行，≤2 并发）┘
  ③ 逐节合并：占位符替换 → 校验 → 写进 draft（job.artifacts，不动 blocks）
  ④ 收尾：全章校验 → 待办
  ⑤ 落库：base_content/revision/evidence 未变 → 写正文 + 1 条 revision；否则返回建议稿，不覆盖
```

### 4.2 调度细节

- **正文串行**：保证节间上下文一致，用户能持续看到"正在写第 N 节"。
- **图表批次并行**：计划一就绪就启动，不等正文；每节只生成交付物要求的图/表。
- **并发上限**：`MODEL_LIMIT=3` 沿用——1 路正文 + 2 路图表；图表批次内部排队。
- **合并顺序**：按大纲节序合并；某节图表还没好时，正文继续写下一节，不阻塞生成；但该节进入 draft 要等图表结束或超时（超时标记"图待补"）。
- **落库策略**：过程中只写 job artifacts（进度可恢复），**结束时一次性落库**，避免写到一半覆盖用户内容。取消时保留 artifacts，用户可打开"建议稿"人工决定是否写入。
- **单任务约束**：同一 block 同时只允许一个 queued/running 作业（沿用 `create_job` 的 `BEGIN IMMEDIATE` 检查）。

### 4.3 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/projects/{pid}/studio/chapter-writes` | 建作业；body：`{thread_id, block_id, settings_override?}`；返回 `{job_id}`；已在跑则返回现有 job |
| GET | `/api/projects/{pid}/studio/chapter-writes/{job_id}/stream` | SSE，事件见 4.4；带 15s heartbeat |
| GET | `/api/projects/{pid}/studio/chapter-writes/{job_id}` | 作业状态 + 节状态 + 部分产物（刷新/重连用） |
| POST | `.../{job_id}/cancel` | 停止后续调度；已完成节保留在 artifacts |
| POST | `.../{job_id}/retry` | 仅重跑失败/待补的节或图表（body 可指定 section/role） |

- 复用 `chapter_writing_jobs`：新增 `mode` 列（`legacy|chapter_sse`），快照字段不变；`chapter_writing.run_job` 的旧轮询路径标记 legacy，不再被新入口调用。
- 入参校验：block 属于当前 project/thread；模型配置存在；大纲可读；否则 409/404，不建 job。

### 4.4 SSE 事件

| 事件 | payload | 驱动 |
|---|---|---|
| `job` | `{job_id, status, stage, progress}` | 顶部状态 |
| `plan` | `{sections:[{index,title,words,deliverables}], source:"existing"\|"generated"}` | 主编头像、节列表 |
| `role` | `{role, state, model, section_index, detail?}` | 4 头像的 `queued/working/done/skipped/failed` |
| `section` | `{index, title, state, words}` | 进度条/节列表 |
| `delta` | `{index, text}` | 正文流式高亮 |
| `chart` | `{role, index, title, state, markdown?, checks?, model}` | 图/表头像、图片卡 |
| `todo` | `{items:[...]}` | 待办增量 |
| `heartbeat` | `{ts}` | 保活 |
| `done` | `{content, saved, reason, models, checks}` | 结束/是否已写入 |
| `error` | `{scope:"job"\|"section"\|"chart", index?, message, recoverable}` | 错误提示 |

- 头像状态由 `role` 事件聚合；"跳过"由后端明确发（本节无图/表交付物），不靠前端猜。
- 重连/刷新：先 GET job 状态重建 UI（节/图表/模型），再开 stream 只收后续事件；SSE 无回放，**状态以 job 详情为准**。

### 4.5 取消、断线、服务重启

| 场景 | 行为 |
|---|---|
| 用户取消 | 停止调度；已完成节保留 artifacts；job=`cancelled`；UI 显示"已完成 N/M 节，可打开建议稿" |
| 浏览器断线 | 服务端继续跑；重进页面 GET job；若已 `done` 直接显示结果 |
| 服务重启 | 运行中的 job 标记 `failed`（`error='服务重启，任务中断'`），已完成节保留；用户可重试，不自动重跑烧额度 |
| 模型不可用 | 单次调用回退到默认模型，发 `role`（`model=used, fallback=true`）；全部不可用则 job 失败 |

## 五、生成输入与提示词

> 三条 Agent 的输入都**不含对方的生成稿**：图示/表格不读正文，正文不读图表内容（只读交付物标题/要素/列名）。

### 5.1 正文 Agent

输入：

```jsonc
{
  "chapter": "...",
  "section": {"title": "...", "points": [...], "words": 900},
  "basis": [...], "how": {...},
  "deliverables": [
    {"kind": "figure", "title": "总体架构图", "type": "layered", "elements": ["接入层", "..."]},
    {"kind": "table", "title": "能力对照表", "cols": ["能力项", "..."]}
  ],
  "requirements": [...],
  "materials": [{"id": 1, "name": "...", "excerpt": "..."}],
  "citations": [...],
  "writing_spec": {...}
}
```

要求（写进 `SECTION_SYSTEM`）：

1. 只写文字，不生成表格/节点；图/表由其他 Agent 并行生成。
2. 在需要图/表的位置**原样输出占位符**：`[[FIGURE:总体架构图]]`、`[[TABLE:能力对照表]]`；每张图/表恰好一个。
3. 在占位符附近写引用句："如图「总体架构图」所示…"或"如表「能力对照表」所示…"。
4. 数字/名称口径与图表一致；不确定的数字标 `【待补充：…】`，不编造。
5. 其余沿用现有 SECTION_SYSTEM（先结论、3–6 段、①②③、引用带【来源】等）。

### 5.2 图示 Agent

输入：

```jsonc
{
  "chapter": "...",
  "section": {"title": "...", "points": [...]},
  "deliverable": {"title": "总体架构图", "type": "layered", "elements": ["接入层", "服务层", "数据层"]},
  "basis": [{"type": "clause", "ref": "...", "use": "..."}],
  "materials": [{"id": 1, "name": "...", "excerpt": "..."}],
  "requirements": [...],
  "user_hint": "可选"
}
```

输出（强约束 JSON）：

```jsonc
{
  "type": "layered",
  "title": "总体架构图",
  "nodes": [
    {"label": "接入层", "level": 0, "ref": {"kind": "element", "index": 0}},
    {"label": "营销服务", "level": 1, "ref": {"kind": "material", "id": 12}},
    {"label": "数据中台", "level": 1, "ref": {"kind": "basis", "index": 0}}
  ]
}
```

要求：

- 节点 2–12 个；`elements` 每个至少映射 1 个节点；可额外补 ≤2 个有依据的节点。
- 节点是短语（≤24 字），不是整句；layered 给 level（0–3）；timeline 给 4 位年份。
- **每个节点必须带 `ref`**：`element`（第几个要素）/`basis`（第几条依据）/`material`（素材 id）。
- 不许出现 ref 来源里没有的数字/日期/标准号；不确定就不写。
- 超过 12 个节点、或 nodes <2 → 不截断、不静默处理，直接判失败并重试一次（更严格提示词）。

### 5.3 表格 Agent

输入：`deliverable{title,cols}` + `section.points` + `basis` + `materials` + `requirements`；不读正文。
输出：Markdown 表（或 `{columns,rows}`），第一行表头；列名按 `cols`，`cols` 为空时自拟 3–5 列。
要求：数字/名称必须来自 basis/materials，缺数据写 `【待补充：…】`；行数 1–12；不编造。

### 5.4 占位符与放置

- 后端按标题精确匹配 `[[FIGURE:标题]]` / `[[TABLE:标题]]`，用 `:::diagram type=… 标题` 块 / Markdown 表 + `**表：标题**` 替换。
- 缺占位符：图/表追加到本节末尾，同时进 `auto` 待办"正文未引用「X」，已放在节末"。
- 多余占位符（无对应交付物）：移除并进 `proof` 待办。
- 图表都不插入正文的中间位置之外的地方；不重排用户段落。

### 5.5 精修/重写/图调整（单 logo 场景）

| 场景 | 角色/模型 | 输入 | 约束 |
|---|---|---|---|
| 整节重写 | `rewrite`（默认 pro） | 本节原文 + 用户优化方向 + basis/how/deliverables + 素材/引用 | 只替换本节文字；保留图/表占位符与已有 `:::figure`/`:::diagram`/表格块；失败保留原文 |
| 局部精修 | `rewrite` | 选中段 + 方向 | 只替换选中段；不动其他段落与图表 |
| 压缩/换语气 | `rewrite` | 原文 + 目标字数/语气 | 字数下界按"目标"而不是"原文 80%"；由用户方向决定 |
| 图调整 | `diagram` | 当前图结构 + 本节 `elements` + 依据/素材 + 用户要求 | 只重生成该图，不动正文；新图重新走第七节校验 |
| 表重生成 | `table` | 交付物 `cols` + 依据/素材 + 用户要求 | 只重生成该表，不动正文 |

- 精修/重写不再"读不到原文就重写一篇"：原文必须注入；输出与原文做 diff，字数/引用/占位符缺失进 `proof`。
- 改完写 revision（`role=rewrite`、`model`、`prompt`），可从版本恢复。

## 六、模型分工与切换

### 6.1 角色字典（唯一口径）

| key | UI 名称 | 头像 | 设置行 | 职责 | 默认模型 |
|---|---|---|---|---|---|
| `chief` | 主编 | 是 | 是 | 生成/校验大纲与节交付物；不写正文 | pro |
| `text` | 文字 | 是 | 是 | 每节正文（流式） | flash |
| `rewrite` | 文字精修 | 否（单 logo） | 是 | 带原文的整节重写/局部精修/压缩 | pro |
| `diagram` | 图片 | 是 | 是 | 由 elements + 依据/素材生成示意图 | flash |
| `table` | 表格 | 是 | 是 | 由 cols + 依据/素材生成表格 | flash |

- 审校 `wang_anshi` / `bao_zheng` 本版不进入链路，设置面板不出现；旧 job 路径保留字段，标 legacy。
- `rewrite` 与 `text` 是不同设置键，接口上走 `role=rewrite`（内部复用 text 的调用，注入原文与精修要求）。v2 的 `text/diagram/table` 三值不够用的问题在此解决。

### 6.2 解析、校验与回退

```
解析顺序：章节覆盖(block) → 项目默认(project) → 内置默认(6.1 表) → 首个可用生成配置
显式选择的模型必须在 config_store.get_all() 里，且 provider 不属于 JUDGMENT_PROVIDERS（typesafe）
建 job 时一次性校验所有角色模型；有不可用 → 409，列出 role/model，不建 job
运行中调用失败 → 回退到"首个可用生成配置"，事件标 fallback=true，used_model 照实记录
生成路径不再轮询：只有完全没有配置时才用轮询池兜底
```

- 不回退到"另一个模型"再重试同一内容（会重复计费）；失败明确报错，由用户决定重试。
- 每次调用返回 `requested_model / used_model / fallback`，SSE 的 `role` 事件带给前端。

### 6.3 存储与 API

新表（SQLite）：

```sql
CREATE TABLE IF NOT EXISTS writing_model_settings (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  scope      TEXT NOT NULL CHECK(scope IN ('project','block')),
  scope_id   TEXT NOT NULL,
  settings   TEXT NOT NULL DEFAULT '{}',
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  UNIQUE(scope, scope_id)
);
```

API：

- `GET/PUT /api/projects/{pid}/writing-settings` —— 项目默认
- `GET/PUT /api/blocks/{bid}/writing-settings` —— 章节覆盖
- PUT body：`{"settings":{"chief":"deepseek-v4-pro","text":"deepseek-flash",...},"reset":false}`；PUT 前校验模型存在。
- 解析在服务端完成，前端只回显"实际生效值"。

**只有两层**：项目默认 + 章节覆盖（v2 的第三个"本次覆盖"删除）。头像点击 = 改章节覆盖，标注"仅本章"；设置面板可把章节值"设为项目默认"。

### 6.4 UI

```
正文上方（工具条下一行，轻量，不新增进度面板）：
┌──────────────────────────────────────────────────────────────┐
│ [🧭 主编 规划中]  [✍ 文字 工作中 · flash]  [🖼 图片 等待]  [▦ 表格 等待] │
│ 正在写：③ 行业发展背景（3/8 节）  ██████░░░░ 62%   [停止]        │
└──────────────────────────────────────────────────────────────┘
```

- 4 个头像：主编/文字/图片/表格；每个下方小字显示当前生效模型；点击弹小菜单"换模型（仅本章）"。
- 状态：`等待 / 工作中 / 完成 / 跳过 / 失败`；失败可点开原因。
- 单 logo 场景：重写/精修 → ✍ 文字精修；图调整 → 🖼；表重生成 → ▦；展示模型 + 换模型。
- 右栏"进度"页签仍是**唯一的节级明细**；头像条只做章级总览，不复制节列表（避免第三套进度）。
- 旧 `chapter-team.mjs`、`team` 占位、`writeChapterApi` 全部删除；"编写整章"两份重复实现合并为一个函数。

### 6.5 运行中切换

- 作业启动时把 role→model 快照写进 job；运行中点头像显示"下次编写生效"，**不改当前作业**，避免同一章混用模型导致不可解释。
- 例外：图表失败后的"重试"按当前设置取模型（重试是新调用，写进记录）。
- 精修/重写弹窗里的换模型属于新调用，立即生效。

### 6.6 默认值

| 角色 | 默认 | 理由 |
|---|---|---|
| 主编 | pro | 大纲/交付物决定后续质量 |
| 文字 | flash | 实测单节 5s 左右，够用；可切 pro |
| 精修 | pro | 改写吃能力 |
| 图片 | flash | 结构抽取任务短（实测 1–2.5s）；质量不达标再切 pro |
| 表格 | flash | 同上 |

- 界面不硬编码"强/快"标签（配置里没有这个字段）；只显示模型名 + 可选备注。
- 设置面板给"调用次数估算"（正文 N 次 + 图数 + 表数），不编造 ¥ 金额（没有定价表之前）。

## 七、校验与待办

### 7.1 图片三档

| 档 | 规则 | 不通过 |
|---|---|---|
| **A. 结构/交付物（硬拦）** | 节点 2–12（不截断）、非空、去重、≤24 字、无换行/箭头；`type` 与交付物一致；`elements` 每项至少一个节点覆盖；提前定义 title | 自动重试一次（更严格提示词）；再失败 → 图失败，不插入，进 `auto` 待办"图待补" |
| **B. 依据可追溯（软）** | 每个节点必须有 `ref`，且指向 `elements` / 依据条款 / 已核对素材三者之一；指向依据或素材时，节点核心词必须能在对应原文找到；节点中的数字/日期/标准号必须出现在对应来源原文 | 插入但在图片卡标"依据待核"，进 `proof` 待办，带"来源：X"证据 |
| **C. 图文不矛盾（软）** | 图与正文都出现的数字/名称必须一致；图比文多不算错；只报可确定的结构数量（正文明确写"分 N 层/类/阶段"时才与图的实际层级/节点数比对），不确定不报 | 进 `proof`；默认不阻断，严格模式才拦导出 |
| **D. 引用/位置（软）** | 正文有对应占位符；占位符前有"如图/表「标题」"引用句；图块落在本节内 | 缺引用 → `proof`；缺占位 → 追加到节末 + `auto` |

**明确不做**：不检查"节点是否出现在正文"；不因图比正文多内容而报错；不在校验里再调一次模型（审校本版不做）。`strip_invalid_diagrams` 的静默删除改为"记录 + 待办"。

### 7.2 表格

| 检查 | 处理 |
|---|---|
| 列名与 `cols` 一致（有 cols 时硬拦） | 不一致 → 重试一次，仍不一致 → `auto` "表待补" |
| 行数 1–12、无空列、表名存在 | 硬拦/重试 |
| 数字/名称来自 basis/素材 | 无来源 → `proof` "表内数字无依据：X" |
| 表内数字与正文冲突 | `proof`；图比文多不算错 |
| 正文有占位符 + 引用句 | 缺失 → `auto` 追加/`proof` 引用 |

### 7.3 进待办

- `auto`（系统可修）：图/表生成失败、缺占位、列名不符 → 动作"重新生成/插入到节末"。
- `proof`（要你核对）：节点无依据、数字无依据、图文矛盾、缺引用 → 动作"定位到图/表 + 查看证据"。
- 沿用 `writing_plans.build_todo_items` / `todo_checks` 的分组与 id 规则；新增 `source="图表校验"`，证据里带节点名/来源名/原文片段。
- 所有校验结果同时写进 job artifacts 的 `checks[]`，刷新后可见。

### 7.4 严格模式（可选，后续）

项目设置 `strict_figure_checks=false`（默认）。开启后：存在未处理的 `proof` 项 → 导出前拦截（复用现有 `gate` 机制）。本版先不做开关 UI，只预留字段。

## 八、失败矩阵与人工保护

| 失败 | 处理 |
|---|---|
| 没有大纲 | 主编生成一次（事件 `plan source=generated`）；失败 → job 失败，不写正文 |
| 没有可用模型 | 建 job 时 409；不进入队列 |
| 某节正文失败 | 保留该节原内容，继续其他节；job `partial`；`auto` "本节待补" |
| 某图/表失败 | 该节正文照常合并（无图/表）；`auto` "图/表待补"；job 不失败 |
| 模型回退 | 用默认模型继续，`role` 事件标 `fallback=true`；结束汇总里列出哪些节回退 |
| 取消 | 停止调度；artifacts 保留；不自动写 blocks；用户可打开建议稿 |
| 人工在编写中改了正文 | 结束落库前比对 `base_content/revision/evidence`；不一致 → 不覆盖，返回建议稿 |
| 素材/依据在编写中变化 | 同上，不覆盖 |
| 服务重启 | running job → failed（"任务中断"），已完成节保留；不自动重跑 |
| 导出 | 只认已保存正文；未保存/待补项在导出前提示（现有 gate 口径） |
