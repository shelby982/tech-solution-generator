# 编写大纲优化方案：把「依据/写法/交付物」下沉到每一节

> 用户思路：有了大纲之后，**每节的内容不同、写法也不同**，所以章一级的「依据 / 写法 / 交付物」应当
> 直接融进每个子章节；右侧进度里重写某节时要能**输入提示词**；章节里的**图片**也要有修正办法。
> 本方案给出数据模型、界面、生成逻辑、交互与图片处理的完整设计。

---

## 一、核心变化：章级 → 节级

| 现在（章级大块） | 改为（每节自带） |
|---|---|
| 计划面板「依据与标准」（评分点/条款/失分点） | 每一节的 **依据**（本节凭什么写） |
| 计划面板「写法要点」（结构/段落/落点） | 每一节的 **写法**（本节怎么写） |
| 计划面板「交付物」（章级 2~5 项） | 每一节的 **交付物**（本节要交什么） |

**为什么**：同一章里，「政策依据」节要引用原文并列表映射；「现状分析」节要写数据与差距；
「建设目标」节要写量化指标——**依据与写法本来就不一样**，放在章级只能写笼统的话。

---

## 二、数据模型：节级计划

```json
{
  "title": "政策依据梳理与要求归纳",
  "words": 1200,
  "points": ["逐项列示适用政策", "归纳对本项目的要求", "区分强制性与引导性"],

  "basis": [
    {"type": "score_point", "ref": "对项目的理解正确、深入、全面（10 分）", "excerpt": "深刻理解…政策背景"},
    {"type": "clause", "ref": "技术规范书 2.2.5(2)", "excerpt": "投标人应说明…"},
    {"type": "policy", "ref": "《中共中央 国务院关于加快建设全国统一大市场的意见》", "use": "引用原文要求"},
    {"type": "material", "ref": "业绩证明_2024.docx", "use": "抽表格数据"}
  ],

  "how": {
    "structure": "政策原文 → 要求归纳 → 对本项目的含义 → 对应工作",
    "style": "首句结论；①②③ 分点；每条政策后必须带【来源】",
    "pitfalls": ["不要复述政策全文", "必须区分强制性与引导性要求"]
  },

  "deliverables": [
    {"kind": "text",  "title": "政策要求归纳", "words": 600},
    {"kind": "table", "title": "政策依据映射表", "cols": ["文件/文号", "核心要求", "对应工作", "依据状态"]},
    {"kind": "figure","title": "政策要求与工作对应关系", "type": "layered"}
  ]
}
```

**节级三问的答案就在这三个字段里**：
- (a) 依据 → `basis[]`（评分点 / 招标条款 / 政策原文 / 素材）
- (b) 写法 → `how`（结构 / 句式 / 禁止项）
- (c) 交付物 → `deliverables[]`（文字多少字、什么表、什么图）

兼容：节级字段缺失时**继承章级**（老大纲不用重做，逐步补齐）。

## 三、界面：计划面板与进度面板各管什么

### 3.1 计划面板（只读说明书，改成"逐节可展开"）

```
本章计划
项目背景现状目标      计划 12 页 · 3000 字

▾ 1  章节大纲   9 节                          [重做大纲]
   ▾ ① 政策依据梳理与要求归纳        1200 字 · 表1 图0
      依据：评分点「对项目的理解…」· 条款 2.2.5(2) · 政策 2 份 · 素材「业绩证明」
      写法：政策原文 → 要求归纳 → 本项目含义 → 对应工作；每条政策带【来源】
      交付物：文字 600 字 + 表格「政策依据映射表」4 列
   ▸ ② 现状分析总体框架              1000 字 · 表0 图1
   ▸ ③ 核心问题诊断                   900 字
   …
▸ 2  章节类型（影响生成）    技术方案
```

- **删除**章级的「依据与标准」「写法要点」「交付物」三块
- 每节**可展开**看三问；默认折叠（避免又变成一屏文字）
- 节的依据/写法**可编辑**（低频，放展开区里的小链接「调整要求」）

### 3.2 进度面板（动作 + 提示词 + 图片状态）

```
进度
章节编写进度 5/9 节已写
[继续编写（补未写）]

▸ ① 政策依据梳理与要求归纳   已写 | 基于提示词 | [重写本节]
   提示词：[ 语气更务实，突出广东电网牵头责任… ]        ← 新增
▸ ② 现状分析总体框架        已写 | 图：待补 1         [重写本节]
   提示词：[ … ]
✓ ③ 核心问题诊断           已写                     [重写本节]
```

- 每节一个**提示词输入框**（可折叠）→ 点「重写本节」时带上
- 提示词**持久化**到该节（下次重写默认复用，可清空）
- 右侧标出**图片状态**：`图：待补 1 / 已生成 / 来自素材`

## 四、生成逻辑改造

| 环节 | 改造 |
|---|---|
| 生成大纲 | 提示词要求**每节都产出 basis / how / deliverables**（依据从本章评分点、条款、素材里挑） |
| 写一节 | 把该节的 basis/how/deliverables **全部注入**提示词；要求按交付物产出（文字 + 表 + 图） |
| 校验 | 写完后检查：该节交付物是否齐（表/图有没有）、依据是否被引用、字数是否达标 |
| 缺口 | 缺表/图 → 进待办与进度（「图：待补」）；缺依据 → 「依据核对」 |

---

## 五、交互：重写时输入提示词

- 新字段：`section.prompt`（用户额外要求）
- API：`POST /studio/section`、`GET /studio/section/stream` 增加 `prompt` 参数
- 提示词注入方式：放在用户消息末尾 `【本次额外要求】{prompt}`，并**优先于**默认写法（冲突时以用户为准）
- 效果：同一节可以「更务实 / 更技术 / 压缩到 800 字 / 补一个对比表 / 换成时间线图」等定向优化
- 持久化：存在节上，进度面板可见可改可清空

## 六、图片处理（第 3 点）

### 6.1 图片的两类来源 × 三种状态

| 来源 | 能否重新生成 | 允许的操作 |
|---|---|---|
| **生成图**（结构/趋势/对比图，`:::diagram`）| ✅ 可由本节内容重新生成 | 重新生成 / 换图型 / 改图注 / 删除 |
| **素材图**（证书、截图、现场照，`:::figure`）| ❌ 不能生成真实图片 | 替换素材 / 换图注 / 删除 |

| 状态 | 显示 | 动作 |
|---|---|---|
| 计划要图·未生成 | 「图：待补 1」 | 生成图 / 从素材插入 |
| 已生成（模型）| 「图：已生成 · 可重生成」 | 重新生成 / 换图型 |
| 来自素材 | 「图：来自《文件名》」 | 替换 / 查看原图 |

### 6.2 图片写进节级计划
- `deliverables` 里 `kind=figure` 的项，进入进度作为该节的**待补/已生成**状态
- 图片元信息：`{slot, source: generate|material, ref, caption, status}`

### 6.3 重写某节时**不丢图**
- 写节前后做**图片保护**：把该节里已有的 `:::diagram` / `:::figure` / `![](…)` 块**抽出来**，
  写回新正文时**原样保留**（放在该节末尾），除非用户明确要求"重做图"
- 若该节交付物要求新图而模型没给 → 标「图：待补」而不是静默丢失

### 6.4 图片的"修正"入口
- 进度面板在该节行显示图片状态 → 点「图」→ 小面板：
  - 生成图：`重新生成` / `换图型（层次/流程/时间线）` / `编辑图注`
  - 素材图：`替换素材` / `调整图注` / `删除`
- 全部走已有的 `:::diagram type=…` 语法与 `/studio/diagram` 接口，**不新增图片格式**

## 七、迁移与兼容

| 现状 | 处理 |
|---|---|
| 章级「依据与标准 / 写法要点 / 交付物」 | 保留为**兜底**（节级缺失时继承），界面从章级移除 |
| 现有 9 节大纲（无 basis/how/deliverables）| 一次性补齐：用章级依据 + 节标题让模型产出三问；缺省用规则兜底 |
| 已有正文 | 不动正文；只更新计划 |

---

## 八、验收标准

1. 计划面板**没有**章级「依据与标准 / 写法要点 / 交付物」三块
2. 每节展开后能看到 **(a) 依据 (b) 写法 (c) 交付物** 三项，且非空
3. 写节时按交付物产出：文字≥目标字数、要求的表/图出现
4. 缺表/图时进度里显示「待补」，不静默丢失
5. 重写支持**提示词**且持久化；带提示词与不带的结果有明显差异
6. 重写**不丢已有图**；生成图可重新生成、素材图可替换
7. 无控制台错误，自检规则覆盖 1/2/4/6

---

## 九、实施顺序（建议）

| 步骤 | 内容 | 量 |
|---|---|---|
| S1 | 后端：大纲 schema 扩展（basis/how/deliverables）+ 大纲生成提示词改造 + 老大纲补齐脚本 | 中 |
| S2 | 计划面板：删除章级三块；大纲逐节展开显示三问 | 中 |
| S3 | 写节注入三问 + 交付物校验（缺表/图标待补）| 中 |
| S4 | 进度面板：每节提示词输入 + 持久化 + 传入写节接口 | 中 |
| S5 | 图片：状态展示 + 重写保图 + 生成图重生成/换图型；素材图替换 | 中 |
| S6 | 自检规则 + 一次性补齐脚本 | 小 |

## 十、待你确认

1. 节级「依据/写法」是否**允许用户编辑**（我建议允许，低频折叠在展开区）？
2. 提示词输入框：**常驻**（每节一行输入）还是**点击展开**（先点「提示词」再展开输入）？
3. 图片"重新生成"时：**保留原图另存**（版本里）还是**直接替换**？我建议直接替换 + 版本可回溯。
