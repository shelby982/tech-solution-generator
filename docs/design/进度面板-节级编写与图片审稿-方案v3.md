# 进度面板 v3（修订）：图片修改入口随节走，另设「一屏审稿」看全章图

> 对 v2 的两点修订（用户澄清）：
> 1. **图片的修改入口放在对应章节后面**（不是独立的全局区块）
> 2. **「图片单列」的真实目的是审稿**：点开**一屏**看到本章所有图片，用来快速审稿

---

## 一、修订后的结构

```
进度
├─ 章节编写进度   5/9 节已写                      [审阅本章图片 5]
│  ① 政策依据梳理与要求归纳   已写 · 834 字   [重写]
│      🖼2  「政策要求与工作对应关系」层次图5节点  [调整]
│           「现状趋势对比」时间线4节点           [调整]
│  ② 现状分析总体框架        已写 · 1204 字  [重写]
│      🖼1  「资质证书扫描件」素材·《资质.pdf》8页  [替换]
│  ③ 核心问题诊断           未写          [编写]
│      🖼1  目标对比图（待补）                   [生成]
│  ④ …
│
└─ （不再有独立的"图片"区块）
```

- **图片挂在节下面**：每节行下方列出该节的图，**修改入口就在图旁**（AI 图 [调整]、素材图 [替换]、待补 [生成]）
- **顶部一个「审阅本章图片 N」按钮** → 打开**一屏图集**（审稿用）

## 二、一屏审稿视图（这是"图片单列"的真正价值）

```
┌ 本章图片（5 张）   [全部] [AI 生成 3] [素材 2] [待补 1]        × ┐
│                                                                 │
│  ┌────────────┐  ┌────────────┐  ┌────────────┐                │
│  │  层次图预览 │  │  时间线预览 │  │  ＋ 待补    │                │
│  │  (缩略)     │  │  (缩略)     │  │  目标对比图  │                │
│  └────────────┘  └────────────┘  └────────────┘                │
│  ① 政策要求与工作   ② 现状趋势对比   ③ 目标对比（待补）            │
│     [调整][定位]      [调整][定位]     [生成]                     │
│                                                                 │
│  ┌────────────┐  ┌────────────┐                                │
│  │  证书扫描件  │  │  现场照片    │                                │
│  │  (素材)     │  │  (素材)     │                                │
│  └────────────┘  └────────────┘                                │
│  ② 资质证书  第8页   ② 机房现场  第12页                             │
│     [替换][查看]      [替换][查看]                                │
└─────────────────────────────────────────────────────────────────┘
```

**审稿时能一眼看清的 5 件事**
1. **图型是否合适**（层次/流程/时间线 与本节内容是否匹配）
2. **节点是否合理**（数量、文案是否过长、是否有重复）
3. **图注是否正确**（`:::diagram 标题` 是否与正文呼应）
4. **缺不缺图**（计划的交付物要图但没生成 → 待补卡片）
5. **素材图是否对**（文件、页码、是否与本节内容对应）

**每张卡片上的动作**
| 类型 | 动作 |
|---|---|
| AI 生成 | 大图预览 · [调整]（提示词+图型）· [定位到正文] · [删除] |
| 素材 | [查看原图] · [替换] · [定位到正文] · [删除] |
| 待补 | [生成]（AI 按本节正文生成）· [从素材插入] |

**筛选**：全部 / AI 生成 / 素材 / 待补 —— 审稿时先看"待补"，再看"AI 生成是否对味"。

**缩略图实现**：复用正文的图型渲染器（HTML 渲染），容器缩放呈现，**不额外生成图片**。

## 三、节下面的图片行（修改入口）

```
① 政策依据梳理与要求归纳   已写 · 834 字        [重写]
   🖼 2
   ▸「政策要求与工作对应关系」层次图 · 5 节点      [调整] [定位]
   ▸「现状趋势对比」时间线 · 4 节点               [调整] [定位]
```

- 默认**折叠**（节行显示 `🖼2`，点开显示图片行）→ 避免列表变长
- 修改入口就在图片行右侧（AI [调整] / 素材 [替换]）
- 与审稿视图**共用同一套动作**（同一组件，两个入口）

---

## 四、两个入口的分工

| 入口 | 场景 | 形态 |
|---|---|---|
| **节下图片行** | 写到某节、发现这张图不对 → 就地改 | 行内（折叠展开）|
| **一屏审稿** | 全章过一遍、统一检查图与表 | 弹窗图集（网格 + 筛选）|

两个入口都指向同一份图片清单与同一套动作，不出现"两处口径"。

## 五、数据契约

```json
{"id":"fig-1","kind":"ai","section":"政策依据梳理与要求归纳","type":"layered",
 "title":"政策要求与工作对应关系","nodes":5,"markdown":":::diagram …","status":"ready"}
{"id":"img-2","kind":"material","section":"现状分析总体框架","file":"资质.pdf",
 "page":8,"url":"/api/…/image","caption":"资质证书扫描件","status":"ready"}
{"id":"fig-3","kind":"pending","section":"核心问题诊断",
 "title":"目标对比图","from":"deliverable","status":"pending"}
```

- `status`: `ready` / `pending`
- 由正文解析（`:::diagram` / `:::figure` / `![]()`）+ 节级交付物（缺图补 `pending`）合成
- 按**节顺序 → 正文出现顺序**排序（审稿时与阅读顺序一致）

---

## 六、验收标准（在 v2 基础上修订）

1. 图片修改入口**在对应节下面**（节行显示 `🖼N`，展开后可 [调整]/[替换]/[生成]）
2. 进度面板顶部有「审阅本章图片 N」，点开是**一屏图集**
3. 图集可筛选：全部 / AI 生成 / 素材 / 待补
4. 图集里每张图有**缩略预览** + 所属节 + 动作（与节下入口一致）
5. 图集可按节定位到正文对应位置
6. 未生成但计划要求的图，以**待补卡片**出现（不静默缺失）
7. 不再有独立的"图片"大区块（改为节下 + 审稿两层）
8. 表格仍不单列（只在节行显示 `含表 N`）

---

## 七、修订点对照

| 项 | v2 | v3（本稿） |
|---|---|---|
| 图片位置 | 进度面板底部独立区块 | **挂在节下**（修改入口随节）|
| "图片单列" | 两组列表 | 改为**一屏审稿图集**（缩略网格 + 筛选）|
| 审稿效率 | 需滚动列表 | 一屏看全章图，按"待补/生成图/素材图"筛 |
| 动作一致性 | 各自实现 | 节下与图集**共用同一动作组件** |
