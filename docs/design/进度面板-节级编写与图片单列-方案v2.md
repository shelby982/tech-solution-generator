# 进度面板（节级编写 + 图片单列）优化方案 v2

> 依据本轮口述细化：节状态与重写（重写前先输提示词）· 表格不单列 · **图片单列**（AI 生成图 / 素材图两组，
> AI 图可输入提示词调整）。本稿在 v1 基础上把「进度面板」这一块做到可实现。

---

## 一、面板结构与职责

```
进度                                    ← 右栏三页签之一
├─ 章节编写进度   5/9 节已写
│  ① 政策依据梳理与要求归纳    已写    [重写]
│  ② 现状分析总体框架         已写    [重写]        🖼 2
│  ③ 核心问题诊断            未写    [编写]
│  ④ 政策依据分析            未写    [编写]
│  ⑤ …（按大纲顺序）
│
└─ 图片 2 张                ← **单列**（不进正文列表，按节归属排序）
   AI 生成（1）
     ▸「政策要求与工作对应关系」· 层次图 · 5 节点 · 属①      [调整]
   ／素材（1）
     ▸「资质证书扫描件」· 《资质.pdf》第 8 页 · 属②           [替换] [查看]
```

**三条口径**
1. **节列表只回答**：这一节写了没有、要不要重写。
2. **表格不单列**：表格留在正文里（进度里只在节行尾显示"含表 N"，不另开区块）。
3. **图片单列**：所有图按「AI 生成 / 素材」两组集中展示，便于统一调整。

## 二、节行：状态 + 重写（重写前先输提示词）

### 2.1 节的三种状态

| 状态 | 判定 | 行内显示 |
|---|---|---|
| **未写** | 正文里没有该 `## 节` 或只有「（本节待写）」| `未写` + [编写] |
| **已写** | 该节有正文（≥100 字）| `已写 · 834 字` + [重写] |
| **编写中** | 正在流式写入 | `编写中… 已 683 字` + 按钮禁用 |

### 2.2 点「重写」→ 先出**提示词面板**（不是直接开写）

```
┌ 重写「政策依据梳理与要求归纳」 ────────────────────────┐
│ 本节现状：已写 834 字 · 交付物 文字600字+表1            │
│ 依据：评分点「对项目的理解…」· 条款 2.2.5(2)            │
│                                                      │
│ 优化方向（提示词）                                     │
│ ┌──────────────────────────────────────────────────┐ │
│ │ 例：语气更务实，突出广东电网牵头责任；每条政策后补    │ │
│ │ 一句"对本项目的含义"                                │ │
│ └──────────────────────────────────────────────────┘ │
│ 常用方向：[更务实] [更技术] [压缩到 800 字] [补对比表]   │
│ 上次提示词：突出强制性与引导性要求的区别        [清空]  │
│                                                      │
│ 此操作会覆盖本节现有内容（已存版本，可回滚）            │
│                                    [取消]  [开始重写] │
└──────────────────────────────────────────────────────┘
```

要点：
- **必须经过这一步**：用户先给方向，避免"点了就覆盖"。
- **显示现状**（字数/交付物/依据）与**覆盖风险**（可回滚）。
- **快捷方向 chips**：按节类型推荐（见第四节）。
- **记住上次提示词**（每节最近 3 条，可快选、可清空）。
- 若提示词为空 → 允许"直接重写"（等于按原计划重写）。

### 2.3 提示词的作用方式

- 注入到写节提示词末尾：`【本次额外要求】{prompt}`
- **冲突时以用户为准**（例：默认要求 600~1200 字，用户说"压缩到 800 字"→ 按 800）
- 持久化到该节 `section.prompt`，整章编写时也带上各自提示词

## 三、图片单列（AI 生成 / 素材 两组）

### 3.1 数据来源

从正文解析：每节段落内的 `:::diagram …`（AI 生成）与 `:::figure …` / `![…](…)`（素材图），
按**出现顺序**归到所属节。

```json
{"id":"fig-1","kind":"ai","section":"政策依据梳理与要求归纳","type":"layered",
 "title":"政策要求与工作对应关系","nodes":5,"text":":::diagram …","status":"ready"}
{"id":"img-2","kind":"material","section":"现状分析总体框架","file":"资质.pdf",
 "page":8,"url":"/api/…/image","caption":"资质证书扫描件","status":"ready"}
```

### 3.2 两种组的行内信息与动作

| 组 | 行内信息 | 动作 |
|---|---|---|
| **AI 生成** | 标题 · 图型（层次/流程/时间线）· 节点数 · 所属节 | **[调整]**（输入提示词重新生成）· [定位] · [删除] |
| **素材图** | 文件名 · 页码 · 图注 · 所属节 | [替换]（换一张素材）· [查看]（原图）· [定位] · [删除] |
| **待补**（计划要图未生成）| 交付物要求的图名 · 所属节 | [生成]（AI）· [从素材插入] |

### 3.3 「调整」AI 图 → 提示词面板

```
┌ 调整图片「政策要求与工作对应关系」 ───────────────────┐
│ 当前：层次图 · 5 节点                                 │
│ 数据来源：本节正文（重新生成不会改动正文）               │
│                                                      │
│ 调整方向：                                            │
│ ┌──────────────────────────────────────────────────┐ │
│ │ 例：改为时间线，按 2024/2025/2026 三个阶段展示        │ │
│ └──────────────────────────────────────────────────┘ │
│ 图型：[自动] [层次] [流程] [时间线]                    │
│                                                      │
│                                  [取消] [重新生成]     │
└──────────────────────────────────────────────────────┘
```

- 生成 → 预览 → `[替换这张图]`（**原图进版本，可回滚**）或 `[再试一次]`
- 图型下拉与正文语法一致（`type=layered|flow|timeline`）
- 提示词持久化到该图，下次调整默认带上

### 3.4 不单列表格，但保留"表格健康度"

- 进度面板**不单独列表格**。
- 节行尾显示 `含表 1`；若表有问题（列数不一致 / 无表头 / 单元格含未转义 `|`）→ 行尾显示 `表待修`
- 点 `表待修` → 定位到该表并提示"一键修表"（复用 `normalize_tables`）

## 四、快捷方向（chips）：按节类型推荐

| 节类型（由标题/依据判断）| 推荐提示词 |
|---|---|
| 现状 / 分析类 | 补数据对比 · 突出差距量化 · 加一张现状对比表 |
| 政策 / 依据类 | 每条政策补"对本项目的含义" · 区分强制性与引导性 |
| 目标 / 指标类 | 目标量化到指标 · 补完成时限与验收口径 |
| 难点 / 措施类 | 逐条对应问题 · 措施写到"谁做、怎么做、何时完成" |
| 通用 | 更务实 · 更技术 · 压缩 20% · 扩写 30% |

## 五、状态回写与异常

| 场景 | 行为 |
|---|---|
| 重写完成 | 节状态 → 已写；字数更新；图片区重算（该节图是否变化）|
| 重写失败/中断 | **保留原内容**，提示"已保留原文，可重试"（不落半截）|
| AI 图生成失败 | **保留原图**，提示原因（不静默删除）|
| 图片被删 | 进版本记录，可回滚 |
| 提示词为空 | 按原计划重写（允许）|

---

## 六、验收标准

1. 节列表每行有 **未写/已写/编写中** 三态，未写显示 [编写]、已写显示 [重写]
2. 点 [重写] **先弹提示词面板**（含现状、依据、chips、上次提示词、覆盖提示），确认后才开始
3. 提示词生效且持久化；同一节带/不带提示词结果不同
4. **图片单列**为「AI 生成 / 素材」两组；组内按节顺序；每行显示所属节与关键信息
5. AI 图可「调整」：输入提示词 + 选图型 → 重新生成 → 预览 → 替换（原图可回滚）
6. 素材图可「替换/查看」；待补图可「生成/从素材插入」
7. **表格不单列**，只显示 `含表 N`；表有问题显示 `表待修`
8. 重写失败不丢原内容；AI 图失败不丢原图
9. 无控制台错误；自检覆盖 1/4/7

## 七、与 v1 方案的差异

| 项 | v1 | v2（本稿） |
|---|---|---|
| 提示词输入 | 每节常驻输入框 | **点「重写」时弹出面板**（先给方向再写）|
| 图片 | 混在节行里提示状态 | **单列成区块**，AI/素材两组，统一调整 |
| 表格 | 未明确 | **不单列**，只显示计数与"待修" |
| 图片重生成 | 只说可重生成 | 增加**提示词 + 图型**两个维度，预览后替换、可回滚 |

## 八、实施拆分（在 v1 的 S1~S6 之上细化）

| 步骤 | 内容 |
|---|---|
| S4a | 节行三态 + [编写/重写] 按钮 |
| S4b | 重写提示词面板（现状/依据/chips/历史/覆盖提示）+ 持久化 + 传参 |
| S5a | 正文解析出图片清单（按节归属 + AI/素材分类 + 待补项）|
| S5b | 图片单列 UI（两组 + 状态 + 定位）|
| S5c | AI 图调整面板（提示词 + 图型 + 预览 + 替换/回滚）|
| S5d | 素材图替换/查看；表"待修"提示 |
| S6 | 自检规则（三态、图片单列、表格不单列、失败不丢内容）|
