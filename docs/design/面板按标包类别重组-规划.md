# 拆解面板 · 按「标包 × 类别」重组（规划）

> 用户口径：
> 1. 上面筛选部分**只保留标包/标的名称**（类别勾选从顶部拿掉）；
> 2. 技术、商务的评分点本就在下面的拆解部分 → **做成两个页签**（商务 / 技术），结构更清晰。
> 本文只规划，确认后再实施。

---

## 一、为什么要这样改（问题复述）

现状（v27）：

```
筛选：标包 [标的1/标包2 ▾]   类别 [☑技术 ☐商务 ☐报价]   当前目录：…   [按此筛选生成目录]
指标：评分点 8 个 | 目录骨架 134 | 技术要求 153 | 映射 8 | 评分表 2 类 | 待确认 3 项
页签：依据·招标文件评分点 | 依据·技术规范书要求 | 产物·目录骨架 | 产物·映射矩阵 | 待确认
```

三个别扭之处：

1. **类别是"勾选框"，但一次只生成一份目录** —— 勾选框暗示"可多选合并"，与"生成技术目录 / 生成商务目录"的心智不符；
2. **类别对内容的影响藏在指标里**：勾掉商务，指标里的"评分点 8→13"会变，但页签内容看不出"这些是哪个类别"；
3. **商务页签里出现"技术要求 153 条"** —— 技术要求来自技术规范书、按**标包**归属，与商务评分点基本无关，
   放在同一层会让"未落点 153 条"这类数字被误读。

## 二、目标结构

```
┌ 筛选（只留标包）──────────────────────────────────────────────────────────────┐
│ 标包 [标的1 / 标包2 · 高可靠技术专题研究与验证标包 ▾]                           │
│ 当前目录：标的1 / 标包2 · 技术应答目录                  [按此标包生成/重新生成目录] │
└──────────────────────────────────────────────────────────────────────────────┘
┌ 类别页签（该标包实际有的类别；badge = 评分点数 · 分值）─────────────────────────┐
│  [ 商务 13 个 · 135 分 ]  [ 技术 8 个 · 100 分 ]  [ 报价 3 个 · 150 分 ]        │
│   ▲ 选中哪个类别，下面全部内容（指标 + 依据 + 产物）都按"该标包 × 该类别"展示      │
└──────────────────────────────────────────────────────────────────────────────┘
┌ 指标（随所选类别）────────────────────────────────────────────────────────────┐
│  评分点 13 个 · 合计 135 分 ｜ 目录骨架 134 个 ｜ 映射 13 个 ｜ 覆盖率 …        │
│  （该类别没生成过目录时：目录骨架/映射/覆盖率显示 — + "该类别还没生成目录"）      │
└──────────────────────────────────────────────────────────────────────────────┘
┌ 内容（随所选类别）────────────────────────────────────────────────────────────┐
│  ① 依据 · 招标文件评分点（本类别）        表格，评分口径**完整展示**             │
│  ② 依据 · 技术规范书要求                  **只在「技术」页签**（见 §四-决策 1）  │
│  ③ 产物 · 目录骨架（本类别）              未生成本类别目录时为空态 + 一键生成      │
│  ④ 产物 · 映射矩阵（本类别）                                                      │
│  ⑤ 待确认（全局，条目带 标包/类别 chip）                                         │
└──────────────────────────────────────────────────────────────────────────────┘
页脚：[重新拆解评分点]  [收起，看目录]（目录已生成时）
```

要点：
- **类别从"勾选框"变成"页签"**（单选；页签 badge 直接给条数与分值，替代原来下拉里的括号概览）；
- **内容改为分区而非嵌套页签**：一个类别的内容量不大（8–13 条评分点 + 数张表），
  用「① 依据 / ② 产物 / ③ 待确认」小标题分区滚动，避免"页签里再套页签"的双层导航；
- **筛选只留标包**：类别由页签承担，顶部不再重复。

## 三、交互规则

| 场景 | 行为 |
|---|---|
| 展开面板 | 默认选中"当前目录所属的标包 + 类别"；没有生成过则选中该标包**分值最高**的类别 |
| 切换标包 | 类别页签重建（该标包有哪些类别就显示哪些）；默认选中该标包分值最高的类别；产物区显示空态（若该标包未生成） |
| 切换类别页签 | **只切视角**，就地刷新指标与内容；不跳页、不重跑 |
| 点「生成目录」 | 按 **当前标包 × 当前类别** 生成（一次一份）；生成后该页签的产物区有内容，标签写「当前目录」 |
| 该类别未生成 | 产物区（骨架/映射/覆盖率）：`—` + 「本类别还没生成目录」+ [生成 <类别>应答目录] 按钮 |
| 该标包未生成 | 依据区仍可看该标包全部类别的评分点；产物区空态 |
| 技术要求页 | 仅「技术」页签展示；商务/报价页签显示一行指引：「技术要求来自技术规范书、按标包归属，请到『技术』页签查看」 |

## 五、改动范围（评估）

**后端**：基本不动。
- `package_points`（按标包 → 按类别分组）与 `package_matrix`（标包 × 类别）已具备全部所需数据；
- 判定"该类别是否已生成"用运行态已有的 `current_categories` + `project_scope`；
- 唯一可能要动：`split_report.tech_matrix` 若要标注"与哪些类别相关"，可加一个 `related_categories`
  （按映射里该要求关联的评分点类别推导）；若不采纳会省掉。

**前端**（`assets/mode-outline.js` 为主，约 200–300 行改动）：
1. 顶部筛选条：删掉类别勾选，只留标包下拉 + 当前目录 + 生成按钮；
2. 新增**类别页签**（数据源：`package_points[].groups`），含 badge 与默认选中规则；
3. 指标：由"当前类别的 groups"计算（已有逻辑复用，把 `viewCats` 换成 `activeCat`）；
4. 内容分区：把现有 `points / tech / units / map / basis` 五个页签内容改为
   **一个类别页签内的分区**，并加"本类别未生成"空态；
5. 交互：切换类别 = 就地重渲染（复用现有 `switchView` 机制，改为 `panelViewCat`）。

**测试**：`tests/frontend/*.mjs` 增加"面板模板含类别页签且不再有 `data-vcat`"的静态断言；
CDP 验证见 §六。

## 六、验收标准（实施后逐条验证）

1. 顶部筛选**只有标包**（无类别勾选）；
2. 类别页签数量 = 该标包**实际解析到的**类别数（当前数据：标包1=商务、标包2=技术+商务、标包3=商务），badge 显示"n 个 · m 分"；
3. 切类别：指标与内容**原地**变化，页签不跳转；
4. 「商务」页签**不出现**技术要求表；「技术」页签出现（含来源文件列）；
5. 未生成的类别：产物区显示 `—` + 空态文案 + 生成按钮；点击后能生成该类别目录；
6. 切换标包：类别页签重建、默认选中分值最高类别；
7. 评分口径仍**完整展示**（无 `…` 截断）；
8. `__bootErrors = []`；后端 748 passed / 前端 101 passed 全绿。
