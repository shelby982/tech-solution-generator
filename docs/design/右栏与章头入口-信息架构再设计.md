# 右栏「计划」页签 + 章头按钮 · 信息架构再设计

> 对象：用户红框标出的两块 —— ① 章头「本章编写计划」按钮 ② 右栏「计划」页签整列。
> 结论先行：**"计划"现在同时扮演了三个角色（动作 / 状态 / 参考），所以怎么摆都乱。**
> 正确做法是按角色拆开，而不是继续在这两块里挪内容。

---

## 一、先看清："计划"在这两块里承担了三个角色

| 角色 | 具体内容 | 本质 | 现在放哪 |
|---|---|---|---|
| ① **动作** | 打开本章计划面板 | 一次性动作 | 章头按钮 + 右栏按钮（重复）|
| ② **状态** | 评分点 X/Y 已落点、待办 N 项 | 一个数字 | 右栏卡片（和依据块重复）|
| ③ **参考** | 评分点原文、招标条款、写法要点 | 只读资料 | 右栏「依据」「写法」两块 |

**同一个词被用在三种性质完全不同的东西上** —— 用户"乱"的感受就来自这里：
点开右栏以为要看状态，结果看到一堆只读资料；想找入口，章头和右栏各有一个。

|---|---|---|
| 1 | **动作重复** | 章头按钮「本章编写计划」+ 右栏「打开本章计划」 |

| 6 | **建议噪声** | 「无已核对素材：可先写…」是一句临时建议，混在参考区里 |

## 三、更优的信息架构

### 核心原则：按"**动作 / 参考 / 结果**"三分，一个概念只出现一次

```
┌──────────────────────────────────────────────────────────────┐
│ 章头（动作区）                                                │
│ 项目背景现状目标   草稿    25.5 / 12 页                       │
│ [本章计划 ·待办3]  [AI 编制本章]  [保存] [编辑|预览] …        │
│   ↑ 唯一入口，带待办角标                                       │
└──────────────────────────────────────────────────────────────┘

┌──────────────┬───────────────────────────┬───────────────────┐
│ 左树（结构） │ 正文（编辑器）             │ 右栏（参考区 · 三视图）│
│              │                           │ 依据 │ 素材池 │ 进度 │
│              │                           │                   │
│              │                           │ 依据 = 评分点/条款/原文 │
│              │                           │ 素材池 = 我方/外部来源  │
│              │                           │ 进度 = 字数/篇幅/生成记录│
└──────────────┴───────────────────────────┴───────────────────┘
```

**三个页签的语义边界（互斥、完整）**
| 页签 | 回答的问题 | 内容 | 有动作吗 |
|---|---|---|---|
| **依据** | 凭什么这么写 | 评分点（含原文）、招标条款、本章原文段落 | 无（纯查阅）|
| **素材池** | 用什么写 | 我方材料、外部来源（含片段）、添加/上传 | 有（素材操作）|
| **进度** | 写到哪了 | 篇幅（计划/已写）、生成记录、章节状态 | 无（纯查看）|

**「计划」不再是页签** —— 它只作为**动作**存在于章头按钮。
理由：计划面板的内容已经按性质分流了 ——
- 状态（待办 N、评分点落点）→ 变成按钮角标 + 进度页签
- 参考（评分点原文、条款、写法）→ 归「依据」
- 动作（改要求、找素材、重新生成）→ 归章头按钮打开的面板

### 章头按钮的改进（唯一入口）

| 项 | 现在 | 建议 |
|---|---|---|
| 文案 | 本章编写计划 | **本章计划**（更短，动作更明确）|
| 角标 | 无 | **待办 N**（红色小角标）；0 时不显示 |
| 位置 | 章头右侧 | 不变（紧邻 AI 编制本章，符合"先看计划再生成"的顺序）|

### 「章节类型」与那句建议的归属

| 内容 | 本质 | 归位 |
|---|---|---|
| 章节类型（项目理解/技术方案…）| **生成输入** | 移到**章计划面板的「写法」块**（它决定骨架/表图/提示词）|
| 「无已核对素材：可先写…」| 临时建议 | 并入章计划面板的**待办**（或直接删除）|

---

## 四、为什么这个划分更优（论证）

1. **一个概念一个位置**：计划=动作（章头）、依据=参考、素材=可用资源、进度=结果。
   用户在任何时刻只需要判断"我现在要动作、要参考、还是要看结果"。✅
2. **页签语义互斥**：现在"计划"页签 = 依据 + 写法 + 类型 + 建议（杂）；改后三页签回答三个不同问题，
   不会出现"打开计划看到的是依据"这种困惑。✅
3. **状态只有一个出口**：待办数 → 章头角标；篇幅 → 进度页签；全局 → 进度中心。
   不再出现"两个 0/4"这种同数不同口径。✅
4. **动作与内容分离**：右栏变成**纯参考区**（只有一个页签有操作 = 素材池），
   动作全部收敛到章头工具条 + 计划面板，符合"信息左、动作右/上"的既有约定。✅
5. **减少一次点击**：现在是"右栏计划页签 → 打开本章计划"两步；改后章头一次直达。✅

## 五、迁移映射（现在的内容去哪）

| 现在的位置 | 内容 | 去向 |
|---|---|---|
| 章头按钮「本章编写计划」 | 动作 | 改文案为「本章计划」+ 待办角标（唯一入口）|
| 右栏「计划」页签 · 卡片 | 评分点落点 | 章头角标 + 进度页签（不单独显示）|
| 右栏「计划」页签 · 依据块 | 评分点原文 / 条款 / 原文段落 | **依据页签**（内容不变）|
| 右栏「计划」页签 · 写法块 | 规范版本 + 查看规范 | 依据页签底部 或 计划面板「写法」|
| 右栏「计划」页签 · 编排建议/章节类型 | 生成输入 | **计划面板「写法」块** |
| 右栏「计划」页签 · 那句建议 | 临时建议 | 删除（其含义已在待办里）|

**改动量**：右栏相当于把「计划」页签的内容并入「依据」，再删掉一个页签 —— 中等偏小的改动
（不新增后端接口，现有字段都够）。

## 六、可选的方案 B（供对比）

**方案 B：右栏不做页签，改成一条竖流**（依据 → 素材 → 进度，依次排列 + 折叠）。
- 优点：不用切换，滚动即可；更少点击。
- 缺点：右栏高度被三个块挤满，编写时"依据"可能被挤出首屏；页面更喧闹。
- 结论：**不推荐**（编写时右栏是并排参考，空间本就紧张）。
