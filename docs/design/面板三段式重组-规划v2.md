# 拆解面板 · 三段式重组（v2 规划）

> 用户口径（原话）：
> - 上面筛选部分只保留标包或标的名称；
> - 技术与商务的评分点本就在下面的拆解部分 → 做成两个页签（商务 / 技术），结构更清晰；
> - **当前结构**：(a) 评分点：包含"商务"和"技术"两类；(b) 技术规范书拆解：与"评分点"并列；
> - **待确认与产物的逻辑**：目前"两个产物"和"待确认"的内容在这一步（拆解）是没有意义的。
>   必须等商务和技术的评分点、以及技术规范书的拆分完成，并且根据待确认的内容确认完成后，
>   才会有对应的两个产物；
> - **产物定义**：(a) 对应的目录；(b) 最终的技术与评分点映射矩阵。
> - 覆盖率目前不涉及（等最终确认完成之后才有意义），模块已删除。

---

## 一、三段式结构（本方案的核心）

```
┌ 筛选（只留标包）────────────────────────────────────────────────────────────┐
│ 标包 [标的1 / 标包2 · 高可靠技术专题研究与验证标包 ▾]                          │
│                                            [拆解评分点 / 重新拆解]              │
└────────────────────────────────────────────────────────────────────────────┘
┌ 阶段指示：① 拆解  ──▶  ② 待确认  ──▶  ③ 产物        （未到达的阶段置灰）      ┐
└────────────────────────────────────────────────────────────────────────────┘

══ ① 拆解（三个并列页签，都是"输入/依据"，本步只做这件事）══
   [ 商务评分点 13 ]   [ 技术评分点 8 ]   [ 技术规范书拆解 153 ]
     · 商务/技术评分点 = 来自**招标文件**的评分表，按类别分列
       （分值、评分因素、详细评审项、**完整评分口径**）
     · 技术规范书拆解 = 来自**技术规范书**的要求条目
       （按主题分组、标来源文件、按标包归属）
   ⚠️ 这一步**不出现**目录、映射矩阵、覆盖率

══ ② 待确认（三个块都拆完才出现；内容是本步真正需要用户决定的）══
   · 投标范围（标包）确认
   · 要生成哪些类别（商务 / 技术）—— 决定产物的范围
   · 技术规范书主题归属（下拉选章节，可选）
   · 分值合计自检（合计 ≠ 100 时提示）
   [ 确认，进入生成 ]        ← 确认是这个门

══ ③ 产物（**确认完成后**才出现）══
   [ 目录 ]   [ 技术与评分点映射矩阵 ]
     · 目录 = 该标包 × 所选类别的应答目录（可在此看章节树）
     · 技术与评分点映射矩阵 = 最终映射（评分点 ↔ 技术要求 ↔ 章节）
     · 覆盖率自检**在这一层**（有目录之后才有意义），作为「目录」页里的自检信息
```

## 二、门控规则（关键，避免"没意义的产物"）

| 条件 | 拆解页签 | 待确认页签 | 产物页签 |
|---|---|---|---|
| 刚上传、还没拆解 | 显示（空态 + 引导拆解） | 不显示 | 不显示 |
| 拆解中 | 显示（进度） | 不显示 | 不显示 |
| 三块都拆完，未确认 | 显示 | **显示**（可作答/确认） | 不显示（或禁用 + 说明"确认后生成"） |
| 已确认、未生成 | 显示 | 显示（已确认） | 显示（空态 + [生成产物]） |
| 已生成 | 显示 | 显示 | **显示内容**：目录 / 映射矩阵 |

判断依据（已有数据即可判定，无需新表）：
- "三块都拆完" = 该运行的评分点（商务、技术）与技术要求都已落库且有内容；
- "已确认" = 运行级作答里有 `categories`（要生成哪些类别）与范围确认；
- "已生成" = 该运行的目录（blocks）已派生（`outline_pending` 为假）。

## 三、页签与内容映射（前端改动点）

| 新页签 | 数据来源（已具备） | 说明 |
|---|---|---|
| 商务评分点 | `package_points[标包].groups[commerce]` | 来自招标文件；评分口径完整展示 |
| 技术评分点 | `package_points[标包].groups[tech]` | 同上 |
| 技术规范书拆解 | `tech_matrix.topics`（含 `source_files`/`package_no`） | 来自技术规范书；按标包归属 |
| 待确认 | `confirmations` + `answers` + `project_scope` | 范围/类别/主题归属；守门 |
| 目录 | 生成后的 `toc`/blocks | 产物 |
| 技术与评分点映射矩阵 | `mapping.point_to_requirement` | 产物 |

页签可见性由 §二 的门控决定；**评分点与要求都是"依据"**，目录与映射是"产物"。

## 四、与现状的差异（要改什么）

1. **页签结构**：现在的 `依据·招标文件评分点 / 依据·技术规范书要求 / 产物·目录骨架 / 产物·映射矩阵 / 待确认`
   → 改为 `商务评分点 / 技术评分点 / 技术规范书拆解 / 待确认 / 目录 / 技术与评分点映射矩阵`，
   并按门控显隐（产物在确认前不出现）。
2. **顶部筛选**：只留标包（类别勾选移除——类别由"待确认"里的选择承担，评分点按类别分页签展示）。
3. **指标条**：随所选页签变化；确认前不显示产物类指标（目录骨架/映射），
   改为显示拆解类（商务 n 个 / 技术 n 个 / 技术要求 n 条）。
4. **门控**：新增"确认"这一关（复用现有 `answerSplit(key='categories'|'scope'|'structure')`），
   确认后自动触发一次生成；产物页签随之出现。
5. 覆盖率**不进**拆解层（已删除）；将来作为「目录」页里的自检信息出现。

## 五、验收标准（实施后逐条验证）

1. 顶部筛选只有标包；页签为「商务评分点 / 技术评分点 / 技术规范书拆解」+（门控后）待确认与产物；
2. 拆解阶段**看不到**目录、映射矩阵、覆盖率；
3. 三块未拆完时，待确认页签不显示（或显示"等拆解完成"的置灰态）；
4. 待确认里能选标包 + 类别（商务/技术）+ 主题归属；确认后触发生成；
5. 确认前"目录/映射矩阵"页签不存在或为禁用态；**确认并生成后**两者出现且有内容；
6. 商务评分点 / 技术评分点各自独立成页，评分口径完整展示（无截断）；
7. 技术规范书拆解页显示主题分组的完整要求，含来源文件；
8. 切换标包：页签内容随之重建；未拆解的标包显示空态 + 引导；
9. `__bootErrors = []`；后端 748 passed / 前端 102 passed 全绿。

## 六、待你确认的两点

| # | 决策 | 我的建议 | 备选 |
|---|---|---|---|
| 1 | 「待确认」是**独立页签**还是**折叠区** | 独立页签（它是守门的一步，需要显式动作） | 放在拆解页签下方作为折叠区 |
| 2 | 确认后**自动生成**还是**再点一次生成** | 确认即生成（少一次点击；生成中显示进度） | 确认后出现 [生成产物] 按钮，由用户点 |
