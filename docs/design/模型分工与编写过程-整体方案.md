# 模型分工如何嵌入编写过程 —— 整体方案

> 目标：让"模型分工"不再是孤立的高级设置，而是**编写链路的配置层**——
> 章级编写、节级改写、文字与图片生成，每一步都用对角色、可被用户覆盖、可追溯可回退。
> 本篇只做**整体设计**，不含实现细节。

---

## 一、结论先行

**把编写过程拆成 6 个动作、4 类角色 + 2 类审校，用一张「阶段 × 角色」矩阵驱动；用户只在两个地方配置，其他全部按默认走。**

| 动作 | 默认角色 | 用户可覆盖什么 |
|---|---|---|
| 生成大纲 | 章节主编 chief | 换模型 |
| 写一节正文 | 正文 text | 换模型 |
| 生成表格 | 表格 table | 换模型 |
| 生成图示 | 图示 diagram | 换模型 |
| 技术审校（可选）| 王安石 wang_anshi | 开关 + 换模型 |
| 合规审校（可选）| 包拯 bao_zheng | 开关 + 换模型 |

用户实际只看到一张表：**「这个角色用哪个模型」**，以及**「哪些审校要开」**。

---

## 二、现状：角色有，链路断了

| 环节 | 现在的实现 | 问题 |
|---|---|---|
| 角色定义 | `chief / text / table / diagram / wang_anshi / bao_zheng` 六个 | 定义齐全 |
| 旧的多 Agent 编制 | `/api/chapters/{id}/write` 接受 `models{...}` 按角色指定模型 | **保留但已被新链路取代** |
| 新大纲生成 | `call_role('chief', …, settings={})` | **不读用户分工**，走默认/轮询 |
| 新表格生成 | `call_role('table', …, settings={})` | 同上 |
| 新图示生成 | `call_role('diagram', …, settings={})` | 同上 |
| **新分节编写（流式）** | 直接 `stream_openai/stream_claude` | **完全没有角色概念**，也没读分工 |
| 审校 | 只存在于旧流程 | 新链路**未接入** |
| 分工入口 | 原在"本章编制进度"区块（已删除）| 现在**没有入口** |

**一句话**：角色齐全，但新编写链路是"裸调模型"，分工没有落点，用户想配也配不了。

---

## 三、设计原则

1. **角色只描述"干什么"，不描述"用哪个模型"** —— 模型是配置，角色是契约。
2. **每个动作只有一个负责人**（避免"这段谁写的"说不清）。
3. **默认能用，覆盖可控** —— 不配也能跑；配了立刻生效、当次即用。
4. **文字与图片同源** —— 图必须由**本节正文**驱动，不允许凭空生成。
5. **改写不破坏已确认的产物**（图表、引用、标题结构）。
6. **每一步都留痕** —— 谁写的、用的哪个模型、多久、花了多少。

---

## 四、角色职责矩阵（核心）

| 阶段 | 动作 | 角色 | 产物 | 是否必选 | 失败时 |
|---|---|---|---|---|---|
| 1 | 生成/重做章节大纲 | chief | 节列表 + 每节三问（依据/写法/交付物）| 必选 | 保留旧大纲 |
| 2 | 写一节正文 | text | 该节 Markdown（含表/图块）| 必选 | 保留原节内容 |
| 2b | 生成本节表格 | table | 表格 Markdown + 表名 | 按交付物 | 标记"表待补" |
| 2c | 生成本节图示 | diagram | `:::diagram` 块 | 按交付物 | 标记"图待补" |
| 3 | 技术审校（可选）| wang_anshi | 问题清单（不改正文）| 可选 | 跳过并提示 |
| 4 | 合规审校（可选）| bao_zheng | 问题清单（不改正文）| 可选 | 跳过并提示 |
| 5 | 改写一节 | text（可"改写专用模型"）| 新节内容 + 差异 | 按需 | 保留原文 |
| 6 | 图调整 | diagram | 新图块 | 按需 | 保留原图 |

**关键约定**
- `text` 同时承担"编写"和"改写"，但允许**分别配置模型**（改写通常想用更强的模型）。
- table / diagram **可以独立于 text 配置**（例如文字用便宜模型、图用强模型）。
- 审校**只产出意见，不改正文**（避免"悄悄改掉用户确认的内容"）。

## 五、编写过程的完整链路

### 5.1 章级：整章编写（6 步）

```
① 计划            chief  →  大纲（每节：依据/写法/交付物）
② 分节循环        text   →  逐节写正文（流式，正文内高亮）
   ②b 每节按需    table  →  表格
   ②c 每节按需    diagram→  图示（由图位置+本节正文驱动）
③ 对齐校验        规则   →  标题与大纲一致、图表齐不齐、字数够不够
④ 审校（可选）    wang_anshi / bao_zheng → 意见进待办
⑤ 人审            用户   →  改 / 重写某节 / 配图
⑥ 定稿            规则   →  补表名、图注、页码
```

**分工要点**
- ② 是**逐节串行**（保证上下文一致、可中断）；②b/②c 在同一节内**可以并行**（文章写到该节时，图表同时生成）。
- ③ 的"缺口"直接落进进度面板（图待补 / 表待修 / 依据核对），**不自动重写**。
- ④ 默认关（见第七节"成本"）。

### 5.2 节级：改写（5 步）

```
① 触发   用户点「重写」→ 弹提示词面板（写方向）
② 快照   备份本节原文（可回滚）+ 抽出本节已有图表（保图）
③ 改写   text（或"改写专用模型"）→ 依据 + 写法 + 交付物 + 用户提示词
④ 合并   新正文 + 保留下来的图表块 + 表名
⑤ 复核   与原文差异提示（字数变化/删了什么）+ 进版本
```

**改写场景的分工差异**

| 场景 | 走哪个角色 | 特别处理 |
|---|---|---|
| 整节重写（有提示词）| text / 改写模型 | 保图保表名；提示词优先于默认写法 |
| 整章补未写 | text（逐节）| 已有内容的节跳过 |
| 只改某一段 | text | 只替换该段，其余不动 |
| 换语气/压缩 | text | 不改结构与图表 |
| 图不对 | diagram | **只重生成图**，正文不动（反过来：文不对不自动改图）|

### 5.3 文字与图片的分工

**原则：图由文生，图不编数字。**

| 环节 | 谁做 | 输入 | 约束 |
|---|---|---|---|
| 图位规划 | chief（大纲阶段）| 节三问的交付物 | 每节最多 1~2 张图 |
| 图内容生成 | diagram | **本节正文** + 交付物里的图型 + 用户图提示词 | 节点 2~12；不出现正文没有的数字；图型按交付物 |
| 图审校 | wang_anshi（可选）| 本节正文 + 图块 | 检查图与文是否矛盾、节点是否遗漏 |
| 图调整 | diagram | 本节正文 + 调整提示词 + 图型 | 只换图，正文不动；原图进版本 |

**禁止**：diagram 角色凭空生成"看起来对"的数据图（曲线/占比）—— 趋势类图只能画**正文里明确给出的**阶段或对比项。

## 六、配置与入口

### 6.1 一张表搞定（改造后的"模型分工"）

```
编写设置
┌───────────────────────────────────────────────┐
│ 角色           模型                   用途      │
│ 章节主编       [deepseek-v4-pro ▾]    大纲/结构  │
│ 正文编写       [deepseek-flash  ▾]    写节      │
│ 正文改写       [同正文 ▾]             重写节    │
│ 表格           [deepseek-flash  ▾]    表格      │
│ 图示           [deepseek-v4-pro ▾]    信息图     │
│ ── 审校（默认关）────────────────────────────── │
│ 技术审校       [关 ▾]                 意见      │
│ 合规审校       [关 ▾]                 意见      │
└───────────────────────────────────────────────┘
估算：本章 8 节约 10 次调用 ≈ ¥X
```

- 入口：章头「更多 → 编写设置」（替代被删掉的旧入口）
- 作用域：**项目级默认** + 本章可覆盖
- 即时生效：下一次生成就用新配置（无需重建大纲）
- 只列"有模型的角色"，没配的角色自动回退默认

### 6.2 配置在链路里怎么传

- 前端每次请求带上 `settings{role: model}`（大纲/节/表/图各一处）
- 后端 `call_role(role, …, settings)` 已支持按角色选模型 → **新链路补齐"读 settings"即可**
- 分节流式接口新增 `role` 参数（默认 text）+ `settings`

## 七、成本、并发与降级

| 项 | 策略 |
|---|---|
| 调用次数 | 章级约 `1 + N节 + 图表数 + 审校×N`，设置面板里**实时估算** |
| 并发 | 分节串行；同节内图表可并行（上限 3，沿用 `MODEL_LIMIT`）|
| 审校默认 | **关**（成本翻倍），需要时手动开或对重点章开 |
| 模型不可用 | 自动回退到默认模型，并在状态条提示"已回退" |
| 超时/中断 | **保留原文**，只提示失败，不落半截 |
| 长章 | 一节一节跑，随时可停；已完成的节保留 |

## 八、记录与可追溯

每一节记录：

```json
{
  "section": "政策要求与项目对应关系",
  "role": "text",
  "model": "deepseek-flash",
  "tokens": 3210,
  "duration_ms": 18400,
  "prompt": "语气更务实…",
  "action": "rewrite",
  "revision_id": 1234
}
```

- 进度面板节行 hover 显示「由 deepseek-flash 生成 · 18s · 有提示词」
- 每次改写/重生成都写 `block_revisions`（含模型与提示词），**可回滚**
- 导出时可选在文档属性里写"编写工具/模型"（内部留痕，不体现在正文）

## 九、审校怎么接入（不打断写）

| 时机 | 行为 |
|---|---|
| 手动 | 章头「更多 → 技术审校/合规审校」→ 出意见 → 进待办 |
| 自动（可选）| 整章写完后跑一次，**只出意见** |
| 意见形态 | 位置 + 问题 + 建议 + [去修改]/[忽略] |
| 不做 | **不自动改正文**；不重复报同一条（去重）；忽略过的记住 |

## 十、验收标准

1. 编写设置面板可配置 7 个角色（含"正文改写"独立于"正文编写"）
2. 改配置后**下一次**生成即生效（大纲/节/表/图分别验证）
3. 分节流式编写按 `text`（或改写模型）选模型，不再"裸调默认"
4. 表/图分别走 table/diagram 角色，可独立配模型
5. 改写时图表被保留（不被删），表名保留
6. 每节记录 model/tokens/时长，进度面板可见，可回滚
7. 模型不可用 → 自动回退 + 明确提示；中断不落半截
8. 设置面板显示本次估算调用次数
9. 审校默认关，开启后只出意见不改正文
10. 无控制台错误

## 十一、实施拆分

| 步骤 | 内容 | 依赖 |
|---|---|---|
| S1 | 后端：新链路统一走 `call_role(role, …, settings)`（大纲/节/表/图），分节流式接口加 `role`+`settings` | — |
| S2 | 前端：请求带上 `settings`；项目级默认存 settings 表 | S1 |
| S3 | 「更多 → 编写设置」面板（7 行 + 估算 + 即时生效）| S1/S2 |
| S4 | 记录：节级 model/tokens/时长写 revision；进度面板显示 | S1 |
| S5 | 改写专用模型（text 拆 write/rewrite 两个 key）+ 保图校验 | S3/S4 |
| S6 | 审校接入（手动优先，自动可选）+ 意见进待办 | S1 |

## 十二、待确认（3 个决策点）

1. **改写是否单独配模型**？（我建议单独，改写更吃模型能力）
2. **审校默认开还是关**？（我建议关；重点章手动开）
3. **模型配置的作用域**：项目级默认 + 章节覆盖，还是全局一套？（我建议项目级默认 + 章节可覆盖）
