# 信息图生成太单一：诊断与优化手段

> 现象：不管内容是什么，生成结果都是**一列竖排方框 + 向下箭头**。
> 结论：这不是渲染问题，是**四层同构**（数据模型 / 提示词 / 渲染 / 导出都只支持线性链）。

---

## 一、为什么只有一种形态（四层都锁死了）

| 层 | 现状 | 后果 |
|---|---|---|
| **数据模型** | 模型只返回 `{"nodes": ["A","B","C"]}` | 只能表达**顺序**，无法表达层级、分支、并列、时间、对比 |
| **提示词** | "把文字抽成 3~8 个节点" | 无论原文是分层架构还是并列要点，都被**压成一条链** |
| **应用内渲染** | 一个模板：竖排框 + `↓` | 5 个节点排 5 行，页面上占半屏，信息密度低 |
| **导出（Word）** | `diagrams.py` 同样是竖排框 + 箭头 | 印在标书里是"一条竖线"，不像图，像大纲 |

一句话：**内容有结构，但管道只认"顺序"。**

---

## 二、优化手段（按投入产出排序）

### 手段 1｜数据模型从"链"升级为"图"（根因，必做）

```json
{
  "type": "layered | flow | tree | timeline | matrix | cycle",
  "title": "项目理解逻辑框架",
  "nodes": [{"id": "n1", "label": "南方电网业务分布总览", "level": 0, "group": "业务域"}],
  "edges": [{"from": "n1", "to": "n2", "label": "下钻"}],
  "note": "数据来源：招标文件第二章"
}
```

- `level` → 支持**分层**
- `edges` → 支持**分支/合并/跨层**
- `type` → 决定渲染模板
- 兼容旧格式：只有 `nodes` 数组时按 `type=flow` 渲染（存量图不坏）

### 手段 2｜提供 6 种基础图型（覆盖 90% 标书场景）

| 图型 | 适用内容 | 例 |
|---|---|---|
| **层次图（分带）** | 架构、体系、业务分层 | 接入层 / 服务层 / 数据层 |
| **流程图** | 步骤、链路、机制 | 采集 → 清洗 → 分析 → 展示 |
| **树形图** | 分类拆解、目录结构 | 业务板块 → 子业务 |
| **时间线** | 阶段、里程碑、演进 | 2024 试点 → 2025 推广 → 2026 全域 |
| **对比矩阵** | 现状 vs 目标、方案对比 | 2×2 / 三列对比 |
| **循环图** | 闭环、PDCA、反馈 | 监测 → 评估 → 优化 |

**高级（P2）**：鱼骨图（问题归因）、泳道图（多角色协作）。

### 手段 3｜结构自动识别 + 用户可覆盖

- 模型先判断原文结构：**并列 / 顺序 / 层级 / 因果 / 对比 / 时间**
- 自动选图型（并列→树形，顺序→流程，层级→层次图…）
- 生成面板给一个「图型」下拉：**自动（推荐）/ 层次 / 流程 / 树形 / 时间线 / 对比 / 循环**
- 生成后仍可「换图型重新生成」——不重写提示词，只换模板

### 手段 4｜版式自适应（解决"一列太浪费"）

| 节点数 | 版式 |
|---|---|
| ≤4 | 单列/单行 |
| 5–8 | **两列或分带**（同一层放一行） |
| 9–12 | 分组（按 group 分带）+ 组内横排 |
| >12 | 提示"建议拆成两张图" |

+ **横竖切换**（时间线默认横向，流程默认横向，层次图纵向）

### 手段 5｜视觉语义（让图"有信息"而不只是"有形状"）

- **层级色阶**：第 1 层深蓝、第 2 层中蓝、第 3 层浅蓝（一眼看出主次）
- **关键节点高亮**：与评分点/交付物直接相关的节点加主色描边
- **连接线语义**：主链路粗实线、次链路细线、间接影响虚线
- **图注与编号**：`图 1-1 项目理解逻辑框架` + 「数据来源：招标文件第 X 章」
- **同层对齐**：同层节点等宽、基线对齐（现在的竖排做不到）

### 手段 6｜生成后可轻编辑（不靠手改 markdown）

- 换图型 → 重新生成（保留节点文案）
- **增删/改节点**：一个简单表单（每行一个节点 + 缩进表示层级）
- 层级调整：节点前的 `-`/`--` 表示层级
- 存回正文仍是文本语法（可审、可 diff、导出可复现）

### 手段 7｜导出升级（标书里要像"图"）

- `infra/docx/diagrams.py` 按 `type` 渲染 PNG：层次=分带、流程=横排、时间线=横轴
- 分辨率按 A4 正文宽度（≥300dpi）
- 自动编号"图 X-Y" + 图注 + 来源行
- 与**图表计划**（`figures_plan`）联动：计划里要求的图，导出时检查是否真有

## 三、优先级（PM 视角）

| 优先级 | 内容 | 为什么排前面 | 工作量 |
|---|---|---|---|
| **P0-1** | 数据模型升级 + 兼容旧格式 | 不改模型，其他优化都白做 | 中 |
| **P0-2** | 图型：层次 / 流程 / 时间线 + 自动识别 | 覆盖标书 80% 场景（架构/机制/演进）| 中 |
| **P0-3** | 应用内渲染 + 导出 PNG 按图型切换 | 用户看到的第一眼 | 中 |
| **P1** | 树形 / 对比矩阵 + 版式自适应（两列/分带）| 解决"一列太长" | 中 |
| **P1** | 视觉语义（色阶/高亮/线型/编号）| 让它像标书里的图 | 小 |
| **P2** | 鱼骨 / 泳道 + 节点轻编辑 + 多图管理 | 锦上添花 | 大 |

## 五、验收标准

1. 同一段文字，选不同图型能得到**明显不同**的图（层次/流程/时间线）
2. 选「自动」时，含"层/架构/体系"的文本 → 层次图；含"先…再…"→ 流程图；含年份 → 时间线
3. 5–8 个节点不再排成一长列（自适应两列/分带）
4. 导出 Word 里的图与页面预览**形态一致**，且带「图 X-Y」编号与来源行
5. 旧正文里的 `:::diagram A -> B -> C` 仍能正常显示与导出（向后兼容）

---

## 六、我建议先做哪一步

**P0-1 + P0-2 + P0-3**（数据模型 + 三种图型 + 渲染/导出切换）一次做完，
这样你下次生成就能直接看到"层次图/流程图/时间线"，而不是一条竖线；
树形/矩阵/视觉语义放下一轮。
