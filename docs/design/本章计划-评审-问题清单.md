# 「本章编写计划」评审：问题清单与修复建议

> 依据：当前界面实测截图 + 数据核对（p29 / 标包 559 / 技术草案 / s1.2.1.1 项目背景现状目标）。
> 结论：**六段结构是对的，但内容归属、一致性、以及"是不是这一章的要求"三点没做到位。**

---

## 一、最严重的 3 个（不修等于白做）

### P1｜要求是"模板通用"的，不是这一章真正的要求

截图里的三条要求：
```
[文字] 政策依据与项目背景结论
[表格] 政策依据映射表（文件/要求/对应工作）
[图示] 趋势或现状对比图
```
这三条来自「8 类章名模板」，是**任何投标文件这一章都这么写**的通用套路。但本项目是
**"高可靠技术专题研究与验证"**——它的「对项目的理解」真正该写的是"业务连续性与可靠性现状、
以往故障与影响、可靠性缺口、验证诉求"之类，而不是泛泛的"政策依据"。

**后果**：用户一看就觉得"这不是文件里要的"，然后放弃这个面板 → 整个"计划为中心"的设计失效。

**修法（对应修订方案 P2）**：要求**必须优先从"评分点要素"生成**
```
① 评分点 criterion 拆分出的分项要素  → 直接变成要求（带依据）
② 技术规范条款（强制性/★ 优先）
③ 8 类模板（兜底，保证结构完整）
```
每条要求标注来源（`from: point/clause/template`），用户能看出"这条是招标文件要的 / 这条是兜底补的"。

### P2｜C 段的建议表图和 E 段的图表计划直接打架

- C 段「建议表格」列了 **6 张表**（政策依据映射表／现状维度表／目标指标表／纳入-不纳入表／交付物清单／难点表+对策表）
- C 段「建议图示」列了 **4 张图**
- 但 E 段说本章**只有 2 表 1 图**

**后果**：用户不知道"到底要出几张"。而且这 6 表 4 图是**整个模块（8 章）**的清单，
其中"范围与内容/纳入-不纳入/交付物清单/难点-对策"根本不属于"项目背景现状目标"这一章。

**修法**：
- C 段只保留**与本章相关**的骨架与写法要点（按章名匹配，已有一版相关性逻辑可复用）
- 表图清单**只在 E 段出现一次**，C 段不重复列
- C 段改为"写法要点"：叙事顺序 + 3 条易失分 + 1 条量化要求（其余折叠）

### P3｜"计划"里混进了"验收结果"，且自相矛盾

面板顶部同时出现：
```
[本章计划已确认] [计划在正文之后有更新] [未达完成]
未达完成：1 条要求正文未回应；3 条要求素材未满足；4 条待修问题
```
同时最上方还有黄条：**「《对项目的理解》的编写计划还未确认（共 7 节）」**

**后果**：同一屏里"本章计划已确认"和"目录计划还未确认"并列 → 用户直接困惑。
而且"未达完成/4 条待修"是**验收结果**，不该占据"计划"面板的顶部。

**修法**：
- 计划面板顶部只保留：`本章计划：已确认/未确认` + `计划 N 页 · 要求 M 条 · 素材待补 K`（一行）
- 「未达完成 + 原因」移到**面板底部折叠区「验收状态」**（或直接放右栏"编制进度"）
- 「计划在正文之后有更新」+ 动作按钮「按新计划重新生成」（不能只是提示）
- 黄条（目录计划未确认）与面板的章级确认**合并成一句**：
  `本章计划未确认（所属《对项目的理解》计划式共 7 节未确认）`，只在一个地方出现

## 二、一致性 bug（真错，要立刻修）

### P4｜右栏"要求 1/1"与面板"要求 3 条（已回应 2）"数字不一致

右栏「本章编写计划 · **要求 1/1 条已落点**」——这个 1/1 是**评分点**数（`review_point_ids` 只有 1 个），
不是"要求"数（3 条）。**标签写错了**，用户会以为右栏和面板是两套数。

**修法**：右栏改为 `评分点 1/1 已落点`，并单独一行 `要求 3 条（已回应 2）`；或者右栏只留"打开本章计划"，
不重复数字。

### P5｜A 段与 D 段重复「素材待补」

A 段每条要求下面已经有「素材待补」，D 段又完整列一遍三条「待补 / 尚未绑定片段」。
同一个状态出现两次，且两处都不能直接操作（A 只有"选片段"，D 什么都没有）。

**修法**：
- **A 段只回答"要写什么"**：要求文字 + 类型 + 依据 + 正文回应状态
- **D 段只回答"素材"**：需求 + 三档状态 + `找素材 / 选片段` 动作（A 段不标素材状态）
- 这样 A/D 不重复，各自有分工

### P6｜三条要求的"依据"完全相同，等于没信息

三条都显示「依据：对项目的理解正确、深入、全面」。因为依据是**本章继承的评分点**（只有 1 个），
三条要求共享同一个依据 → 每条都显示它，等于噪音。

**修法**：
- 若依据是"本章共享"，就在**章级显示一次**（顶部一行：`依据：对项目的理解正确、深入、全面（10 分）`）
- 每条要求只在**有独立依据**时显示（来自评分点分项要素/条款）

## 三、效率与体验（影响日常使用）

### P7｜六段全展开，"还差什么"要滚动才看得到
A/B/C/D/E/F 六段默认全展开 → 一屏放不下 → 最高频的 F（还差什么）被挤到最下面。

**修法**：A 与 F 默认展开；B/C/D/E 默认折叠（标题行带摘要，如 `D 素材 3 条待补`）。

### P8｜B 段三种信息挤一行，且"页数"没有答案
`计划 — 页 · 正文已写 25.5 页（6382 字）（篇幅在「应答策划」分配；"已写"以进度为准）本章尚未分到页数，可到「应答策划」调整篇幅分配。`
一句话里塞了「计划页数（空）/ 已写页数 / 两条说明」。

**修法**：
- 主信息一行：`计划 12 页 · 已写 25.5 页` + 超额时红字 `超 13.5 页`
- 没有分配页数时：`本章未分到页数 [去分配]`（一个按钮，不是一句说明）
- 「已写以进度为准」这类解释性文字收进 `ⓘ`

### P9｜D 段没有动作
D 段三条素材需求都是「尚未绑定片段」，但**没有任何操作入口**（要回到 A 段点"选片段"，或去素材池）。

**修法**：D 每条右侧给 `[找素材]`（打开官方来源抽屉）`[选片段]`（绑定）。

### P10｜没有"未达完成也能生成"的说明
底部只有「AI 编制本章」。用户看到"未达完成：4 条待修"会以为**不能生成**。

**修法**：按钮旁一行小字：`未达完成也可生成（正文会写【待补充】），修复后可重新生成`。

### P11｜C 段的「查看/修改写作规范」是**全局**的，没提示
点开会改「项目理解」这个模块的配方 → **影响所有同类型章节**，但界面没有任何提示。

**修法**：按钮改 `查看写作规范（全局，影响所有理解类章节）`，或在抽屉里顶部提示"这是模块级规范，改动影响 N 章"。

### P12｜类型徽标语义不清（文字/表格/图示）
`[表格] 政策依据映射表` 容易被读成"这条要求用表格写"，实际是"这条要求要**产出一张表**"。

**修法**：徽标改为 `产出·表` / `产出·图` / `写作` / `素材`。

### P13｜缺少"与同目录其他章的关系"
「项目背景现状目标」与「建设范围」「建设内容」「项目重难点」几章内容高度相邻，
计划里没有任何"避免重复"的提示（父章/子节、相邻章之间）。

**修法**：D/C 段加一句"相邻章节：建设范围、建设内容（注意不要重复展开）"，或验收项里加"与相邻章重复度"检查（后置）。

## 四、修复批次建议

| 批次 | 内容 | 价值 |
|---|---|---|
| **R1（立刻，纯前端/展示层）** | P3 顶部整理 + P4 数字修正 + P5 A/D 去重 + P7 折叠策略 + P8 篇幅行重排 + P9 D 段动作 + P10 生成说明 + P12 徽标 | 面板立刻从"看不懂"变"能用" |
| **R2（前端 + 小后端）** | P1 要求改由"评分点要素"生成（优先级：要素 → 条款 → 模板）+ 每条标来源 | 解决"要求不是这一章的"——最关键 |
| **R3（前端）** | P2 C 段只留与本章相关的写法要点 + 表图只在 E 段 | 消除 C/E 打架 |
| **R4（后置）** | P6 依据章级展示 + P11 全局规范提示 + P13 相邻章提示 | 减少误导 |

**顺序建议**：先 R1（当天见效）→ R3（自洽）→ R2（内容正确）→ R4。
