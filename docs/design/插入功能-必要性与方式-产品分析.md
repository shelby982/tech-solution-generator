# 插入文字 / 表格 / 图片 —— 必要性与插入方式（产品分析）

> 背景：编写页工具条的「插入 ▾」现在有 文字说明 / 手动表格 / 关系图。
> 本文回答两件事：**这些插入到底有没有必要**、**应该用什么方式插入**。
> 结论先行：
> 1. **必要性差别极大**：图片/表格/引用片段是刚需（AI 无法编造的真实材料），空白"文字说明"几乎无价值。
> 2. **现在的入口分错了维度**：按"内容类型"（文字/表格/图）分，而用户脑子里想的是"我要放一份**真实的东西**"。
> 3. 应改为**按来源分**：从素材插入 / 从官方来源插入 / 插入结构模板。

---

## 一、先问：为什么会有人"手动插入"？

如果 AI 能一次写对，就不需要插入。手动插入存在的唯一理由是：
**有些内容必须由人来提供，模型不能编、也编不对。**

| 内容 | AI 能写吗 | 必须人工插入吗 | 例子 |
|---|---|---|---|
| 我方业绩 / 案例 / 资质 | ✗ 编造风险极高 | **必须** | 近三年同类项目合同、验收报告、证书扫描件 |
| 真实参数 / 实测数据 | ✗ 编不出来 | **必须** | 系统吞吐、并发、响应时间实测值 |
| 官方文件的原文片段 | ✗ 易失真 | **必须（且要带来源）** | 政策/标准条文原文引用 |
| 通用论述、方案思路 | ✓ 能写 | 不需要 | 背景分析、技术路线 |
| 结构骨架（分点/对比表）| ✓ 能写 | 可选（提效） | 对比表、响应表框架 |

**这条划分决定了必要性矩阵** —— 插入的价值 = 这份内容 AI 能否可靠产出。

---

## 二、必要性矩阵（按插入类型）

| 插入类型 | 必要性 | 理由 | 建议 |
|---|---|---|---|
| **从素材插入图片** | ★★★★★ | 资质证书、系统截图、拓扑图、组织架构图，**AI 无法生成真实图片**；且这些是评分点的硬证据 | **P0 必做**（现在只能从素材卡片里找，入口太深）|
| **从素材插入表格** | ★★★★★ | 业绩表、参数对比表、案例清单，常来自已有 Word/Excel | **P0 必做**（现在只能手打）|
| **从官方来源插入片段** | ★★★★★ | 合规要求"可核验"，插入时**自动带【来源】** 是最省心也最不容易漏的做法 | **P0 必做** |
| **插入表格模板**（章节类型感知）| ★★★★ | 减少"从零画表"的返工；评分点常要求固定格式（响应表、偏离表）| **P1** |
| **插入关系图 / 结构骨架** | ★★★☆ | AI 也能出图，人工插入只是"我自己画一张" | **P2** |
| **空白「文字说明」** | ★☆ | 想写一段话，直接回车打字即可；插个空段落反而要多删 | **建议删除** |
| **空白「手动表格」**（当前是固定 3 列表头）| ★★ | 固定表头"要求/响应/验证"只适合少数场景，多数时候用户要自己删改 | 改为**选模板**，不再给死表头 |

**一句话**：插入的价值不在"形状"（文字/表格/图），而在**"这段内容有出处"**。

---

## 三、现在的问题：入口按"类型"分，用户按"来源"想

当前：

```
插入 ▾ → 文字说明 / 手动表格 / 关系图        （按内容类型分）
```

但用户真实的心智是：

> "这一节要放一份**近三年业绩表**" → 我去找**那份文件**
> "这里要引一段**政策原文**" → 我去找**那条来源**
> "这里要一张**证书图片**" → 我去找**那张图**

**类型驱动会诱导"空壳"**：点了「手动表格」得到一张空表 → 用户面对空表不知填什么 → 或者用 AI 编内容填 → 违反"不编造"的硬约束。

**来源驱动天然闭环**：插入的内容自带出处 → 可核验 → 与"素材池 / 依据"打通 → 与"计划待办（补 N 份我方材料）"打通。

---

## 四、建议的插入结构（IA）

```
插入 ▾
├─ 从素材插入 ▸          ← 我方材料（真实、有出处）
│    ├─ 摘录原文（可改字数）
│    ├─ 表格（从 Word/Excel 提取，保留原格式）
│    └─ 图片（证书 / 截图 / 架构图，保留原图）
├─ 从官方来源插入 ▸      ← 外部依据（自动带【来源】）
│    └─ 片段列表（勾选后插入，自动附【来源：文件名 · 第 N 页】）
└─ 插入结构 ▸            ← 模板（提效，非必须）
     ├─ 对比表 / 响应表 / 偏离表（按章节类型推荐）
     ├─ 关系图骨架
     └─ 分点清单
```

**为什么不放在"素材池"页签里就够了？**
素材池是"管理素材"的地方（看、核对、移除）；插入是"写作时的一次动作"，必须**在光标处随手可达**，否则写一句话就要切页签找素材，写作流被打断。

---

## 五、插入方式（交互层）怎么做更合适

| 要素 | 建议 | 理由 |
|---|---|---|
| **触发位置** | 工具条「插入 ▾」+ 素材卡片上的「插入」按钮（两处入口）| 写作时随手可达；管理素材时也能直接放进去 |
| **插入位置** | **当前光标处**（保留选区）| 符合编辑器直觉；不需要用户再拖动 |
| **插入前** | 小预览（将插入的内容 + 来源 + 字数/页数估算）| 避免"点了不知道插了什么"，尤其是长表格/图片 |
| **插入后** | 自动**选中新内容** + toast「已插入（可 Cmd+Z 撤销）」| 让用户立刻确认位置；撤销低成本 |
| **模板插入** | 用 `【待补充：xx】` 占位并高亮 | 空的表格更容易被 AI 填假数据；占位符强制人工补齐 |
| **图片插入** | 插入为独立段落 + `:::figure 图注` 体裁 | 与现有图表计划/图注体系一致，导出时能生成"图 1-1"编号 |
| **来源插入** | 自动附【来源：文件名 · 页】 | 合规硬要求，靠人记必漏 |
| **插入失败/冲突** | 光标落在表格中间等非法位置时，插到**最近段落末尾**并提示 | 避免静默插错位置 |

## 六、优先级（按投入产出）

| 优先级 | 事项 | 说明 |
|---|---|---|
| **P0** | 从素材插入：摘录 / 表格 / 图片 | 现在的缺口最大：素材卡里只有"插入图片/引用摘录"，表格完全没法用 |
| **P0** | 从官方来源插入片段（自动带来源）| 合规价值最高；现在要在素材池里点"片段"→选→再回正文 |
| **P1** | 插入结构模板（章节类型感知 + 占位符）| 替换现在那个固定 3 列表头 |
| **P2** | 关系图骨架入口 | AI 已能出图，人工入口保留即可 |
| **P3** | 删除空白「文字说明」| 空段落没有信息价值，只会制造"AI 味"排版 |

---

## 七、与现有体系的衔接（避免又造一个孤岛）

- **待办闭环**：计划待办里的"补 1 份我方材料" → 点开就是"从素材插入"（同一个心理动作：把真实材料放进去）
- **素材池**：插入 = 素材的第二个出口（第一个是"核对/移除"）；插入后回写"被引用"状态
- **依据页签**：插入来源片段 → 依据页签的"正文已回应"立刻变化（已有 basis 统计）
- **图表计划**：插入图片 → 计入图表示例，导出编号自动生成

---

## 八、结论（给决策的三句话）

1. **必要性**：图片、素材表格、官方原文片段 = **刚需**；空白"文字说明"= **可以删**；模板 = 提效项。
2. **入口**：从"按内容类型"改为"**按来源**"（素材 / 官方来源 / 结构模板）。
3. **方式**：光标处插入 + 插入前预览 + 插入后选中并提示可撤销 + 来源自动带出处 + 模板用占位符强制人工补齐。
