# 「目录级编写计划」评审：确认门槛、逻辑耦合与价值定位

> 触发：用户提问——① 这个界面的价值在哪？② 让应答人员去"填要求并确认"，他怎么确认得了？
> ③ 后面的章节要等当前模块确认才能生成，这个耦合对不对？
> 依据：界面实测 + 数据核对（p29 技术草案：s1.2 有 7 章；plan status=confirmed；章级 confirmed 均为空）。

---

## 一、先回答"价值在哪里"

一个**目录级**（一级目录 = 技术评分点，含 5~7 章）的计划，真正的价值只有三个：

| 真实价值 | 具体收益 |
|---|---|
| **① 排期与分工** | 一次看到这个评分点下 7 章的工作量（页数/表图数/要求数），据此分配给人、排到周 |
| **② 批量动作** | 一次把"确认计划 / 分配篇幅 / 导出要求清单"做掉，而不是点 7 次 |
| **③ 跨章一致性** | 发现 7 章之间的重复要求、口径冲突、同一素材被多章争用 |

**但现在这个界面的形态是"7 份可编辑的要求表单"** ✗ —— 它实际上在要求用户：
**逐条审阅、逐条编辑 21 条要求的措辞**，然后"保存"。

这不是目录级的价值，这是**把章级编辑在一个抽屉里重复 7 遍** ✗。
于是价值被稀释成"看起来很忙、其实没人会做"。

**结论**：目录级入口应该做"**汇总 + 批量 + 一致性检查**"，
**编辑与确认都下沉到章**（章计划面板已经具备）。

## 二、问题一：为什么"确认"这件事对用户是个门槛

用户原话："我作为一个应标人员，打开这个编写计划，直接在图文处填入内容并确认。但对一个应答人员来讲，他怎么确认得了？"

这句话点出了三个根因：

### 2.1 角色错位：把"主编的职责"推给了普通应答人员

- **"要求"是主编/项目负责人定标准的活**（依据评分点与招标条款，决定这一章比什么、答到什么程度）
- **"能不能写、缺什么料"才是编写人员能判断的**
- 现在的界面把要求做成**可编辑输入框** ✗ → 语言上就在说"你来定要求" ✗ →
  一个普通应答人员既没有依据、也没有授权去改"这一章要答什么" ✗ → 他只能瞎改或者跳过 ✗

### 2.2 "确认"没有定义：确认什么？标准是什么？

界面里只有「保存要求」✗，**没有"确认"按钮** ✗，也没有说明"确认后会发生什么"。
用户面对的是：一堆可编辑行 + 一个"保存" → **他不知道自己在批准什么**。

"确认"在应答流程里其实是**两件不同的事**，现在被混成一件：

| 确认什么 | 谁有资格 | 应该在哪 | 判定标准 |
|---|---|---|---|
| **标准确认**：这一章的要求覆盖了评分点、没跑偏 | 主编/项目负责人 | **目录级**（一次看 7 章的要求是否互补/重复） | 要求来源是否每条能对上评分点要素/条款 |
| **条件确认**：这一章我现在能写（素材够、结构清楚） | 编写人员 | **章级** | 素材三档是否满足、篇幅、图表是否明确 |

**修法**：
- 目录抽屉 → 只保留**标准确认**（"本目录这 7 章的要点是否覆盖评分点"），且**只读展示**（不改要求）
- 章计划面板 → **条件确认**（"我能写了"），按钮文案改为「**我已备齐，可以生成**」
- 两处都不叫"确认"，分别叫「**主编审核要点**」「**编写条件确认**」——名字即职责

### 2.3 信息不足：看不出"需要什么素材、什么内容"

用户说"也看不出来需要什么素材、需要什么内容"——在这个抽屉里确实看不出：

| 用户需要知道 | 界面上有吗 |
|---|---|
| 这条要求要什么素材（类型/数量/去哪找） | ✗ 只有「未补素材」标签，点了没反应 |
| 这条要求写多少字/几段/什么结构 | ✗ 完全没有 |
| 这条要求对应招标文件哪句话 | ✗ 没有（因为要求本身是模板套出来的） |
| 这条要求不满足会怎样（失多少分） | ✗ 没有 |

**修法**：要求行必须带三个东西才谈得上"确认"：
1. **依据**（评分点要素 / 规范条款原文，可点开）
2. **素材需求**（类型 + 门槛，如"≥1 条官方来源片段"，带「去找」入口）
3. **完成形态**（预计页数 / 是否出表出图）

## 三、问题二：逻辑耦合——"后面的章节要等这个模块确认才能生成"

### 3.1 实际行为（已核实）

- 生成闸：`本章已确认 || 目录计划已确认` → 放行
- 未确认时不生成，而是**直接弹出这个目录级抽屉** ✗
- 数据现状：s1.2 的目录计划 `status=confirmed` → 意味着**7 章被一次性"确认"了** ✗，
  而 7 个章级的 `confirmed` 全为空 ✗

### 3.2 三个问题

1. **"总闸"思维**：目录确认变成"整目录总闸" → 用户想先写第 1 章，也被要求先把 7 章的要求过一遍 ✗
2. **批量确认 ≠ 逐章确认**：点了"确认并开始编制"（目录级）→ 7 章全部视为已确认 ✗ →
   用户从未真正看过第 5/6/7 章的要求 ✗ → "确认"失去意义 ✗（也会让"未回应/未补素材"被掩盖 ✗）
3. **弹出的是目录抽屉**：用户只是想"写这一章"，却被迫面对 7 章的编辑表单 ✗ → 门槛感 + 迷失

### 3.3 正确的耦合

```
生成条件 = 本章条件（不是目录条件）
  · 本章计划已确认（章级）
  · 素材/篇幅可选告警，不阻断（未达完成也能生成，正文写【待补充】）
  
目录级确认 = 批量便利（可选）
  · 一键把本目录 7 章标为"已确认"
  · 但批量确认时必须提示："将把 7 章视为已确认，你确认过它们的要点吗？"
  · 且列清单（7 章 × 要求数 × 未补素材）让用户扫一眼
```

**修法**：
- 生成闸只看**本章** ✓
- 未确认时弹的是**本章计划面板**（不是目录抽屉），带「我已备齐，可以生成」✓
- 目录抽屉里「确认并开始编制」改名「**批量确认本目录 7 章**」+ 确认前列出 7 章清单 ✓

## 四、顺带发现的 5 个具体问题（实测）

| # | 问题 | 证据 |
|---|---|---|
| 1 | **两套"要求编辑入口"** | 这个抽屉能改要求，章计划面板也能改 → 用户不知道以哪为准 |
| 2 | **同一目录存在两份计划** | s1.2 有两份（一份 confirmed、一份 draft 带新要求）→ 章级确认写到了 draft 那份，面板显示"已确认"但闸看的是另一份 |
| 3 | **"已回应"不可信** | 是按关键词匹配算的（正文里出现要求的前几个词就算"已回应"）→ 用户拿它当确认依据会被误导 |
| 4 | **「未补素材」无入口** | 只是个标签，点不了 → 用户不知道去哪补 |
| 5 | **抽屉里没有"确认"按钮** | 只有「保存要求」→ 用户问"我怎么确认"就是因为这个 |

## 五、重构后的两个界面（一轻一重）

### 目录级（轻：汇总 + 批量 + 一致性）

```
编写计划 · 《对项目的理解》（7 章）
工作量：7 章 · 计划 45 页 · 表 14 张 / 图 7 张 · 要求 21 条（已落点 13）

章                    页    要求      素材      正文      状态
项目背景现状目标       —     3 条 2/3  待补 3    已写 25.5 页  [打开本章计划]
建设范围               —     3 条 2/3  待补 3    —            [打开本章计划]
建设内容 …（共 7 行，点击进章计划）

[批量确认本目录 7 章]  ← 点击前先列清单提醒
[导出要求清单（Word/Excel）]
[一致性检查：本目录内重复/冲突的要求 2 处 ▾]
```

### 章级（重：干活）

章计划面板（已具备 A~F）+ 一个明确的确认按钮：
```
[我已备齐，可以生成]   ← 替代"确认本章计划"
  说明：确认后本章可生成；未确认也可生成（正文写【待补充】）
```

## 六、与"要求从哪来"的关系（这是地基）

用户"看不出需要什么内容"的根本原因，是**要求本身不是从招标文件推出来的**：
现在三条要求是模板套的（政策依据/映射表/趋势图）→ 用户无法把它和"招标文件要我答什么"对上 →
自然无法确认。

所以顺序必须是：**先让要求来自"评分点要素 + 规范条款"（R2）**，
再谈"确认"——那时每条要求都能显示"依据：评分点要素（理解现状、现状数据、重难点）"，
用户才可能判断"这条我能写/我没料"。

## 七、分批修复建议

| 批次 | 内容 | 解决 |
|---|---|---|
| **C1** | 目录抽屉降级为"汇总 + 批量"：去掉逐条编辑，改为 7 行清单（页数/要求/素材/正文/状态 + 打开本章计划）；「批量确认」带清单提醒；只保留一个要求编辑入口（章面板） | Q0 价值、Q1 门槛、④⑤ |
| **C2** | 生成闸只看本章；未确认时弹**章计划面板**并给「我已备齐，可以生成」；文案区分"主编审核要点 / 编写条件确认" | Q2 耦合 |
| **C3** | 修数据：同一目录多份计划合并（保留最新，旧计划标记 deprecated）；章级确认写到"当前生效计划" | ④ 数据一致性 |
| **C4** | 「已回应」改为「正文出现相关表述（疑似）」并降低权重；「未补素材」给入口（跳章计划 D 段） | ③④ 可信度 |
| **C5（R2）** | 要求来源改为评分点要素 → 条款 → 模板，每条标来源 | 根因 |

## 八、一句话总结

> 这个界面现在的问题不是"排版不好"，而是**它在让人做一件他没有资格、也没有信息做的事**：
> 让编写人员去审核/编辑"这一章要答什么"。
> 正确分工是：**目录级只做汇总与批量（主编看要点覆盖）· 章级才做编辑与确认（编写人确认"我能写"）·
> 生成只卡本章条件**。
