# 「未保存 / 保存 / 确认本章完成」梳理与方案

> 用户截图指出三处控制：**未保存**（章头右上）、**保存**（工具条）、**确认本章完成**（更多菜单）。
> 问：实际意义与价值在哪？区别是什么？目前有歧义。

---

## 一、结论先行

**现在这三者混了三个不同层次的东西**：

| 层次 | 该表达什么 | 现在承载者 |
|---|---|---|
| 内容状态 | 正文有没有改动、存没存 | 未保存（标签）+ 保存（按钮）|
| 交付状态 | 这一章是否可交付 | 确认本章完成 |
| 生命周期 | 草稿 / 已保存 / 已完成 | 三处各说一半 |

**问题根源：状态只有一个"半个状态机"，没有明确的层间规则。**

方案：**把三个控制收敛成一条状态线 + 两个动作**
- 状态线：`草稿（有改动）→ 已保存 → 已确认完成`
- 动作：**保存**（自动 + 手动）、**确认完成**（唯一的"交付状态切换"）

---

## 二、逐项梳理：现在各自做什么

### 2.1 「未保存」（章头右上）

| 项 | 现状 |
|---|---|
| 是什么 | 一个**状态文本**（`chapter-head` 里的 span）|
| 何时出现 | `dirty=true`（编辑器内容与服务器不一致）|
| 三种文案 | `未保存` / `未保存 · 已恢复本地修改`（sessionStorage 草稿恢复）/ `已保存 · <状态>`|
| 价值 | 提示"改动还没写进服务器" |
| **歧义** | ① 它只说"没保存"，不说"会不会丢" ② 没有"上次保存时间" ③ 与「已保存 · 草稿」混在一起，看不出层级 |

### 2.2 「保存」（工具条）

| 项 | 现状 |
|---|---|
| 是什么 | `PUT /blocks/{id}` 写正文 + 写一条 revision |
| 何时可用 | 仅 `dirty=true`（否则 disabled）|
| 副带行为 | 如果该章原本是 `complete` → **自动降级为 `review`**（无提示）|
| 价值 | 真正落库；导出只认已保存内容 |
| **歧义** | ① 没有自动保存 → 用户必须记得点 ② 保存的含义是"暂存"还是"提交"？③ 保存导致"完成状态"被悄悄降级 ④ disabled 时用户不知道"我到底该不该点" |

### 2.3 「确认本章完成」（更多菜单）

| 项 | 现状 |
|---|---|
| 是什么 | 先 `save()` → `completion-check`（AI 编制是否结束 / 正文是否为空 / gaps / issues）→ 有缺口弹"待核对"→ 否则标记 `complete` |
| 价值 | 标记"这章写完了"，导出/进度上体现 |
| **歧义** | ① 它检查的问题与「待办」**两套说法** ② 完成后还能改吗？（能，但改了会自动降级，用户不知道）③ 完成 ≠ 可交付（只是"没检查出问题"）④ 与"导出本章"的关系不清楚（导出时是否要求已完成？）|

### 2.4 三者的关系（现状）

```
编辑 → dirty=true → 显示"未保存" → 点保存 → 已保存 · 草稿
                                          ↓
                             点"确认本章完成" → 检查 → complete
                                          ↓
                              再次编辑保存 → 自动降级 review（无提示）
```

**歧义清单（6 条）**

| # | 歧义 |
|---|---|
| 1 | 「未保存」是状态还是警告？会不会丢？ |
| 2 | 「保存」是"暂存"还是"定稿"？ |
| 3 | 「确认本章完成」与「待办」检查项不一致 |
| 4 | 完成后编辑，状态被悄悄降级 |
| 5 | 导出用的是哪一版？（未保存时导出会缺最新内容，无提示）|
| 6 | 三个控制分在三处，用户需要记三件事 |

## 三、方案：一条状态线 + 两个动作

### 3.1 状态模型（唯一真相）

```
┌──────────┐  自动保存(2s) / 手动保存   ┌──────────┐   确认完成(通过检查)   ┌──────────┐
│ 草稿·有改动 │ ──────────────────────▶ │  已保存    │ ───────────────────▶ │ 已确认完成 │
│ (未保存)   │ ◀────────────────────── │ (可导出)  │ ◀─────────────────── │ (正式稿)  │
└──────────┘   任何内容改动 → 回草稿     └──────────┘   取消确认/再次编辑     └──────────┘
```

**规则（写进产品，界面上也要说出来）**

| 规则 | 说明 |
|---|---|
| R1 | 任何内容改动 → 回到「草稿·有改动」，并**自动保存**（2 秒防抖）|
| R2 | 「已保存」= 服务器内容 = 编辑器内容；导出**只导已保存内容** |
| R3 | 「已确认完成」= 用户明确认可可交付；它**不是锁**，改动后自动退回「已保存」并**明确提示**「本章已退回待确认」|
| R4 | 退出/切章前若有未保存改动 → 拦截提示（已有 beforeunload，保留）|
| R5 | 导出时若处于「草稿·有改动」→ **提示并先保存**（不静默导旧版）|

### 3.2 三个控制怎么改

| 现在 | 改后 | 理由 |
|---|---|---|
| 「未保存」纯文本 | **状态胶囊 + 保存入口合一**：<br>`● 未保存 · 刚刚改动 [保存]` / `✓ 已保存 · 12:03` / `✓ 已确认完成 · 今天` | 一眼知道状态 + 一键动作 |
| 「保存」按钮 | **保留，但降级为"次要"**（自动保存已兜底），并支持 `Cmd/Ctrl+S` | 用户习惯 + 心理安全 |
| 「确认本章完成」 | **升格为唯一交付动作**，放在状态胶囊旁（「已完成 → ✓ 已确认完成」），检查项**复用待办 F 组（交付门槛）** | 交付语义唯一 |

### 3.3 「确认完成」的检查项 = 待办里的 F 组

**统一到一套清单**（都来自"交付门槛检查"）：

| 检查项 | 属于 |
|---|---|
| AI 编制是否已结束 | 门槛前的状态检查 |
| 正文是否为空 | F |
| 必备表/图是否齐（按计划交付物）| F |
| 未消除的阻塞待办（A/C 组）| F（待办里"阻塞交付"的项）|
| 图片是否都渲染成功 | F |

**规则**：有阻塞项 → **不允许标记完成**（或允许但明确标"带风险完成"，导出时再提醒）。
建议：**不允许**（标书场景风险高）。

### 3.4 导出与状态的关系

| 状态 | 导出本章 |
|---|---|
| 草稿·有改动 | 提示「有未保存修改，先保存再导出」→ 一键保存后继续 |
| 已保存 | 允许（导出内容 = 已保存）|
| 已确认完成 | 允许，且文件名/页眉可标"定稿"|

## 四、界面呈现（改后）

```
项目背景现状目标                        ○ 未保存 · 刚刚改动 [保存]   本章计划
[编写整章]  [保存]  [编辑|预览]                     插入…  更多
                                                        ├ 确认本章完成
                                                        ├ 导出本章 Word
                                                        └ 导出本组 Word
```

- 状态胶囊：`○ 未保存`（琥珀）/ `✓ 已保存 · 12:03`（省略为灰）/ `✓ 已确认完成`（绿）
- 「确认本章完成」仍在更多菜单（低频、破坏性动作放菜单里），但完成后**状态胶囊变绿**，用户知道生效了
- 未保存时点导出 → 弹「先保存」确认

## 五、验收标准

1. 状态胶囊三态准确：未保存 / 已保存（带时间）/ 已确认完成
2. 停止输入 2 秒内自动保存；保存中显示「保存中…」；失败提示可重试
3. `Cmd/Ctrl+S` 立即保存
4. 完成后再次编辑 → 状态回到「已保存」并提示「本章已退回待确认」
5. 「确认本章完成」的检查项与待办「阻塞交付」项**完全一致**
6. 有阻塞项时不允许确认完成（给出清单）
7. 未保存时点导出 → 先保存再导出（提示一次）
8. 切章/关闭页面有未保存改动 → 拦截（保留现状）
9. 无控制台错误；自检覆盖 1/4/5/7

## 六、实施拆分

| 步 | 内容 | 量 |
|---|---|---|
| S1 | 状态胶囊组件（三态 + 时间 + 保存入口）| 小 |
| S2 | 自动保存（2s 防抖 + 保存中/失败态）+ Cmd+S | 小 |
| S3 | 完成后降级改为**显式提示**，不再是静默 | 小 |
| S4 | 「确认完成」检查项复用待办阻塞项（统一清单）| 中 |
| S5 | 导出前状态校验（未保存 → 先保存）| 小 |
| S6 | 完成后状态在进度/目录上的可见标识 | 小 |
| S7 | 自检规则 4 条 | 小 |

建议顺序：**S1 → S2 → S3 → S5 → S4 → S6 → S7**（前四项是"消除歧义"，S4 是"统一口径"）。
