# 章节编写方案（计划为中心）：计划 = 章的唯一容器

> 核心论断（来自产品判断）：
> **编写计划不是"任务清单"，而是"这一章怎么写"的全部信息容器**；
> **质检清单不是独立功能，而是计划里的"验收项 / 还差什么"（隐性）**；
> **编写进度才是结果**（写到哪、写了多少、达没达标）。
> 三者：**计划（输入）→ 编写（执行）→ 进度与验收（结果）**。

---

## 一、现状的问题（按这三个概念重新定位）

| 概念 | 现在放在哪 | 问题 |
|---|---|---|
| **编写计划** | 一级目录的抽屉（5~7 章共用一份）；章头只显示"所属计划" | 计划单位错了：**计划应属于章**；且只含体裁/篇幅/要求，缺"怎么写、要什么素材、哪些图表" |
| **要求** | 在目录计划的章条目里 | 没有依据（哪个评分点/条款）、没有对应的素材需求、不可在章内编辑 |
| **素材** | 右栏「素材」页签（独立） | 与"要求"没有结构关系；看不出"这条要求缺什么素材" |
| **图表** | 计划里的 tasks（体裁） | 只有"表格 2 张"这种数量，没有"哪几张表、什么用途、从哪来" |
| **质检清单** | 「更多 › 质检清单」（独立菜单） | 被当成"工具/报告"，独立于计划 → 用户要跑一遍才看到问题；且按整册汇总，不是"这一章还差什么" |
| **进度** | 章头/左树/进度中心 | 结果是有的，但没有和"计划里的要求"对齐（要求 3 条达成几条） |

一句话：**计划被做小了（只是任务清单），质检被做大了（独立功能），进度没有对齐计划。**

---

## 二、目标模型：一个容器、两类输出

```
章节（最小单位）
│
├─ ① 编写计划（本章唯一入口 = 唯一容器，可编辑、可确认）
│    ├ A 要写什么   ：要求（逐条）+ 内容边界（含哪些节/不含哪些）
│    ├ B 写多少     ：篇幅（页/字）+ 分配
│    ├ C 怎么写更好 ：规划（结构套路：骨架/必表/必图/失分点/写法要点）
│    ├ D 要哪些素材 ：素材需求（按 A 派生：政策/标准/数据/案例/证明/图片）+ 已补/待补
│    ├ E 体现哪些图表：表（张数+每张用途+来源）+ 图（张数+每张用途+来源）
│    └ F 验收清单（隐性）：还缺什么 / 还要改什么（由 A~E 自动推导 + 可手加）
│
└─ ② 编写（执行）：读计划 → 多 Agent 生成（按 A~E 对齐）→ 保存
      ↓
  ③ 编写进度（结果）：状态 / 字数篇幅 / 生成记录 / 版本
  ④ 验收结果（结果之一）：F 的达成情况（要求已回应 N/M、素材已补 X/Y、图表齐不齐）
```

**关键区别**
- **计划是"输入"**：写之前就有，写的时候照它写，写完对照它验收。
- **验收清单（原质检）是计划的一部分**，不是另一个模块：它的作用是"告诉我还差什么"，跟"计划"在同一屏。
- **进度是"结果"**：只在写之后有意义，独立展示（章头/左树/进度中心）。

## 三、计划的六段：每段要回答什么、从哪来、界面怎么呈现

### A. 要写什么（要求 + 内容边界）

| 项 | 内容 |
|---|---|
| 要求 | 逐条（5~8 条），带类型（文字/表格/图示/素材）+ **依据**（评分点/规范条款） |
| 内容边界 | 本章该覆盖的子主题（来自评分点要素/规范条款/原文段落）；不写的要明说 |
| 从哪来 | 计划 requirements（已有）+ 本章评分点/条款（已有 `review_point_ids`）+ 配方骨架 |
| 界面 | 列表：每条「要求文字 · 类型 · 依据 · 已回应/未回应」，可编辑/增删 |
| 生成作用 | 逐条要求写进去（提示词强制"每条要求都要有着落"） |

### B. 写多少（篇幅）

| 项 | 内容 |
|---|---|
| 篇幅 | 页数（本章分配）+ 按节拆分；字数换算（1 页≈250 字） |
| 从哪来 | 策划页的篇幅分配（已有）+ 计划 pages |
| 界面 | 「12 页 · 已写 8.4 页」进度条；可在此微调本章页数 |
| 生成作用 | 控制成稿长度（少写/超写都在验收里报） |

### C. 怎么写更好（规划）

| 项 | 内容 |
|---|---|
| 结构套路 | 骨架（先结论后论证）、必表/必图、失分点提醒 |
| 写法要点 | 本章的叙事顺序（如"政策→现状→差距→目标→对策"）、量化要求、禁写内容 |
| 从哪来 | 编写规范 L1 模块配方（已有）+ 8 类章名模板（已有） |
| 界面 | 折叠块「本章写法建议」（读自规范，可跳"编写规范"改） |
| 生成作用 | 注入提示词（L0/L1 已在做，补齐"本章写法要点"） |

### D. 要哪些素材（素材需求）

| 项 | 内容 |
|---|---|
| 需求 | 每条要求 → 素材需求（类型：政策/标准/数据/案例/我方证明/图片） |
| 状态 | 每条：已补（绑定了片段/材料）| 待补 |
| 从哪来 | 由 A 的要求派生（已有 needs + need_snippets）+ 我方材料（已有） + 外部来源片段（已有） |
| 界面 | 每条要求后面「素材 已补 N / 待补」；待补的一键「找素材」；已补的可展开看绑了哪些片段 |
| 生成作用 | 按"要求 → 绑定片段"注入（已有） |

### E. 体现哪些图表（图表计划）

| 项 | 内容 |
|---|---|
| 表 | 张数 + 每张：用途/表头/数据来源（我方材料 or 外部来源片段） |
| 图 | 张数 + 每张：类型（架构/流程/时间轴）+ 用途 + 数据来源 |
| 从哪来 | 规范 L0（每节至少 1 表）+ 配方（必表/必图）+ 8 类模板（已有表名） |
| 界面 | 「图表计划」列表：`表格 2 张 · 图 1 张`，逐条可看用途与来源 |
| 生成作用 | 明确"必须产出这些表/图"，避免生成时漏 |

### F. 验收清单（隐性，原"质检"）

| 项 | 内容 |
|---|---|
| 作用 | 告诉用户"这一章还差什么、还要改什么"，**不是一份报告** |
| 内容 | ① 素材待补（来自 D）② 要求未回应（来自 A）③ 依据未落点（评分点/条款）④ 图表缺失（来自 E）⑤ 格式纪律（骨架/空词/篇幅/来源标注） |
| 从哪来 | 现有质检四组（规范/计划/依据/素材）+ needs 待补，按本章聚合 |
| 界面 | 计划面板最后一块「还差什么」：每条一句话 + 一键动作（去找素材/重新生成/标为已处理） |
| 生成作用 | 不参与生成；生成后回填"达成情况" |

## 四、界面：章头一个按钮，打开"本章计划"单页

```
┌ 本章计划：项目背景现状目标 ───────────────────────────── [×] ┐
│ 12 页 · 已写 8.4 页 · 要求 3 条（已回应 2） · 素材待补 2        │
│                                                              │
│ A 要写什么                                                   │
│   [文字] 政策依据与项目背景结论    依据：对项目的理解·10分    │
│          正文已回应 ✓                                         │
│   [表格] 政策依据映射表            依据：…    正文未回应      │
│   [图示] 趋势或现状对比图          依据：…    正文未回应      │
│                                        [编辑要求]             │
│ B 写多少   12 页（已写 8.4）  [调整篇幅]                      │
│ C 怎么写更好 ▸ 本章写法建议（先结论后论证 / 政策→现状→…）      │
│ D 要哪些素材                                                 │
│   政策依据与项目背景结论  素材 已补 2                          │
│   政策依据映射表          素材 待补      [找素材]             │
│   趋势或现状对比图        素材 待补      [找素材]             │
│ E 体现哪些图表                                               │
│   表格 2 张：政策依据映射表 / 现状维度表                      │
│   图 1 张：趋势对比图（建议流程/对比图）                       │
│ F 还差什么（验收清单）                                        │
│   · 政策依据映射表：素材待补            [找素材]              │
│   · 趋势或现状对比图：正文未回应         [重新生成]            │
│   · 正文引用政策但无【来源】标注          [去补来源]            │
│                                                              │
│                            [AI 编制本章]  [关闭]              │
└──────────────────────────────────────────────────────────────┘
```

**右栏三页签的去向**（收敛，不再各说各话）：

| 现在 | 目标 |
|---|---|
| 右栏「依据」页签 | → 并入计划 A（依据在要求上） |
| 右栏「素材」页签 | → 并入计划 D（素材挂要求）；「外部依据/本章素材」作为"D 的素材池"折叠 |
| 右栏「编制进度」页签 | → 保留（进度是结果）：角色/字数/耗时 |
| 「更多 › 质检清单」 | → **降级为汇总**（进度中心里的"待补/待改"，按章汇总）；章内入口就是计划 F |

## 五、闸门与状态

| 闸门 | 条件 | 说明 |
|---|---|---|
| 计划确认 | **章级**：本章要求已确认（可一次批量确认某目录下所有章） | 确认的是"这一章怎么写"，不是"整棵子树" |
| 无计划时生成 | 允许，但提示"本章还没有要求，生成的正文无法验收" | 不硬拦（避免卡住） |
| 验收 | 不阻断保存/导出；导出前提示"待补素材 N · 未回应要求 M" | 用户口径 |

**章节状态**：目录 → 未计划 → 已计划（待写）→ 编写中（草稿）→ 待验收（有未达成项）→ 已完成（要求全回应 + 已补素材 + 无高优）
**"已完成"由系统判定 + 人工确认**（现在纯人工点，改造后给"还差什么"作为依据）

## 七、分期实施

| 期 | 内容 | 验收 |
|---|---|---|
| **S1（最小可用）** | 章头「编写计划」改为**本章计划单页**（A 要求依据 / B 篇幅 / D 素材待补 / F 还差什么）——四段即可 | 打开任一章，一屏看到"要求/素材缺口/还缺什么"，无需跳到别处 |
| **S2** | C 写法建议 + E 图表计划（每张表/图的用途与来源） | 计划里能说清"这章要出 2 表 1 图，分别是什么、从哪来" |
| **S3** | 验收清单并入计划（F）+ 右栏三页签收敛（依据/素材并入计划，进度保留）+ 全局质检降级为进度中心汇总 | 章内不再有独立"质检"入口 |
| **S4（可选）** | 计划确认改到章级（批量确认保留）；"已完成"由系统判定 | — |

## 八、验收标准（方案做完的判断）

1. 打开任一章 → **一个面板看全**：要求、依据、篇幅、怎么写、要什么素材、哪些图表、还差什么。
2. 每条要求能回答：**依据是什么、素材补没补、正文回应没回应**。
3. 「还差什么」的每一条都能**一键去处理**（找素材/重新生成/看规范）。
4. 右栏不再出现"依据/素材/进度"三页签各说各话（依据、素材进计划；进度独立）。
5. 全局视角只剩"进度中心"（各章达标情况汇总），不再有"质检清单"独立菜单。
6. 生成时计划 A~E 全部进提示词（要求逐条、素材按绑定、图表明确、写法有据）。

## 九、边界

1. **计划是输入，不是报告**：计划里不放"写得怎么样"（那是进度/验收），只放"要写成什么样"。
2. **验收是隐性**：不叫"质检"，叫"还差什么"；不给总分；不阻断。
3. **不重复收集**：素材池（我方材料/外部来源）只维护一处，计划里的 D 只做"需求↔素材"的对应。
4. **章是单位**：计划、确认、验收都以章为单位；一级目录只做"批量确认/汇总"。
5. **人工优先**：要求由人确认；AI 只起草；标"已处理"要留痕（谁标、何时）。
