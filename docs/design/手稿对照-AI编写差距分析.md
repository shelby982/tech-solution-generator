# 对项目的理解（手稿）vs 产品 AI 编写：差距分析

> 参照物：`对项目的理解.docx`（已完成的真实稿件，项目 2.1–2.8）
> 对比对象：本项目「对项目的理解」分支已生成的 11 章 AI 正文
> 结论先行：**差距不在"会不会写"，在"写多深、写多实、有没有依据"** ——
> 篇幅 14 倍、引用 0 vs 172、结构深度 3 级 vs 7 级。

**结构与写法特征**
1. **七级标题**：H2（大节）→ H3（章）→ H4（子主题）→ H5（要素）→ H6（要点）→ 甚至 H7
2. **成对结构**：每个专项都是「建设难点分析 → 建设痛点分析 → 针对性解决措施」三段式，**问题与措施一一对应**
3. **每段首句即结论**，随后 ①②③ 展开；段落 176 字左右
4. **表格是"对比/指标/清单"**：如「可靠性指标 | 定义 | 行业参考值」「架构维度 | 现状特征 | 主要挑战 | 影响范围」

6. 手稿**也没有图表编号**（"图 1-1"为零）→ 这一点产品可以做得更好

## 三、六个硬差距（按对评分的影响排序）

### 差距 1｜篇幅差 14 倍 —— 根本原因：**生成单元不对**
- 手稿「2.1 项目背景」一节就 5.7 万字；产品给的"章"目标字数 3000 字
- 产品是"一章一次生成"，手稿是"一节 → 子主题 → 要素"层层展开
- **后果**：内容只能写"面"，写不到"层"

### 差距 2｜引用 0 处 —— 最致命
- 手稿 172 处《…》政策/标准引用，且每处"政策 → 要求 → 对应工作"
- 产品正文【来源】为 0：素材片段有，但**没有被写进正文**
- **后果**：说服力与合规性双失（评分点常直接看"依据是否充分"）

### 差距 3｜结构深度 3 级 vs 7 级
- 产品章内只有模型自拟的小标题（不可控、不统一）
- 手稿每层都有**明确命名**（H5 是"要素"，H6 是"要点"）
- **后果**：AI 稿"看起来有结构"，但评审找不到"要素是否齐"

### 差距 4｜难点-措施不成对
- 手稿：每个难点/痛点都有**同名对应**的解决措施（H5×N 与 H6×N 一一对应）
- 产品：重难点与措施各写各的，**对不上**
- **后果**：2.6/2.8 这类"分析能力"评分点直接失分

### 差距 5｜表格与图"少而泛"
- 手稿 63 张表，都是"指标/对比/清单"型；19 张图（架构/分层）
- 产品 10 张表（如"政策依据映射表"），图 5 张（刚支持三型）
- **后果**：可读性与专业度不足

### 差距 6｜段落与句法
- 手稿 176 字/段、首句结论、①②③ 分点
- 产品段落偏长（300+）、分点少、偶有"综上所述/赋能"式空话

## 四、根因（三条）

| 根因 | 说明 |
|---|---|
| **R1 生成粒度太粗** | 一次生成整章（3000–8000 字）→ 模型前 2000 字质量尚可，后面沦为复述 |
| **R2 没有"依据/数据"清单** | 模型不知道哪些政策名、指标、系统名必须出现 → 只能写"较高/较强" |
| **R3 结构是"自由发挥"** | 小标题、成对关系、表格位置都不受控 → 每章结构都不一样 |

## 五、完善点清单（P0 / P1 / P2）

### P0（不解决就永远达不到手稿水平）

| 编号 | 完善点 | 做法 | 验收指标 |
|---|---|---|---|
| **P0-1** | **小标题计划**（节 → 子节两级大纲）| 生成前先出两级大纲（结合交付物、评分点、素材），用户可增删改；确认后逐节写 | 每章 ≥6 个子节，命名来自计划而非模型自拟 |
| **P0-2** | **分节生成** | 每个子节一次调用（600–1200 字），节内结构固定：结论句 + 依据/数据 + ①②③ | 单段落 ≤200 字；每节 ≥3 段 |
| **P0-3** | **数据与依据清单** | 从招标文件/素材抽「指标数字 / 标准号 / 系统名 / 政策名」，形成"必须出现"清单，写作时注入并对稿检查 | 每 1000 字 ≥1 个带单位数字；每节 ≥1 处《》引用 |
| **P0-4** | **难点-措施成对模板** | 识别"重难点/痛点/措施"章节 → 强制 `问题 → 影响 → 措施 → 验证` 四段成对生成 | 难点与措施数量一致、标题一一对应 |
| **P0-5** | **每节配表/图** | 按子节类型自动布点：指标/对比类 → 表；架构/层次类 → 图（用已上线的三型）| 每 2 节 ≥1 张表或图 |

### P1（决定"像不像标书"）

| 编号 | 完善点 | 做法 |
|---|---|---|
| P1-1 | 术语与规范库 | 把"部门术语表 + 写作规范"接进提示词（现有 writing_specs 扩展覆盖率）|
| P1-2 | 引用密度与格式 | 引用统一为「政策名（发文机关 · 年份）」+ 正文对应要求；导出带出处 |
| P1-3 | 语言风格校准 | 禁用词表（综上所述/赋能/闭环/抓手…）+ 句长控制 + 分点规范 |
| P1-4 | 表格模板库 | 指标表/对比表/清单表/矩阵表 4 类模板，按节类型自动选 |

### P2（规模化与一致性）

| 编号 | 完善点 | 做法 |
|---|---|---|
| P2-1 | 全篇一致性 | 编号体系（2.x / 图 1-1 / 表 1-1）、术语统一、跨章引用 |
| P2-2 | 篇幅校准 | 按目标页数反推每节字数（手稿 ≈ 2,000 字/页）|
| P2-3 | 复用库 | 难点-措施、表结构、图结构沉淀为可复用模板 |

## 六、落地路线（3 周，可度量）

| 阶段 | 内容 | 交付 |
|---|---|---|
| 第 1 周 | P0-1 小标题计划 + P0-2 分节生成 | 章节能生成 6–10 个子节、单节 600–1200 字 |
| 第 2 周 | P0-3 数据/依据清单 + P0-5 表图布点 | 每 1000 字 ≥1 数字、每节 ≥1 引用、每 2 节 ≥1 表/图 |
| 第 3 周 | P0-4 成对模板 + P1-3 风格校准 | 难点-措施一一对应；禁用词 0 出现 |

**评测方式**：把这份手稿拆成"对照集"（每个 H3 的目标结构 + 表格/图/引用数量），
对 AI 生成稿自动打分：`结构完整度 / 数据密度 / 引用密度 / 表图数量 / 成对率 / 段落规范`。
目标是先在「2.1 项目背景」一节上做到手稿的 60%，再谈全篇。

---

## 七、先说结论

产品现在能写出"结构像、但很薄"的稿子。要达到手稿的实际效果，**不是把提示词写长，而是把生成方式从"整章一次"改成"计划 → 分节 → 对稿"**，
并给模型三样它现在没有的东西：**子节大纲、必须出现的依据与数据、成对的问题-措施结构**。
