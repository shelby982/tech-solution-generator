# 素材库信息架构修正方案 v3（只出方案，不改代码）

> 用户修正后的口径（以此为准）：
> 1. **片段 = 素材**；素材 = 从「文章/文件」里挑中的内容；
> 2. **文件删除后，已挑的素材一起失效**；
> 3. **三页签的划分是错的**：不是「素材 / 我的文件 / 联网来源」三块并列；
>    正确是 **「我的文件」和「联网来源」是素材的两类出处**，它们属于素材库内部的两个页签；
> 4. 所以**添加素材时**才去选择：**上传文件** 或 **联网搜索**；
> 5. 素材 → AI 编写的接入交互，也要一并设计。

---

## 一、修正后的信息架构

```
素材（右栏页签，保留位置）
└─ 素材库（弹窗）
   ├─ 顶栏： [＋ 添加素材 ▾]   → 上传文件 / 联网搜索
   ├─ 页签： ① 我的文件  ② 联网来源         ← 这是"素材的出处"分类，不是并列三大块
   ├─ 内容： 当前页签的出处列表
   │        · 广东电网…pdf    477 段 · 已选 18     [展开]
   │            展开后 → 该文件里的片段列表
   │            ☑ 2.1 招标范围…（第 3 页）        ← 勾选 = 这段就是素材
   │            ☐ 2.2 项目概况…（第 4 页）
   │        · 技术招标文件.docx  54 段 · 已选 0
   └─ 底栏： [应用到本章]
```

**一句话**：素材库 = **两类出处（文件 / 来源）** + **每个出处里挑片段（挑中即素材）**。

---

## 二、为什么这样更对（对比上一版）

| 上一版 | 修正版 | 理由 |
|---|---|---|
| 三个并列页签：素材 / 我的文件 / 联网来源 | 两个页签：我的文件 / 联网来源 | 「素材」不是与出处并列的东西，**素材是出处里挑出来的片段** |
| 先在"素材页"看结果、再去"文件页"挑 | 在出处里直接挑，挑中即为素材 | 少了"结果页/原料页"的来回跳 |
| 添加素材入口分散 | **统一「＋添加素材」**：上传 or 联网搜索 | 符合用户的动作顺序：先决定素材从哪来 |

---

## 三、添加素材：两个入口，一个菜单

```
[＋ 添加素材 ▾]
 ├─ 上传文件…        （多选 PDF / Word / Excel / 图片）
 └─ 联网搜索…        （关键词 → 结果列表 → 选择来源入库）
```

| 动作 | 流程 | 结果 |
|---|---|---|
| 上传文件 | 选择文件 → 上传 → 后台解析成片段 → 出现在「我的文件」 | 出处（文件）+ 若干候选片段 |
| 联网搜索 | 输关键词 → 搜索结果列表 → 勾选要保留的来源 → 入库 | 出处（来源）+ 若干候选片段 |

## 四、在出处里挑素材（核心交互：内容多怎么找）

点出处的 **[展开]** → 就地展开片段挑选器（不必跳页）：

```
┌────────────────────────────────────────────────────────────────────┐
│ 广东电网…pdf  477 段 · 已选 18                       [收起] [删除]  │
│ 🔍[业绩 / 资质 / 数据]     筛选：[含数字][含条款][表格]  ☑ 全选命中    │
├────────────────────────────────────────────────────────────────────┤
│ ☑ 2.1 招标范围：…（第 3 页）        命中「业绩」                    │
│ ☑ 3.2 投标人资格要求：具备…（第 4 页）                              │
│ ☐ 3.3 业绩要求：近三年…（第 5 页）                                  │
│ …（虚拟滚动；每段可展开全文）                                        │
└────────────────────────────────────────────────────────────────────┘
已选 18 · [清空] [只看已选]
```

**六种手段解决"找不到"**

| 手段 | 作用 |
|---|---|
| 关键词搜索 + 命中高亮 | 输"业绩/资质/数据"，直接命中并高亮 |
| 结构化筛选 | 含数字 / 含条款号 / 表格 / 政策文件名 |
| 只看已选 | 复盘时用 |
| 批量选择 | 全选当前页 / 全选命中 / 按章节 |
| 目录/页码跳转（招标文件）| 直达"第三章 投标人资格" |
| AI 预筛（可选）| 按本章各节要点匹配 Top 10 |

**勾选 = 素材（方案 C 语义）**：勾上即成为素材，不需要二次确认；取消勾选即移除。

## 五、出处的增删改查

| 操作 | 我的文件 | 联网来源 |
|---|---|---|
| 增 | 上传 | 联网搜索 → 入库 |
| 查 | 文件名 · 段数 · 已选数 · 解析状态 | 标题 · 域名/日期 · 段数 · 已选数 |
| 改 | 重新解析（换切片策略）、替换文件 | 重新抓取 |
| **删** | 软删文件 → **其下已挑素材一起失效** | 删来源 → 其下片段与素材一起失效 |

**失效的表现**：本章引用清单里该素材标「来源已删除」；正文已有【来源：…】保持原文不动，但提示"需重新补来源"。

## 六、素材 → AI 编写（交互设计）

### 6.1 素材的三种用法（决定提示词怎么注入）

在出处里挑中片段后，可在「本章素材」里设置用法：

| 用法 | 生成时 | 正文表现 |
|---|---|---|
| **引用出处** cite | 只给来源标签 | 句尾【来源：广东电网…pdf（第 3 页）】|
| **数据依据** data | 注入片段 ≤300 字 | 句子含具体数字 + 【来源：…】|
| **仅上下文** context | 注入 ≤500 字，**禁止出现在正文** | 无标注，只影响口径与写法 |

### 6.2 应用素材到章节

```
素材库（挑好片段）→ [应用到本章]
   → 弹小面板：
      用到哪一节： [本章全部 / 项目政策依据梳理 / …]
      用法：       [引用出处 / 数据依据 / 仅上下文]
   → 确定 → 进入「本章素材」（写进 chapter_material_chunks）
```

### 6.3 编写时的注入规则（确定性，可解释）

```
本章素材 cite    → 只给 source_label
本章素材 data    → 片段 ≤300 字
本章素材 context → 片段 ≤500 字
本节指定素材     → 优先注入
未被挑中的片段   → 不进提示词
```

### 6.4 生成后：引用可追溯（已实现）

本章引用清单按模块折叠，每处【来源：X】可追到素材（第几页 / 哪个 URL），
点一下能定位正文那句。

## 七、数据模型（按"片段=素材"简化）

| 用途 | 现有表能否承担 | 结论 |
|---|---|---|
| 出处-文件 | `materials`（+软删）| ✅ 沿用 |
| 出处-来源 | `citations`（+软删）| ✅ 沿用 |
| 片段/候选 | `material_chunks` / `citation_chunks` | ✅ 沿用 |
| **素材 = 挑中的片段** | 片段表加状态：`candidate`（候选）/ `selected`（已挑=素材）| ✅ **不需要单独的素材表** |
| 章节引用 | `chapter_material_chunks(block_id, chunk_kind, chunk_id, section, mode)` | ✅ 沿用（mode = cite/data/context）|
| 文件删除→素材失效 | 文件软删时，其片段置 `rejected` | ✅ 级联规则 |

## 九、分期

| 期 | 内容 | 验收 |
|---|---|---|
| **M1** | 两页签（我的文件 / 联网来源）+ 出处列表（段数/已选数/解析状态）+ 删除（级联失效）| 删除文件后，其片段在素材中消失 |
| **M2** | 展开出处 → 片段列表 + 勾选即素材（candidate→selected）| 勾 5 段 → 已选 5；取消 → 0 |
| **M3** | 片段挑选器增强：搜索/筛选/批量/只看已选/目录跳转 | 477 段里 30 秒挑出"投标人资格"3 段 |
| **M4** | [＋添加素材]：上传 / 联网搜索两个入口 | 两个入口都能新增出处 |
| **M5** | 应用到本章（选小节 + 三种用法）+ 生成注入规则 | 生成后引用可追溯；context 素材不出现在正文 |

## 十一、实现核对（2026-10-23，最新代码）

`f07103b` 已把「应用到本章」从"只登记"推进到"参与生成"：

- 绑定写 `chapter_material_chunks(block_id, chunk_id, section, mode)`；
- `services/material_context.py` 读取绑定，渲染【可引用来源】/【数据依据】/【背景材料】；
- 注入点：章节级 SSE `_stream_section` + 单节流式 `/studio/section/stream`；
- 本章素材列表显示文件名/页码/用法/小节。

但以下 6 处仍未闭环，属于"点了但结果不符合预期"的来源：

| # | 现状 | 应该 |
|---|---|---|
| 1 | 弹窗底栏只有"小节"选择，**没有用法选择**；`mode` 仍硬编码 `'cite'` | 增加 引用出处/数据依据/仅上下文 三选一 |
| 2 | `section` 存了但 `chapter_material_context()` **只按 block_id 查**，所有节都注入 | 按 `section` 过滤：本节指定优先，整章绑定兜底 |
| 3 | `data` 模式只塞片段文本，不带来源标签；提示词却要求标【来源】 | 返回"来源标签 + 片段"，模型才标得出来 |
| 4 | `context` 只写"不得照抄"，**没有写后校验**；`cite` 也没有强校验 | 加 30 字重合/数字一致/引用存在校验 |
| 5 | `paste` 后端允许，但无 UI、无消费逻辑；不在 MODE_LIMITS 会被当成 cite | 删除或单独实现"插入正文" |
| 6 | 点击"应用"不立即改正文，只影响**之后**生成/重写的节；用户会以为没生效 | UI 明确"用于下一次生成"；需要立即插入则单独按钮 |

**结论**：方案里的目标逻辑（三种用法 + 按节注入 + 生成后校验）只完成了"绑定 + 注入"两步；
要真正可用，先补齐 1/2/3，再补 4；5/6 属于交互边界，建议明确区分"加入编写上下文"与"插入正文"。
