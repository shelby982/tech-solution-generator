# 素材库信息架构修正方案 v3（只出方案，不改代码）

> 用户修正后的口径（以此为准）：
> 1. **片段 = 素材**；素材 = 从「文章/文件」里挑中的内容；
> 2. **文件删除后，已挑的素材一起失效**；
> 3. **三页签的划分是错的**：不是「素材 / 我的文件 / 联网来源」三块并列；
>    正确是 **「我的文件」和「联网来源」是素材的两类出处**，它们属于素材库内部的两个页签；
> 4. 所以**添加素材时**才去选择：**上传文件** 或 **联网搜索**；
> 5. 素材 → AI 编写的接入交互，也要一并设计。

---

## 一、修正后的信息架构

```
素材（右栏页签，保留位置）
└─ 素材库（弹窗）
   ├─ 顶栏： [＋ 添加素材 ▾]   → 上传文件 / 联网搜索
   ├─ 页签： ① 我的文件  ② 联网来源         ← 这是"素材的出处"分类，不是并列三大块
   ├─ 内容： 当前页签的出处列表
   │        · 广东电网…pdf    477 段 · 已选 18     [展开]
   │            展开后 → 该文件里的片段列表
   │            ☑ 2.1 招标范围…（第 3 页）        ← 勾选 = 这段就是素材
   │            ☐ 2.2 项目概况…（第 4 页）
   │        · 技术招标文件.docx  54 段 · 已选 0
   └─ 底栏： [应用到本章]
```

**一句话**：素材库 = **两类出处（文件 / 来源）** + **每个出处里挑片段（挑中即素材）**。

---

## 二、为什么这样更对（对比上一版）

| 上一版 | 修正版 | 理由 |
|---|---|---|
| 三个并列页签：素材 / 我的文件 / 联网来源 | 两个页签：我的文件 / 联网来源 | 「素材」不是与出处并列的东西，**素材是出处里挑出来的片段** |
| 先在"素材页"看结果、再去"文件页"挑 | 在出处里直接挑，挑中即为素材 | 少了"结果页/原料页"的来回跳 |
| 添加素材入口分散 | **统一「＋添加素材」**：上传 or 联网搜索 | 符合用户的动作顺序：先决定素材从哪来 |

---

## 三、添加素材：两个入口，一个菜单

```
[＋ 添加素材 ▾]
 ├─ 上传文件…        （多选 PDF / Word / Excel / 图片）
 └─ 联网搜索…        （关键词 → 结果列表 → 选择来源入库）
```

| 动作 | 流程 | 结果 |
|---|---|---|
| 上传文件 | 选择文件 → 上传 → 后台解析成片段 → 出现在「我的文件」 | 出处（文件）+ 若干候选片段 |
| 联网搜索 | 输关键词 → 搜索结果列表 → 勾选要保留的来源 → 入库 | 出处（来源）+ 若干候选片段 |

## 四、在出处里挑素材（核心交互：内容多怎么找）

点出处的 **[展开]** → 就地展开片段挑选器（不必跳页）：

```
┌────────────────────────────────────────────────────────────────────┐
│ 广东电网…pdf  477 段 · 已选 18                       [收起] [删除]  │
│ 🔍[业绩 / 资质 / 数据]     筛选：[含数字][含条款][表格]  ☑ 全选命中    │
├────────────────────────────────────────────────────────────────────┤
│ ☑ 2.1 招标范围：…（第 3 页）        命中「业绩」                    │
│ ☑ 3.2 投标人资格要求：具备…（第 4 页）                              │
│ ☐ 3.3 业绩要求：近三年…（第 5 页）                                  │
│ …（虚拟滚动；每段可展开全文）                                        │
└────────────────────────────────────────────────────────────────────┘
已选 18 · [清空] [只看已选]
```

**六种手段解决"找不到"**

| 手段 | 作用 |
|---|---|
| 关键词搜索 + 命中高亮 | 输"业绩/资质/数据"，直接命中并高亮 |
| 结构化筛选 | 含数字 / 含条款号 / 表格 / 政策文件名 |
| 只看已选 | 复盘时用 |
| 批量选择 | 全选当前页 / 全选命中 / 按章节 |
| 目录/页码跳转（招标文件）| 直达"第三章 投标人资格" |
| AI 预筛（可选）| 按本章各节要点匹配 Top 10 |

**勾选 = 素材（方案 C 语义）**：勾上即成为素材，不需要二次确认；取消勾选即移除。

## 五、出处的增删改查

| 操作 | 我的文件 | 联网来源 |
|---|---|---|
| 增 | 上传 | 联网搜索 → 入库 |
| 查 | 文件名 · 段数 · 已选数 · 解析状态 | 标题 · 域名/日期 · 段数 · 已选数 |
| 改 | 重新解析（换切片策略）、替换文件 | 重新抓取 |
| **删** | 软删文件 → **其下已挑素材一起失效** | 删来源 → 其下片段与素材一起失效 |

**失效的表现**：本章引用清单里该素材标「来源已删除」；正文已有【来源：…】保持原文不动，但提示"需重新补来源"。

## 六、素材 → AI 编写（交互设计）

### 6.1 素材的三种用法（决定提示词怎么注入）

在出处里挑中片段后，可在「本章素材」里设置用法：

| 用法 | 生成时 | 正文表现 |
|---|---|---|
| **引用出处** cite | 只给来源标签 | 句尾【来源：广东电网…pdf（第 3 页）】|
| **数据依据** data | 注入片段 ≤300 字 | 句子含具体数字 + 【来源：…】|
| **仅上下文** context | 注入 ≤500 字，**禁止出现在正文** | 无标注，只影响口径与写法 |

### 6.2 应用素材到章节

```
素材库（挑好片段）→ [应用到本章]
   → 弹小面板：
      用到哪一节： [本章全部 / 项目政策依据梳理 / …]
      用法：       [引用出处 / 数据依据 / 仅上下文]
   → 确定 → 进入「本章素材」（写进 chapter_material_chunks）
```

### 6.3 编写时的注入规则（确定性，可解释）

```
本章素材 cite    → 只给 source_label
本章素材 data    → 片段 ≤300 字
本章素材 context → 片段 ≤500 字
本节指定素材     → 优先注入
未被挑中的片段   → 不进提示词
```

### 6.4 生成后：引用可追溯（已实现）

本章引用清单按模块折叠，每处【来源：X】可追到素材（第几页 / 哪个 URL），
点一下能定位正文那句。

## 七、数据模型（按"片段=素材"简化）

| 用途 | 现有表能否承担 | 结论 |
|---|---|---|
| 出处-文件 | `materials`（+软删）| ✅ 沿用 |
| 出处-来源 | `citations`（+软删）| ✅ 沿用 |
| 片段/候选 | `material_chunks` / `citation_chunks` | ✅ 沿用 |
| **素材 = 挑中的片段** | 片段表加状态：`candidate`（候选）/ `selected`（已挑=素材）| ✅ **不需要单独的素材表** |
| 章节引用 | `chapter_material_chunks(block_id, chunk_kind, chunk_id, section, mode)` | ✅ 沿用（mode = cite/data/context）|
| 文件删除→素材失效 | 文件软删时，其片段置 `rejected` | ✅ 级联规则 |

| 期 | 内容 | 验收 |

## 十一、实现核对（2026-10-28，v4 计划×素材）

v4（`d7ef79f`/`e9989eb`）已经把「计划阶段逐节确认素材」和「按节注入」接上：

- 计划面板每节显示素材建议 → 「采用所选」按节覆盖绑定；「清空本节素材」删除该节绑定；
- `chapter_material_context()` 已接受 `section`，章节 SSE / 单节流式都会传本节标题；
- 素材库「应用到本章」的"整章/小节"选择已能影响注入（不再完全忽略 section）。

但核对代码与两张截图后，仍有 7 个逻辑问题：

| # | 现状 | 后果 |
|---|---|---|
| 1 | `material_context` 按节取绑定；**本节没有绑定就回退到该章全部绑定**（含其他节） | 第 3 节没绑素材，会把第 1、2 节的素材注入第 3 节；「清空本节素材」后反而"继承"了别的节 |
| 2 | 反过来，本节有绑定时**不包含整章绑定**（`section=''` 的素材） | 在素材库选"整章"应用的素材，对已有本节绑定的节反而不生效 |
| 3 | 计划面板「已确认 N」只数本节绑定（`plan_materials._bound` 按 section 分组），整章绑定不计 | 出现截图里的"已确认 0 · 正文引用 7 处"——用户以为没确认，实际有整章素材在用 |
| 4 | 素材库弹窗「应用到本章」仍把 `mode` 写死 `'cite'`，没有用法选择；计划面板用 `auto` 按标签猜 | 同一份素材走两个入口得到不同用法；用户无法在素材库选"数据依据/仅上下文" |
| 5 | 计划建议候选池包含**要求类文件**（招标文件/技术规范书）的已选片段，且 `_TRUST` 给 main_rfp/spec 1.0 最高权重 | 截图里"项目政策依据梳理"建议的是招标文件条款，其中一条还是"投标人被南方电网…不接受投标处理"的**废标条款**；这类条款被当素材注入会跑题 |
| 6 | `data` 模式仍只把片段文本放进【数据依据】，不带来源标签 | 提示词要求标【来源】，模型不知道标哪个 |
| 7 | `context` 没有写后"是否照抄"校验；`paste` 后端允许但无 UI/消费；「应用到本章」不立即改正文 | 背景材料可能被抄；用户点完看不到正文变化，以为没生效 |

补充：

- **两个入口的语义不一致**：计划「采用所选」= **替换**本节绑定（先 DELETE 再 INSERT）；素材库「应用到本章」= **追加/更新**（只 UPSERT，不删除未勾选项）。同一件事两种结果，用户无法预期。
- **建议候选缺少"换一批/去检索/上传"**：截图里 2 条都不合适时，计划面板没有出口，只能关闭去素材库。
- **「采用所选」不勾任何项 = 清空本节**，没有二次确认；「清空本节素材」也无确认。

**结论**：v4 把"按节"从 0 做到了 1，但回退/合并规则错了；建议先统一成
`本节绑定 + 整章绑定（去重，本节 mode 覆盖整章）→ 无绑定才用 NO_MATERIAL_HINT`，
再统一两个入口的"替换/追加"语义和用法选择，最后处理候选池角色与写后校验。
