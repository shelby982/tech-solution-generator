# 应答策划与编写：整体方案

> 本文把「应答策划」和「应答编写」两个页面**合成一份方案**。
> 前提口径（用户已确认）：
> 1. 技术应答与商务应答是**两份独立的文件**，各自一套目录、正文、运行 —— 篇幅要求也各算各的。
> 2. **选了类型，就在那一份应答的篇幅要求里工作**；不出现"技术多少 / 商务多少"的合并总盘。
> 3. 企业自身信息**只从企业官方来源**取（内部官方系统 / 政府与发证机构官方渠道 / 本企业官网与认证公众号），
>   **不引第三方**，每条都要有可追溯的事实来源；官网与公众号只能算**线索级**。
> 4. 篇幅预算与应答策划**合成一体**（同一张表、同一次确认）。

---

## 0. 一页结论

| | 现在 | 方案 |
|---|---|---|
| 策划页产出 | 只产出**目录**（+ 覆盖检查） | 产出**目录 + 篇幅 + 证据需求**，一次确认冻结 |
| 篇幅要求归属 | 不存在 | **应答类型级**属性（`response_plan`），不跨类型合计 |
| 编写页的定位 | 能启动 AI 的 **Markdown 编辑器** | 以**评分点为坐标**、看得清**哪段是谁写的**、知道**能不能交**的编制台 |
| 编写页的产出依据 | 只有"待核对" | 段落来源徽标 + 章节预算条 + 本章缺口 + 完成检查清单 |
| 证据与来源 | 右栏一句模糊提示 | **证据清单**（等级 / 凭证 / 权威源 / 缺口），红线拦截 |

---

## 1. 目标

1. **一次策划做三件事**：定类型、定结构（目录）、定篇幅与证据。
2. **策划与编写职责分离**：策划负责**决策**，编写负责**执行与回检**。
3. **类型是上下文主键**：切换类型 = 切换整份应答（目录/篇幅/证据/正文/进度）。
4. **交付有客观门槛**：评分点覆盖、字数达标、证据凭证级、无依据承诺 —— 四类可检查。
5. **来源可追溯**：每条企业信息落到权威源与凭证等级，缺则出**待补清单**，绝不降级用第三方。

## 2. 现状诊断（带证据）

### 2.1 应答策划（`mode-outline.js` stage 2）

现有能力（真实实现）：
- 单选应答类型（商务 / 技术），各自生成**独立目录草案**与**独立运行**
  （`docs/design/应答策划-商务技术独立编制.md`）
- 目录三部分：评分点优先 → 必须响应/标记条款在前部承接 → 末尾**点对点应答**保留原文全部章节
- 覆盖检查：评分点 13/13、规范要求 411/411、原文章节 68/68（项目 27 实测）
- 确认 → 直接进入编写；改目录则撤销确认

缺口：
| # | 缺口 | 证据 |
|---|---|---|
| 1 | **不产出篇幅** | 策划页只有类型 + 目录 + 覆盖；没有任何页数/字数信息 |
| 2 | **不产出证据需求** | 只有"评分点 / 规范要求 / 原文"三类依据，没有"这章需要哪几类证据" |
| 3 | **确认语义不完整** | 确认的是"目录对不对"，用户确认完仍不知道写多少 |
| 4 | 点对点部分无篇幅规则 | 末尾 68 章保留原文，篇幅由**原文体量**决定，不适用按分值分摊 |
| 5 | 商务/技术的篇幅**上限可能不同** | 招标文件常分别规定；现在没有这个输入位 |

### 2.2 应答编写（`frontend/assets/chapter-studio.mjs`）

现有能力（真实实现）：
- 三栏：应答目录树 / 正文（`textarea` + 编辑·预览）/ 右栏助手（依据 · 素材 · 编制进度）+ 多 Agent 状态
- 工具条：AI 编制本章 / 保存 / 编辑·预览 / 更多（添加内容：文字·表格·关系图 / 确认本章完成 / 导出本章 Word / 导出本组 Word）
- 实时多 Agent：主编组织计划 → 正文流式 → 表格/图示并行 → 合稿 → 双审校；可停可重试，启动恢复
- 已实现的保护：**人工修改与移除的块不被后台覆盖**；服务端核对正文 hash；再次编辑退回待核对
- 页签：正文编写 / 目录总览 165 / 按评分点查找 13

缺口（按严重度）：
| # | 缺口 | 证据 / 后果 |
|---|---|---|
| 1 | **页面没有主语** | 一页同时是"指挥 AI 写 / 自己写 / 查资料 / 看进度"；工具条 4 个按钮四种心智 |
| 2 | **写作单位错位** | 章节是容器，评分点只是右栏依据条目 → 写时看不到"这条评分点答没答" |
| 3 | **正文载体不匹配** | `textarea` Markdown，表格只能以管道符/占位表达，而评审看的是排版后文档 |
| 4 | **看不到计划** | 点 AI 编制直接开跑，用户无法在花掉调用前否决坏计划 |
| 5 | **AI/人工边界不可见** | 规则存在（不覆盖人工块），但界面无标识 → 用户不敢重编 |
| 6 | **进度是工程语言** | 右栏展示"4 个文字任务 / 1 张表"，与"能不能交"无关 |
| 7 | **完成确认无质量门槛** | 只校验正文非空 + hash；STATE 明确"完成是人工标记，不代表质量验收" |
| 8 | **规模不可用** | 编制请求上限 3 章、主编任务上限 8 → 126 个编写单元 ≈ 42 轮人工启动 |
| 9 | **跨章一致性无解** | 按章独立编制 → 重复标题/重复论述/评分上下文扩写/无依据承诺（STATE 记录的高发问题） |

### 2.3 共性问题（两页都踩）

- **两处真相**：目录在策划改、篇幅在别处改 → 必然漂移（本项目已多次踩坑）
- **决策与查看混淆**：把"决策"（策划）放到"查看"（目录总览）里
- **来源不可溯源**：正文没有来源标注，证据只有一句模糊提示

## 3. 模型修正（四条硬规则）

| 编号 | 规则 | 推论 |
|---|---|---|
| **R1** | **应答类型是上下文主键** | 商务与技术各自一套目录/正文/运行/篇幅/证据；页面上不并列显示另一类型 |
| **R2** | **篇幅要求挂在类型上** | `response_plan.budget`；**不跨类型合计**；只在当前类型内校验"章节合计 ↔ 本类型总页数" |
| **R3** | **预算与目录同一张表、同一次确认** | 同源于评分点；目录增删必须联动预算；确认 = 目录 + 篇幅 + 证据一起冻结 |
| **R4** | **来源三级 + 凭证等级** | L1 企业官方（内部系统/政府与发证机构官方渠道/本企业官网与认证公众号）· L2 公开发布（强制出处）· ⛔ 第三方不引；官网与公众号 = **线索级**，业绩/资质/人员段必须**凭证级** |

**R4 的铁律**：官方源未接入或只有线索 → 出**待补清单**派人补，**绝不降级用第三方**。

## 4. 整体信息架构

```
项目准备（识别标包 → 选择标包 → 明确技术规范书归属）
   ↓
标包工作空间（四个阶段）
   ① 解析依据      评分点 / 规范要求 / 原文（只读事实）
   ② 应答策划  ← 决策：选类型 → 定结构 → 定篇幅与证据 → 双确认
   ③ 应答编写  ← 执行：按章编制与人工编辑 + 回检
   ④ 评审与交付 导出 + 红线拦截清单
```
**职责边界**：②负责"写什么、写多少、凭什么写"；③负责"把它写出来、并知道能不能交"。

## 5. 应答策划方案

### 5.1 界面蓝图

```
应答策划
┌ 应答类型（单选；决定整页上下文）───────────────────────────────┐
│  ◉ 技术应答    ○ 商务应答                                      │
│  技术应答 = 技术评分点 + 已关联规范书（含背景与范围）              │
│  商务应答 = 商务评分点（不挂技术规范书）                          │
└───────────────────────────────────────────────────────────────┘
┌ 本类型篇幅要求（R2：只属于当前类型）────────────────────────────┐
│  总页数 [ 120 ] 页  来源：[招标文件技术部分规定 ▾]                │
│  章节合计 112 页    ✅ 一致 / ⚠ 差 8 页未分配                     │
└───────────────────────────────────────────────────────────────┘
┌ 技术应答 · 目录与篇幅（R3：同一张表）───────────────────────────┐
│ 章节                分值  建议页  你填页  需要证据        状态     │
│ 项目背景              4     6      [ 6]   实测参数 ✅      已确认  │
│ ├ 系统架构设计        12    16     [16]   —              已确认  │
│ 技术方案             30    42     [45]   业绩/人员/实测   缺 2 项  │
│ ─── 点对点应答（原文章节 68 章）：按原文体量给区间，不参与分摊 ─── │
│ 合计 112 / 120 页                          证据缺口 3 项         │
└───────────────────────────────────────────────────────────────┘
        [ 确认目录与篇幅 ]   ← 双确认：目录 + 篇幅 + 证据一次冻结
```

### 5.2 篇幅与证据（与目录同表）

- **总页数**：用户填；系统**不猜**。来源可标注（招标文件硬性规定 / 公司模板经验值）。
- **自动分配（用户明确要求：不能让用户一章一章手工填）**：
  - 改完总页数 → **自动**按 `评分点分值 × 章节类型系数` 分配到各章，**合计精确等于总页数**
    （最大余额法：先取整，再按小数部分补齐/扣减，保证不差页）
  - 手工改过某一章 → 该章**固定**（显示「已调整」），其余章节吸收差额
  - 两个明确动作：「**按评分点分配**」＝尊重手工固定，只分配剩余额度；
    「**清除手工调整**」＝全部重算
  - 切换应答类型 → 按该类型总页数重新分配一次
- **建议页数**：算法产出的可解释参考值（分值 × 类型系数），不再是需要用户维护的输入。
- **点对点部分**：单独分区，**按原文体量给区间**，不参与分值分摊（否则 68 章吃掉总额）。
- **需要证据**：每章列出所需证据类型（业绩/资质/人员/实测/背景）；与已核对素材比对得到**缺口**。
- **校验只在当前类型内**：`章节合计 ↔ 本类型总页数`。

### 5.3 确认与冻结

- 确认按钮改为「**确认目录与篇幅**」；一次写入并冻结：目录 + 篇幅 + 证据需求。
- **改目录 → 撤销确认**（与现有规则一致）。
- 确认后进入编写；编写页只读这些目标，不再改目标（要改回策划）。

### 5.4 点对点的特殊规则

- 保留原文全部章节（标题/编号/层级/顺序/标记/完整内容）；
- 服务端禁止改名、删节、调层级、重排序或移出末尾（现有规则）；
- 篇幅不以分值为准，改以**原文体量**给"建议区间"，允许超区间但需确认。

## 6. 应答编写方案

### 6.1 P0（本轮）

**① 给编辑器一个主语**
```
项目背景   预算 6 页 · 已写 2.5 页 · 差 3.5 页            待核对
本章 6 段：AI 已编 3 段 · 人工改 2 段 · 未编 1 段 · 证据 3/5 · 覆盖 2/3
```
每段带来源徽标：`AI 生成` / `人工修改 ✎` / `AI 生成·人工改过` / `未编制`。

**② 正文块级渲染**（编辑可回落文本）
标题 / 段落 / **真表格** / 图占位，按块渲染；表格不再是管道符。

**③ 编制计划预览**
点「AI 编制本章」先出计划：`预计 5 个任务（现状/方案/2 表/1 图）· 约 11,250 字 · 需要 3 类证据（已有 1，缺 2）` → **确认后开始**。

**④ 完成确认加客观检查**
点「确认本章完成」先跑四项：评分点覆盖 / 字数达标 / 证据凭证级 / 无依据承诺。
**不通过也能确认，但必须看到不通过清单**（保留"完成是人工标记"的现有语义）。

### 6.2 P1

**⑤ 进度口语化**：把"4 个文字任务 / 1 张表"换成「本章 6 段：已写 4 段（其中 2 段人工改过）」。
**⑥ 批量队列**：多章排队、可停可续、**分值高的先写**（解决 42 轮人工启动）。
**⑦ 按评分点写作视图**：以评分点为入口，列出它散落在哪些章节 + 一键"补齐未覆盖"。

### 6.3 P2

**⑧ 全书事实总编**：跨章重复检测、统一数字/术语/承诺口径、防止评分上下文扩写到邻章。
**⑨ 块级 AI 重写**：选中段落重编，不整章重来。

### 6.4 编写页蓝图（P0 后）

```
左：应答目录（树，带 差 X 页 / 已达标）   右：依据 | 素材 | 编制进度
中：章节头（预算条 + 段数构成）
    字数缺口条（差 N 字 → 查看补写建议 → 生成草稿，人工确认后合并）
    块级正文（段落角色徽标 + 来源徽标 + 真表格）
    工具条：AI 编制本章(先看计划) / 保存 / 编辑·预览 / 添加内容 / 完成并检查
```

## 7. 数据模型

### 7.1 复用现有（不新增表的部分）

| 现有 | 位置 | 用途 |
|---|---|---|
| `response_plan` | **`split_answers` 的键**（非表），作用域 = `(project_id, thread_id)` | 已存**类型**与来源运行 —— **天然就是"按应答类型"作用域**，正是 R2 需要的载体 |
| `chapter_studio(block_id, layout, writing_status, confirmed_hash)` | 表 | 章节级状态与完成 hash |
| `chapter_materials(block_id, material_id, confirmed)` | 表 | 章 ↔ 素材关联与核对状态 |
| `chapter_writing_jobs(...)` | 表 | 编制任务（可停可重试，启动恢复） |
| `response_document_settings(project_id, thread_id, template)` | 表 | 导出模板（按类型隔离） |

### 7.2 新增（分期）

| 新增 | 形态 | 作用 |
|---|---|---|
| `response_plan.budget` | 现有 key 内加字段 `{total, source_note, per_chapter:{block_id:pages}}` | **P0**：本类型总页数与每章分配 |
| `chapter_budget`（可选升级） | 表 `(thread_id, block_id, pages, basis, updated_at)` | P1：需要按章查询/回检/审计时 |
| `chapter_evidence_need` | 表 `(thread_id, block_id, evidence_type, required_level, source_hint)` | P1：每章需要哪几类证据、要什么凭证等级 |
| `source_registry` | 表 `(project_id, name, level, credential_level, access_mode, connected)` | P1：企业官方信息源清单（内部系统/政府公示/官网/公众号） |
| 证据凭证 | `chapter_materials` 扩展 `source_level / credential_level / source_ref / snapshot_at` | P1：每条素材的来源等级与凭证 |

**不新增**：不存在"标包总页数"字段 —— 因为它没有业务含义（R2）。

### 7.3 语义要点

- `budget.total` 为空 = 尚未填；**系统不自动填**。
- `per_chapter` 用 `block_id`（逻辑 id），与目录树同源，避免两处真相。
- 点对点章节在 `response_plan` 里标 `part: 'point_to_point'`，预算按区间而非分值。
- 证据缺口的判定：`chapter_evidence_need` × `chapter_materials(confirmed)` → 缺 / 仅线索 / 已具备。

## 8. 接口（草案）

```
GET  /projects/{id}/response-plan?threadId=…          读当前类型的 类型/目录/篇幅/证据
PUT  /projects/{id}/response-plan/budget              写总页数与每章分配（当前类型）
POST /projects/{id}/response-plan/confirm             双确认：目录 + 篇幅 + 证据一次冻结
GET  /projects/{id}/source-registry                   企业官方信息源清单与接入状态
POST /projects/{id}/chapters/{blockId}/evidence-need  设置该章需要的证据类型
GET  /projects/{id}/chapters/{blockId}/gaps           本章缺口（类型/权威源/是否接入/动作）
POST /projects/{id}/chapters/{blockId}/complete-check 完成前四项检查（不阻断）
```
沿用现有约束：所有接口**必须带 threadId（= 应答类型）**，跨类型/跨项目一律拒绝。

## 9. 分期与验收标准

| 期 | 内容 | 验收 |
|---|---|---|
| **P0-1** | 策划页：类型单选在最上；**篇幅与目录同表**；类型内合计校验；双确认 | 切换类型 → 目录/篇幅/证据**整体换掉**；合计只在本类型内校验；改目录撤销确认 |
| **P0-2** | 编写页：主语状态条 + 段落来源徽标 + 块级渲染 + 计划预览 + 完成检查 | 段数构成与实际一致；表格以真表格渲染；点 AI 编制先出计划；完成时看到四项检查结论 |
| **P1** | 证据清单与缺口 + 来源登记表 + 批量队列 + 按评分点写作 | 缺口给出权威源与接入状态；队列可停可续；按评分点能定位并补齐未覆盖 |
| **P2** | 全书事实总编 + 块级重写 | 跨章重复可检出并给合并建议；单段重编不整章重来 |

**通用验收**：任何"目标值"变更都能追溯到人（谁在何时改的），任何"我方陈述"都能追溯到来源或标注为待补。

## 10. 边界与非目标

- 不把商务与技术**合并**到一张篇幅表（R1/R2）。
- 不做"自动填满"：字数不足只给**建议 + 草稿**，**人工确认后合并**，不覆盖人工修改。
- 不引第三方信息；官网/公众号**不升格为凭证**。
- 不代替用户确认目录；不重建用户已确认的目录。
- 图示仍为简单关系链、不接复杂架构图与图片模型（与当前边界一致）。
- 不实现全书几千页批量编制的"全自动"。

## 11. 风险与待定

| # | 风险/待定 | 建议 |
|---|---|---|
| 1 | 建议页数的系数怎么定 | 先用「分值 × 类型系数」并**允许手改**，跑 2-3 个真实标包后校准 |
| 2 | 点对点区间怎么给 | 按原文字数 × 系数给**区间**（如 ±20%），超区间需确认 |
| 3 | 内部官方源接入范围 | 先做"待补清单 + 人工上传凭证"，内部库接入按可提供性排期 |
| 4 | 完成检查的严格度 | 只做**提示**不做**阻断**（保留人工判断），但导出时带"未通过清单" |
| 5 | 证据类型从哪来 | 先从评分点口径启发式归类（业绩/资质/人员/实测/背景），允许人工调整 |
