# 插入按钮的重新定位：从"选来源"回到"造非文字块"

> 用户判断：插入按钮的目的是**便捷插入图片、表格**，其中图片还包括**调用模型生成信息图**；
> 当前界面的三块（从官方来源 / 从素材 / 结构模板）**实际意义不大**。
> 本文分析为什么，并给出应该长什么样。

---

## 一、先明确"插入"到底解决什么问题

正文是文字流。AI 编制能写文字，但有三种东西**必须从别处来**：

| 对象 | 为什么 AI 不行 | 正确的获得方式 |
|---|---|---|
| **真实图片**（证书、截图、现场照） | 无法编造真实图像 | 从**素材**里选（已有文件）|
| **真实表格**（业绩、参数、报价） | 数据不在模型里 | 从**素材**里抽（docx/xlsx）|
| **信息图 / 关系图 / 架构图** | 能从文字推断，但需要"结构化表达" | **模型生成**（这正是 AI 擅长且能省的活）|

所以插入的本质是：**降低"非文字块"的生产成本** ——
- 真实图/表：降低**搬运成本**（素材 → 正文）
- 信息图/表：降低**创作成本**（文字 → 结构）
- 空模板：**不降低成本**（只是换个地方手打）

**结论**：插入面板应该按「**块类型 × 获得方式**」组织，不是按"来源"。

---

## 二、为什么现在这三块没有价值（逐条）

| 现在的页签 | 实际提供的东西 | 为什么没价值 |
|---|---|---|
| **从官方来源插入** | 把政策原文片段插进正文 | **它插的是文字**。文字不需要"插入"——要么 AI 写，要么用户自己打字。放在插入里，等于把"引用"这件写作动作伪装成"插图/插表"，语义错位。引用应该走**素材/待办**链路（缺来源 → 去补来源）。 |
| **从素材插入** | 摘录 / 图片 / 表格 | 只有**图片和表格**是对的方向 ✓；**摘录是文字** ✗ → 同一个面板里混了"文字"和"块"，又把语义搞乱。 |
| **结构模板** | 空表 / 图骨架 | **空壳没有价值** ✗。用户点"对比表"得到一张 `【待补充】` 的表，工作没减少、反而多了填表步骤。真正省事的是**AI 按本章要求直接生成一张有内容的表**，用户再改。 |

一句话：**三块里只有"图片、表格"两件事是对的；"插文字"和"给空壳"都是伪需求。**

## 三、正确的结构：块类型 × 获得方式（4 格矩阵）

```
插入内容
┌ 想放什么？  [图片]  [表格]        ← 按块类型分（互斥页签）
└──────────────────────────────
图片
  ● AI 生成信息图        把选中的文字 / 本章要点抽成结构图      [生成]
  ● AI 生成关系/架构图    分层结构（接入 → 服务 → 数据）        [生成]
  ● 从素材插入图片       证书 / 截图 / 现场照（真实图片）        [选择素材]

表格
  ● AI 生成表格          按本章交付物要求自动出表（含内容草稿）   [生成]
  ● 从素材插入表格       docx / xlsx 抽取真实表格               [选择素材]
```

| | 真实（有出处） | 生成（模型造） |
|---|---|---|
| **图片** | 从素材插入 | **AI 生成信息图 / 架构图** |
| **表格** | 从素材插入 | **AI 生成表格** |

**为什么"生成"要排在"真实"前面**：真实图/表是**少数情况**（有素材时才有），
而交付物里"要一张图/表"是**常见要求**（计划里本来就有图表计划）→ 生成是高频主路径。

## 四、生成能力怎么设计（这是本面板的核心）

### 4.1 信息图生成（已有后端，入口断了）

后端已有 `POST /api/blocks/{id}/studio/diagram`（入参：一段文字；出参：节点 + markdown 图），
但工具条改版时入口被去掉了 → 现在**无处可用**。应该收回插入面板。

**流程**：
1. 打开「AI 生成信息图」
2. 输入区**预填**：正文选中文字（有选区时）/ 本章交付物要点（无选区时）
3. 可写一句"想画成什么"（对比 / 流程 / 层次 / 因果）
4. 生成 → **预览**（节点数 + 图形）→ `[插入正文] [重新生成]`
5. 落库为 `:::diagram …` 块，可继续手改

### 4.2 表格生成（新增，复用已有模型角色）

- 入参：本章标题 + 本章要求（交付物/评分点）+ 一句话说明
- 出参：Markdown 表（含**待补充占位**，不编造数据）
- 与信息图一致的流程：生成 → 预览 → 插入 / 重新生成

### 4.3 生成 vs 素材的边界（防止互相污染）

| 场景 | 走哪条 |
|---|---|
| 有真实证书/截图 | 从素材插入图片 |
| 有业绩 Excel | 从素材插入表格 |
| 只是想"把这段讲清楚" | AI 生成信息图 |
| 交付物要求一张对比表但还没有内容 | AI 生成表格（再手工修订）|

## 五、与现有体系的衔接

- **图表计划 / 待办**：待办里的「缺图示」「缺表格」→ 点进去直接落到插入面板的**生成**入口（同一动作）
- **素材页签**：缺口「必须你上传」→ 上传后回到插入面板「从素材插入」
- **计划面板**：交付物里的"表格/图示"要求 → 生成的默认范围（按交付物标题生成）
- **导出**：`:::figure` / `:::diagram` / Markdown 表 都被现有导出链路支持

---

## 六、要删掉的东西

| 删除项 | 理由 |
|---|---|
| 「从官方来源插入」页签 | 插文字 ≠ 插入；引用走素材/待办链路 |
| 素材里的「摘录」按钮 | 同上（文字）|
| 「结构模板」整块（空表/骨架） | 空壳不降成本 |
| 原「文字生成图」独立入口 | 并入插入面板「AI 生成信息图」 |

---

## 七、验收标准

1. 「插入…」打开面板，只有 **图片 / 表格** 两个页签
2. 图片页签含：AI 生成信息图、AI 生成架构图、从素材插入图片
3. 表格页签含：AI 生成表格、从素材插入表格
4. 生成流程：预填内容 → 生成 → **预览** → 插入 / 重新生成
5. 面板里**不再出现**「从官方来源」「结构模板」「摘录」
6. 生成的表/图插入后可有内容、可继续手改；无数据时用 `【待补充】` 占位
7. 无控制台错误
