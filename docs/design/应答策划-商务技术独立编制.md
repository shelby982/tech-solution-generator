# 应答策划：商务与技术独立编制

## 流程与边界

当前标包完成解析后，选择商务应答或技术应答，生成独立目录草案，检查章节与来源映射，确认后直接进入编写。原技术规范书阅读视图继续保持原文结构；应答目录允许按评分和写作逻辑整合。

| 应答类型 | 依据 | 输出 |
|---|---|---|
| 商务 | 商务评分点，人工核对商务格式及证明材料 | 商务目录、依据映射、商务正文 |
| 技术 | 技术评分点、已关联规范书、背景与范围等基础内容 | 技术目录、规范与评分映射、技术正文 |

招标文件明确规定的组成、格式优先。当前格式及证明材料完整性仍需人工核对，不将关联数量等同于合规通过。

## 界面

1. “待确认”改为“应答策划”，单选应答类型。
2. 展示当前标包编制依据、输出类型、来源和编制规则。
3. 生成目录草案后展示可编辑的目录及覆盖检查。
4. 选中章节查看评分点与规范书原文；完整映射作为辅助查看。
5. 确认后直接进入正文编写，目录总览与评分点映射作为编写辅助视图。取消先逐项手工挂载全部规范主题的前置步骤。

## 数据隔离

- 以解析运行作为共同来源，每种应答单独创建一个工作流运行；复用解析事实，不重新上传文件。
- `response_plan` 记录类型、来源运行和确认状态；同来源同类型复用已有草案。
- 各应答独立保存目录、正文和评审数据。创建草案不清理来源或其他应答的 blocks。
- 商务目录构建不传入技术规范书节点及规范要求映射；技术目录保留这两类依据。
- 重新派生目录撤销原确认状态。导出显式携带 threadId，文件名标明商务或技术应答。

## 验证

- 自动测试：验证同来源创建两种应答、重复打开复用、原运行保留及混合类别拒绝。
- 页面验证：类型选择、依据数量、目录生成、预览和确认入口。
- 商务格式、资格、证明材料的专门提取与自动校验仍是后续能力，不在界面中冒充已完成检查。

## 技术目录编排第二版

- 评分点优先组织第一部分；有原文标记或明确必须响应、否决、实质性约束的章节，在相关评分章节下呈现，匹配不到的集中于第二部分。
- 最后一部分固定为“技术规范书点对点应答”，保留全部原文章节（包括背景、概述、表格），不进行主题聚合或同名去重。原文标题、编号、层级、顺序、标记与完整内容均保留。
- 原文章节直接绑定来源与完整正文，不再通过相似标题检索或 3000 字截断回填。
- 前部重点章节与末尾点对点章节通过相同规范要求 ID 关联；目录位置完整不等同于正文充分响应。
- 服务端禁止将点对点目录改名、删节、调层级、重排序或移出末尾。前部评分与重点章节可继续编辑。
- 当前标包实测第二版：177 个节点，评分点 13/13，原文章节 68/68，点对点要求归属 411/411；星号在前部重点要求与末尾对应原文章节均可见。原商务草案保持独立保存。

## 承接位置检查优化

- 确认时按规范要求 ID 检查承接关系，不再要求生成时的重点章节逐名保留。多个要求可以合并到同一评分章节，改名不影响已保存的关联。
- 普通“必须/须/不得”要求或未明确定义含义的符号项，仅在末尾点对点部分安排时，提示“建议前部突出”，允许确认。
- 明确否决、实质性约束要求须有承接位置；前部或末尾已安排均视为有位置。仅在末尾安排时仍提示建议前部突出。
- 点对点目录缺章、标题/层级/顺序不一致、要求归属不完整，继续阻止确认。正文充分性仍由编写后检查。
- 当前已手动调整的目录不自动恢复独立重点章节：原文 68/68、要求归属 411/411，可确认；13 条仅在末尾安排的重点要求显示为建议。
# 编写工作台整合（2026-10-16）

- 主流程收敛为：解析依据 → 应答策划 → 应答编写 → 评审与交付。
- 取消独立“产物”阶段。确认目录后直接进入编写；已确认的目录提供“进入编写”按钮。
- 编写工作台包含正文编写、目录总览、按评分点查找。目录与映射中的章节可直接定位正文。
- 章头展示当前章节、评分口径、举证要求及关联技术规范原文；重点要求与点对点章节区分来源。
- 目录与编写进度统一使用“目录节点”计数，避免将三个顶层分组误写成三章。
- Word 草稿导出放在评审与交付中，明确仅包含已保存正文，空章节不代表已完成应答。
