# 质检方案（重构版）：从"整体打分"到"按章按条体检"

> 问题：现在的质检是**按整章内容**算出来的（骨架缺失/表图数量/篇幅/素材充足度），
> 界面只给"96 个单元、通过 4、高优 1"这种整体数字 → 用户看不出"哪一章、哪一条要求没做到"。
> 本方案把质检改成**对照准绳的逐条体检**，准绳 = 编写规范（全局）+ 编写计划（章节）。

---

## 一、定位与三条原则

1. **质检 = 对照准绳体检，不是打分**：每条结论必须能回答"对照的是哪条准绳、问题在哪个位置、该做什么"。
2. **粒度 = 章节 × 检查项**：不做"整册总分"，不做"整章笼统扣分"；结论落到具体章、具体节、具体位置。
3. **不阻断保存**：只出清单 + 可执行动作；是否修由人决定（用户口径：别卡住手工修正）。

---

## 二、准绳：质检对照哪三样东西

| 层 | 准绳 | 来源对象 | 质检用途 |
|---|---|---|---|
| **规范** | L0 全局纪律 + L1 模块配方（骨架/必表/必图/失分点） | `writing_specs` | 结构、图表数量、失分点、来源纪律 |
| **计划** | 本章的 requirements（要求）/ tasks（体裁）/ pages（篇幅） | `writing_plans` | 要求是否回应、体裁是否齐全、篇幅是否达标 |
| **依据** | 评分点（分值/要素）+ 技术规范条款 | `review_points` / `spec_requirements` | 评分点是否被回应、规范条款是否有落点 |
| **素材** | 我方的材料 + 外部来源与片段 | `chapter_materials` / `citations` + `segments` | 需求是否补齐、来源是否被引用 |

> 注意：质检**不评价"写得好不好"**（那是人工评审），只核对"该有的有没有、有依据没有、形式对不对"。

---

## 三、检查项矩阵（四组 15 项）

### A. 规范级（每章都查，来源=规范）

| 编号 | 检查项 | 判定 | 级别 | 状态 |
|---|---|---|---|---|
| A1 | 骨架落点 | 配方骨架的每一项在正文里有关键词落点 | 中 | 已有 |
| A2 | 必表 | 每节 ≥1 张表（L0） | 高 | 已有 |
| A3 | 必图 | 配方要求图时 ≥1 张（含 `:::diagram` / 图片） | 高 | 已有 |
| A4 | 空词 | 非常/极大/显著提升… | 低 | 已有 |
| A5 | **来源标注** | 正文出现政策/标准/数据类表述但无【来源】 | 中 | **新增** |
| A6 | 篇幅偏差 | 已写页 vs 分配页（>130% 或 <40%） | 中 | 已有 |

### B. 计划级（来源=本章计划）

| 编号 | 检查项 | 判定 | 级别 | 状态 |
|---|---|---|---|---|
| B1 | **要求回应** | 计划 requirements 的每一条在正文里有着落（关键词/要点覆盖） | 高 | **待 P6** |
| B2 | **体裁齐全** | 正文表格数 ≥ 计划表任务数；图示数 ≥ 计划图任务数 | 中 | 新增 |
| B3 | **篇幅达标** | 计划 pages 与已写页对比（与 A6 合并展示，口径以计划为准） | 中 | 已有（改口径） |

### C. 依据级（来源=评分点/规范条款）

| 编号 | 检查项 | 判定 | 级别 | 状态 |
|---|---|---|---|---|
| C1 | **评分点覆盖** | 本章 `review_point_ids` 对应的评分要素在正文有回应 | 高 | **迁移**（现只在策划页） |
| C2 | **规范条款承接** | 本章 `spec_requirement_ids` 的条款在正文各有一句以上落点 | 中 | **新增** |
| C3 | 点对点不漏条 | 仅点对点章节：响应表是否覆盖全部条款 | 高 | **迁移**（现是确认闸） |
| C4 | 缺口未落实 | `evidence_required` 的要求在正文写【待补充】 | 中 | 已有（并入 D3） |

### D. 素材级（来源=材料/来源/片段）

| 编号 | 检查项 | 判定 | 级别 | 状态 |
|---|---|---|---|---|
| D1 | 素材不足 | 有正文但无材料也无来源 | 中 | 已有 |
| D2 | 来源未引用 | 已接受来源但正文没引用 | 中 | 已有 |
| D3 | **需求待补** | 计划要求派生的素材需求仍"待补" | 中 | **待 P7** |
| D4 | **来源待确认** | 非官方来源（trust=unverified）未确认 | 高 | 新增（入库前就拦，这里兜底） |

---

## 四、粒度与聚合（关键改动）

```
每章（blocks 的编写单元）→ 一份结果：{ chapter, issues[] }
        ↓ 聚合
每个一级目录（技术评分点）→ 汇总：要求覆盖 5/7 · 高优 2 · 待补需求 3
        ↓ 聚合（**只做汇总，不评分**）
整册 → 顶部一条汇总：待修 12 条（高优 2）· 覆盖 47 章
```

**不做的事**：
- ❌ 不给整册/整章"质量分"（用户看不懂、也不可执行）
- ❌ 不把不同性质的问题混成一个数字（结构/依据/素材分开列）

---

## 五、输出形态

每条问题统一结构（无论来自哪个检查项）：

```json
{
  "chapter": {"block_id": "s1.2.1.1", "title": "项目背景现状目标"},
  "check": "B1 要求回应",
  "level": "high",                       // high | medium | low | info
  "message": "要求 r2「给出行业数据（2025 年口径）」在正文里没有落点",
  "basis": {"kind": "requirement", "requirement_id": "r2"},   // 对照的是哪条准绳
  "location": {"anchor": "二、政策与技术发展动因"},           // 正文位置（可跳转）
  "actions": [
    {"label": "去补素材", "kind": "find_material", "need_id": "n2"},
    {"label": "重新生成本节", "kind": "regenerate", "block_id": "s1.2.1.1"},
    {"label": "标为已处理", "kind": "ignore"}
  ]
}
```

**三个视图**
1. **按章**（默认）：章 → 问题列表（按级别排序）
2. **按检查项**：同一问题跨章汇总（"12 章缺图示"）
3. **按级别**：先修 high

## 六、触发与留存

| 触发 | 说明 |
|---|---|
| 手动 | 编写页「质检」按钮 / 进度中心待办入口 |
| 自动（生成后） | 每次生成/保存后对该章跑一次（只跑该章，节流 3s） |
| 自动（全局） | 打开"按检查项"视图时跑全量（可缓存 1 分钟） |

**落库（新增）**：`quality_findings`（project_id / thread_id / block_id / check / level / message / basis / status(open|fixed|ignored) / created_at）
- 目的：待办只读"open 且 high/medium"；修完自动消失需要重算；历史可看趋势
- 已有实时计算保留（作为"当前状态"），落库只用于**跟踪与趋势**

## 七、界面

### 章节工作台（右栏第四块）
```
③ 进度 / 质检
  要求回应 2/3   ·   质检：高优 1 中优 2
  ├ [高] 要求 r2「给出行业数据」未落点        [去补素材] [重新生成]
  ├ [中] 骨架项「现状差距」无落点             [看规范]
  └ [中] 已接受 1 条来源但正文未引用          [去素材]
```

### 全局清单（保留在「更多 › 质检清单」）
- 顶部：待修 12 条（高优 2）· 覆盖 47 章 · 待补需求 3
- 视图切换：按章 / 按检查项 / 按级别
- 每行可跳转到章节 + 一键动作

## 八、分期

| 期 | 内容 | 依赖 |
|---|---|---|
| **Q1** | 现有 10 项检查**归入四组**并统一输出结构（check/basis/location/actions）；章级结果按章列出（不再只给整体数字）；A5/C2 新增；落库 `quality_findings` | 无（可立即做） |
| **Q2** | B1 要求回应 / B2 体裁齐全 / D3 需求待补（依赖计划里的 requirements 与 needs） | P6/P7 |
| **Q3** | 三视图 + 一键动作（去补素材/重新生成/标为已处理）+ 趋势 | Q1/Q2 |

---

## 九、边界

1. **不评价文章好坏**：只查"该有的有没有、有依据没有、形式对不对"；文风/说服力归人工评审。
2. **不阻断**：high 也只提示，不禁止保存/导出（导出前可给"未解决 N 条"确认）。
3. **口径唯一**：篇幅以计划 pages 为准；表格/图示以规范与计划中较严格者为准。
4. **可解释**：每条结论都能指到"规范哪条/计划哪条要求/哪条来源"，不能是黑盒判断。
